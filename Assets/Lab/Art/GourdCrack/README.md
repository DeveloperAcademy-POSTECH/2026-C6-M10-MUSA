# 박 명중 크랙 프로토타입 (#150)

Unity 6000.6.5f1에서 **C6 Lab → Open Gourd Crack Prototype**을 선택하고 Play를 누른다. DEV의 START SOLO로 라운드를 시작한 뒤 Yin/Yang을 조합해 Combined를 위로 스와이프하여 던진다. 현재 팀 버전의 투척·명중 판정과 HP를 사용한다.

실험 장면은 `Assets/Lab/Scenes/LabGourdCrack.unity`다. 원본 Lab 장면을 복사하여 박 표현만 추가했다. 이 메뉴는 빌드 시작 Scene을 바꾸지 않으므로 실기기에서 시험하려면 이 장면을 포함하는 빌드 구성을 별도로 지정해야 한다.

- 팀의 Target2_Intact 박 프리팹을 시각 요소로 사용한다. 모델의 자체 애니메이션과 중복 끈은 비활성화한다.
- 기존 Cylinder 피격체와 매달림·회전 로직을 유지한다. 박은 외형만 교체한 것으로 구형 표면과 원통 판정의 차이는 후속 개선 대상이다.
- 첫 피해: 작은 금. 남은 HP 66% 이하: 2단계. 33% 이하: 3단계. 마지막 단계에서도 실제로 조각나지는 않는다.
- 호스트가 확정한 공유 HP에서 단계가 결정되므로 빗나감·중복 타격 패킷으로 따로 크랙을 추가하지 않는다. 로비나 새 라운드의 초기 HP에서는 0단계로 돌아간다.
- 크랙은 절차적 셰이더로 표시하며 이번에는 맞은 위치에 생기는 국소 크랙이 아니라 누적 피해별 표면 패턴이다. 색칠 봉인은 포함하지 않는다.
- HP 1000으로 시험하면 한 발 피해가 작아 다음 단계까지 여러 번 맞혀야 한다. DEV에서 HP를 낮춰 단계 전환을 빠르게 확인할 수 있다.

## 검증 기록 — 2026-10-15

Unity 6000.6.5f1에서 Scene 연결·셰이더 렌더·껍질 재질 교체·물리 컴포넌트 제거·로비 초기화 확인. EditMode 88/88, PlayMode 66/66 통과. 이번 추가 검사는 단계 경계값 5개 및 저장 실험 장면의 외형·렌더·초기화 검사 1개다. 실행 중 실제 손 입력과 다중 기기 연결·iOS 성능은 별도 확인이 필요하다.

0~3단계 렌더 캡처는 `Library/GourdCrackCaptures`에 있으며 기본 로비 카메라로 촬영한 외형 확인 이미지다. 실제 전투 화면 검증과 구분한다.

## 마지막 명중 마무리

HP 0의 승리 스냅샷이 도착하면 약 0.2초 움찔한 뒤, 박이 고정된 자체 방향으로 두 쪽으로 벌어지며 내려간다. 가운데 작은 주황색 요괴 기운이 나타난다. 약 1.2초 후 승리 카드와 결과 대시보드가 표시된다. 패배 결과는 지연하지 않는다. 라운드가 바뀌거나 로비로 돌아가면 껍질과 기운을 정리한다.

각 클라이언트가 호스트의 승리 상태를 받아 한 번씩 재생한다. 네트워크 지연만큼 시작 시각 차이는 있을 수 있다. 박은 원본 껍질을 절반씩 잘라 보여주는 셰이더 방식으로 벌어지며, 실제 파편 물리나 호리병 회수는 포함하지 않는다.

## 마무리 연출 검증 — 2026-10-15

Unity 6000.6.5f1에서 실험 Scene에 마무리 컴포넌트를 연결하고, 갈라진 상태를 렌더 캡처하여 확인했다. 전체 PlayMode 66/66 통과 후, 반복 스냅샷 재생 방지·승리 지연 해제·패배 즉시 표시·로비 복귀 초기화 검사를 추가한 관련 검사 6/6 재통과. EditMode 88/88 통과. 실제 다중 기기에서의 연출 동기와 iOS 성능은 미검증. 원본 Lab 장면에는 마무리 컴포넌트를 추가하지 않았으며, 해당 컴포넌트가 있는 실험 장면에서만 결과 표시가 지연된다.
