# 3인 스토리 로비·캐릭터 선택 UI (#802)

## 적용 범위

Hapio 스토리 방의 선택된 자리에는 인원에 관계없이 Figma 원본 캐릭터 컴포넌트를 사용한다(#804). 기본·방장·나·방장+나의 네 상태는 실제 자리 소유권을 따른다. 3인 방의 빈 자리와 캐릭터 팝업은 #802 원본을 사용하고, 2·4·5인 방의 빈 자리·배치·팝업은 기존 표시를 유지한다. 땅따먹기·Lab 로비는 변경하지 않는다. 일반 게임과 A/B 스태프 시연은 같은 표시 경로를 사용한다.

이번 변경은 로비의 표시와 캐릭터 선택 팝업에 한정한다. P번호·자리 소유권·캐릭터 중복 금지·Host 승인·시작 조건·LAN/핫스팟 연결은 기존 [게임 흐름](GAME_FLOW.md)을 따른다. 스테이지·결과·시연 종료 QR 화면도 기존 경로를 유지한다.

## 자리와 캐릭터 선택

1. 빈 P1·P2·P3 자리를 누르면 다섯 캐릭터를 고르는 팝업이 열린다.
2. 다른 참가자가 선택한 캐릭터는 원본 초상을 옅게 표시하고 원본 선택 완료 도장을 덧붙이며 누를 수 없다. 이 표시는 실제 세션의 캐릭터 소유권을 따른다.
3. 선택 가능한 캐릭터를 누르면 팝업이 즉시 닫히고 기존 요청으로 자리와 캐릭터를 함께 Host에게 보낸다. 자리의 확정 표시는 Host가 승인한 결과를 사용한다.
4. 닫기 또는 팝업 바깥을 누르면 선택 요청을 보내지 않는다. 이미 확정한 자기 자리를 다시 누르면 기존처럼 선택이 해제된다. 재입장 후 자기 자리만 복원되고 캐릭터가 비어 있을 때에는 팝업 아래에 `자리 비우기`가 나타나며 자리와 캐릭터를 함께 해제한다. 평상시 팝업에는 이 추가 동작을 표시하지 않는다.
5. 세 명의 자리·캐릭터·설정이 모두 준비되면 Host가 시작한다. 캐릭터 팝업이나 세 번째 참가자의 입장으로 자동 시작하지 않는다.

**P번호와 캐릭터 번호는 서로 다르다.** P번호는 전투 위치와 좌우 이웃을 정하고, 캐릭터 번호는 초상과 이름을 정한다. 방장 표시도 실제 Host가 고른 자리를 따른다. 예를 들어 Host가 P2에서 만복을 고르면 P2에 만복의 방장 그림을 표시하며, P1 고정 그림이나 두 번째 캐릭터 그림을 사용하지 않는다.

런타임 그림 경로는 `Resources/Hapio/UI/ThreePlayerLobby/`다. `GameThreePlayerLobbyArt`가 원본 Sprite를 읽고, `GameLobbySeatDesign`과 `GameLobbyCharacterPicker`가 실제 자리·캐릭터 상태에 맞춰 선택한다.

| `SeatHost1`~`SeatHost5` | 해당 캐릭터가 차지한 실제 Host 자리 |

팝업의 표시 순서는 기존 `LabPlayerSlots.CharacterOrder`를 따라 **불이·묵이·솔이·금옥·만복**이다. 화면의 두 번째 항목을 캐릭터 번호 2로 해석하지 않는다.

### 팝업 초상의 세 상태

불이·묵이·솔이·금옥·만복 모두 실제 소유권에 따라 아래 세 상태를 사용한다. 모든 상태를 점선으로 고정하거나 일부 캐릭터만 기본 테두리를 다르게 두지 않는다. 아래 굵기와 점선 간격은 4배 PNG 픽셀 수가 아닌 Figma 원본 단위다.

| 상태 | 초상과 외곽선 | 이름·표식 | 선택 동작 |
| --- | --- | --- | --- |
| 선택 가능 (`Available`) | 굵기 2.5, 점선 `[8, 8]`, 초상 불투명도 1 | 이름 `#746C62`·불투명도 1, 추가 표식 없음 | 누를 수 있음 |
| 다른 참가자가 선택 (`Taken`) | 굵기 1.327868938의 실선, 초상 불투명도 0.25 | 이름 `#746C62`·불투명도 0.56, `Taken` 도장 | 누를 수 없음 |
| 내가 선택 (`Selected`) | 굵기 3의 `#312B23` 실선, 초상 불투명도 1 | 이름 `#312B23`·불투명도 1, `ChoiceCheck` 체크 | 기존 규칙대로 누를 수 있음 |

각 캐릭터는 세 상태의 별도 PNG를 사용한다. `ChoiceTaken`에는 초상의 0.25 불투명도가 이미 포함돼 있으므로 런타임 Image는 흰색·불투명도 1을 유지한다. 런타임에서 알파 0.25를 다시 곱해 초상과 테두리가 원래 의도한 0.25보다 더 흐려지지 않도록 한다. 팝업 이름은 편집 가능한 UI 텍스트로 위 색과 알파를 따로 적용하고, 도장·체크는 해당 상태에서만 한 번 표시한다. 자리 원본에 이미 포함된 이름·방장 표식은 별도 글자로 중복해서 그리지 않는다.

색이 포함된 그림에는 기존 자리 마커 색을 다시 곱하거나 흑백 필터를 추가하지 않는다. 자리 그림·배치·캐릭터를 누른 직후 팝업을 닫는 동작과 기존 인원·모드의 팝업은 그대로 유지한다.

빈 자리의 논리 원 지름 38.347824를 입력 영역 63에 맞춘 공통 배율을 사용한다. 같은 배율에서 찬 자리의 원본 초상 지름 42는 약 69가 되어 빈 자리보다 조금 크게 보인다. 이름·방장 표시가 포함된 전체 원본 PNG를 같은 비율로 표시하고 원래 여백과 위치를 함께 적용하며, 실제 자리 버튼의 입력 영역은 63×63을 유지한다.

## 원본 출처와 다시 불러오기

출처는 Figma `적용되어야할UI` 페이지의 프레임 `5820:31051`, `5820:32875`, `5820:32908`과 캐릭터 섹션 `5820:31181`이다. 각 이미지의 원본 노드·PNG 크기·배율·SHA256은 [FigmaSource.json](../Assets/Hapio/Art/UI/ThreePlayerLobby/FigmaSource.json)에 기록한다.

저장된 PNG는 총 42장으로, 이 중 15장이 다섯 캐릭터의 세 상태 초상이다. Figma의 `node.exportAsync`로 4배 크기에 내보내며 페이지·상위 프레임의 배경을 포함하지 않는 투명도를 유지한다. 초상 이미지·텍스처·색·크롭을 다시 그리거나 이미지 편집으로 바꾸지 않는다. 팝업 바탕은 닫기 그림이 없는 임시 배경 사본으로 내보내고 닫기 버튼을 별도로 연결한다.

세 상태를 명확히 구분하도록 승인된 Figma 참고 상태의 테두리·불투명도 속성을 각 캐릭터의 임시 내보내기 사본에 적용했다. 이는 원본 프레임의 기본 테두리를 그대로 복사하는 방식과 구분되는 의도적인 상태별 보정이다. 초상의 원래 이미지·텍스처·크롭은 유지하고, 상태별 점선·실선·굵기·선택 테두리 색·초상 알파만 위 명세에 맞춘다. 내보내기 후 임시 노드는 제거하며 원본 프레임과 원본 노드는 변경하지 않는다. 원본 출처와 상태별 보정 내용은 FigmaSource.json에 함께 기록한다.

PNG는 `Assets/Hapio/Resources/Hapio/UI/ThreePlayerLobby/`에 있고, `ThreePlayerLobbyArtImporter`가 Sprite·투명 배경·전체 사각형·밉맵 없음·무압축으로 가져온다. 이미 가져온 그림으로 Play하거나 빌드할 때 추가 설정은 필요 없다.

직접 PNG를 교체한 뒤 명시적으로 다시 가져오려면 **`Hapio > UI > Import Three Player Lobby Art`**를 실행한다. 이 메뉴는 해당 폴더의 원본 PNG만 가져오며 Scene·공통 로비 Prefab·방·네트워크 설정을 다시 만들지 않는다. 파일 이름과 캐릭터 번호 대응을 유지하고, 출처·크기·해시가 바뀌면 FigmaSource.json도 함께 갱신한다.

## 기존 표시와의 경계

3인 전용 그림은 저장된 공통 로비를 다른 모드용으로 덮어쓰지 않는다. 인원이나 방 모드가 바뀌면 해당 화면에 맞는 기존 표시로 돌아가며, 이전 3인 팝업의 그림·위치가 4·5인 팝업에 남지 않아야 한다. 2인 스토리는 기존 개발·검사 경로를 포함하고, 일반 방 만들기의 기존 인원 제한을 변경하지 않는다.

일반 게임의 4·5인 자리 배치와 빈 마커, 땅따먹기의 팀 자리와 시작 조건, Lab의 자리 선택은 유지한다. 4·5인 스토리에서 선택한 자리는 #804 공통 원본 컴포넌트를 사용한다. Host를 P1로 고정하거나 캐릭터를 P번호에 자동 대응시키지 않는다. 통신 규약과 공유 설정도 변경하지 않는다.

## 확인할 항목

- 3인 스토리에서 빈 자리 세 개가 원본을 사용하고, 모든 다섯 캐릭터가 선택 가능·다른 사람 선택·내 선택의 세 상태를 정확한 외곽선·알파·표식으로 표시하는지 확인한다.
- Host가 P2에서 만복 등 P번호와 다른 캐릭터를 골라도 정확한 자리의 이름·초상·방장 그림이 연결되는지 확인한다.
- 이미 사용 중인 캐릭터를 눌러도 요청하지 않는지, 다른 캐릭터를 고르면 팝업이 즉시 닫히는지, 닫기만 했을 때 자리가 바뀌지 않는지 확인한다.
- 3인 → 4·5인 전환과 2인 개발·검사 경로에서 기존 팝업이 복원되는지, 땅따먹기 자리 표시가 유지되는지 확인한다.
- 원본 Sprite 참조·입력 영역·가림막과 함께 실제 화면에서 글자 중복·잘림·이중 틴트가 없는지 확인한다.

이 문서의 확인 항목은 검증 기준이다. 실제로 실행한 자동 검사·Editor 화면 확인과 미실행 기기·빌드 범위는 [VALIDATION](VALIDATION.md)에 구분해 기록한다.

## 내 자리 표시 (#804)

Figma `5820:33177`과 `5902:6334`의 네 상태를 따른다. 빈 자리는 기존 표시를 유지한다. 실제 자리 소유자와 로컬 플레이어 ID가 같을 때 `SeatMe1`~`SeatMe5`(나) 또는 `SeatHostMe1`~`SeatHostMe5`(방장+나)를 사용한다. 다른 참가자는 기존 `Seat`·`SeatHost`를 사용한다. 보존 중인 부재중 자리는 나 배지 없이 기존 흐림 표시를 유지한다. 선택 해제·자리 이동·재입장 후에는 소유권으로 다시 표시한다.

진한 테두리·빛 번짐·이름·배지는 원본 PNG에 포함돼 있으며 별도 텍스트나 효과를 중복하지 않는다. 58×73 프레임을 4배 PNG로 내보내 기존 초상 배율을 유지한다. 만복의 위 여백 5, 나머지 7을 적용하고 버튼 입력 영역은 63×63을 유지한다. Scene과 공통 Prefab은 변경하지 않는다. 새 원본 노드·크기·해시는 FigmaSource.json에 기록한다.

### #804 적용 범위 정정

초기 변경의 3인 전용 분기를 제거했다. `GameLobbySeatDesign.PresentStorySeat`가 4·5인에서도 실제 캐릭터·Host·로컬 소유권을 조회하고 동일한 원본 Sprite와 크기를 적용한다. 원본 이름과 배지를 포함한 전체 프레임을 표시하므로 별도 이름·방장 문구를 중복하지 않는다. 빈 자리는 각 인원의 기존 마커로 복원한다. `5902:6335`는 컴포넌트 시트에 따로 놓인 2×2 갈색 점으로, 독립 화면이나 추가 자리 상태가 아니다. 만복 방장 원본 안에도 해당 점이 포함돼 있으므로 UI 위에 장식으로 추가하지 않는다.

5인 배치 위쪽 두 자리의 이름은 원본 컴포넌트를 두 RectMask2D 영역으로 나눠 위에 표시한다. 초상과 이름 모두 같은 원본 Sprite 픽셀을 사용하며 PNG를 자르거나 글자를 다시 그리지 않는다. 다른 자리는 전체 원본 프레임을 표시한다. 빈 자리나 다른 인원·팀 모드로 바뀌면 분리 표시를 끄고 기존 Image 표시로 복원한다.
