## 시계와 결과

같은 ScreenLayoutConfig 원본에 Battle Duration180초·Team HP decay1/초를 추가했다. Host가 시작할 때 새 roundId와 단조 시계의 시작/종료 시각을 확정한다. Team HP는 남은 시간×감소율이다. Lobby·Ready·Result는 감소하지 않으며 클라이언트는 Host가 보낸 값을 표시한다.

호스트의 실제 충돌 처리 시각이 deadline보다 엄격히 작을 때만 기존 AttackAuthority에 피해를 전달한다. 그 한 충돌의 처리 시각을 피해·공격자 회복·승패 판단까지 고정하므로 중간 관찰자 콜백이 더 늦은 시간을 읽어 마지막 유효 +5를 누락하지 않는다. 피해·Consumed와 +5를 먼저 확정한 후 HP0·시간양수면 Victory다. deadline와 같거나 이후면 Defeat며 결과는 바뀌지 않는다. 결과 진입 시 자원 정지 snapshot을 먼저 발행하고 Pending·입력·남은 투사체를 정리한다.

OS 중단 후 복귀해도 전투 제한 시간은 연장되지 않는다. 개인 자원은 기존 규칙대로 OS pause 구간을 자동 회복하지 않는다. 이 두 정책은 구분된다. 실제 suspend 시간에 대한 이번 기기 검증 여부는 T09_VALIDATION을 따른다.

## 시작과 Reset

기본 모드는 인증된 참가자2명이 필요하다. 한 참가자는 Lobby이며 Host Start·Generate가 막힌다. 명시적인 개발용 DEV SOLO를 연결 전에 켠 경우만 한 참가자 Ready를 허용한다. 어느 모드든 Host Start를 별도로 누른다. 자동 탐색·별도 Ready 교환·버전 호환 handshake는 T10-A 범위다.

Host Retry/Lobby는 새 라운드 Ready 또는 참가자 부족 Lobby로 돌아간다. 구슬·투사체·HP·Stamina·Pending·포인터·개발 Fixture 상태를 초기화하고 Host Start를 다시 요구한다. Start도 새 문맥을 만들어 이전 요청이 새 판에 적용되지 않는다. 단순 봉투 전송 성공과 Host의 요청 거부는 구분한다. Close/END는 연결을 종료하며 자동 재연결은 하지 않는다.
