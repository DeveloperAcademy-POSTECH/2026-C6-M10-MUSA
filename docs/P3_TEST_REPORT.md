## 확인 결과

최종 전체 실행 XML은 **EditMode 1,188개와 PlayMode 123개, 합계 1,311개 PASS**다. 실패·건너뜀·판정 불가는 모두 0개다. XML 선언 수치와 실제 `test-case` 항목 수, 매개변수를 포함한 전체 테스트 이름의 중복 여부를 확인했다.

각 실행의 실제 결과 JSON, 오류 첫 줄, 실행 파일·시험 도구 해시, 기기별 결과 해시는 [원본 비공개 자료: tests.json — 공개 요약](VALIDATION_SUMMARY.md)에 기록했다. 네 실행 모두 종료되지 않은 새 시험 프로세스는 0개였다. 두 번째 실패에서 초기 상태 확인이 끝났다는 사실을 게임 기능 전체 PASS로 해석하지 않았다.

위 초기 보고 시점에는 최종 Mac 재검증이 미실행이었다. 후속 r8의 2·3·4·5인 실행은 모두 PASS이며 총654개 공통 상태가 일치했다. iOS 앱 빌드·서명도 PASS다. 설치·실행·직접 터치는 NOT_RUN을 유지한다. 최종 결과는 별도 [P3_VALIDATION.md](P3_VALIDATION.md)와 해당 실행 증거에서 갱신한다. Mac의 합성 포인터 입력은 직접 터치나 Bonjour 탐색의 검증으로 표시하지 않는다.

## 최종 앱과 전체 테스트 실행 시점

전체 `edit-3`·`play-2` 실행 후 좁은 화면의 5인 스태미나 표기를 줄이고 Mac 전용 진단의 대기·캡처를 정리했다. 이 마지막 표시·진단 변경 후 전체1,311개를 재실행했다고 기록하지 않는다. 변경이 포함된 동일 최종 앱으로 r8의 2·3·4·5인 전체 시나리오를 재실행했으며, 각각123·138·161·232개 전원 공통 상태와 최종 P5 자원 표시가 PASS다.

r5 4인 실패는 마지막 참가자의 Ready보다 늦게 미Ready를 검사한 진단 순서 문제였고, r6 3인 실패는 Retry 뒤 도착한 새 라운드를 이전 라운드로 저장한 진단 문제였다. 단계별 대기와 이전 라운드 캡처 순서를 수정했다. r7 전체 PASS도 중간 결과로 보존하고 최종은 r8로 한정한다. [원본 비공개 자료: Mac 실행 이력과 원본 요약 — 공개 요약](VALIDATION_SUMMARY.md)·[전체 최종 보고](P3_VALIDATION.md)를 따른다.
