# C6 Physics Lab 범위와 검증 기준

작성 기준: Unity **6000.6.5f1** 신규 프로젝트의 코드·설정 구조. **이 문서는 구현 범위와 확인할 동작을 정리하며 실행 결과를 주장하지 않는다.** 구 프로젝트의 코드·Scene·그래픽을 통째로 이식한 버전이 아니다.

## 포함하는 동작

| 범위 | 현재 실험실의 규칙과 책임 |
| --- | --- |
| 연결 | 같은 로컬 네트워크에서 Host가 일반 로비의 **ROOM PLAYERS**로 **2~5명** 목표 인원 N(기본 3명)을 정한다. DEV 인원 선택도 같은 목표값을 사용하며, 인원은 방 생성 전에만 변경한다. 기본 포트는 `7777`이며 방 목록에서 선택하거나 Host 주소를 직접 입력해 참가한다. IPv4/IPv6 연결을 시도하고 핫스팟도 실제 기기에서 별도 검증한다. 연결 후 Host는 P1, 참가자는 접속 완료 순서대로 P2~PN을 자동 배정한다. 목표 인원이 모이고 전원 설정 확인을 마친 뒤 시작한다. P번호의 오름차순으로 360°/N 간격의 고리를 만들며 PN 다음은 P1이다. 2인 판에서는 좌우가 같은 상대다. |
| 방 이름·조회 | 앱 시작 시 기존 LOCAL ROOMS 패널에서 Bonjour 자동 검색. 검색 중에도 CREATE ROOM·인원 조정·DEV 사용 가능. 목록의 이름을 명시적으로 눌러 입장하며 Host/Client 모두 확인된 이름을 공유한다. 접속 중 목록·선택 행 유지, 중복 요청 차단, 취소 후 NGO 종료 완료를 기다려 검색 복귀. 실패 원인은 다음 명시 동작까지 유지하고 검색 자체 실패는 REFRESH로 재시도한다. 새로고침 캐시는 최대 5초 보존하지만 새로 확인된 주소가 없는 행은 선택 불가. 5초간 결과가 없으면 안내하면서 검색을 계속한다. IP·포트·JOIN은 DIRECT IP로 펼친다. 같은 방 IPv4/IPv6 경로와 12초/60초 기준은 유지한다. 실시간 인원/전투 상태 광고는 없다. |
| 세션 설정 | Editor·Development Build의 Host는 DEV 패널에서 고정 목표를 포함한 118개 설정을 확인하고 조정 가능한 값을 네트워크 방에 적용할 수 있다. 기존 필드의 순서는 유지하고, 끝에 요괴 피격 회전 3개(#115), 생성 퍼짐 각도·최소/최대 속도 3개(#117), 소리 음량·햅틱 11개(#142), 생성 북 개수·크기·떠돌기 속도·방향 전환·회전 세기 5개(#137)를 추가했다. 박 모드 통합에서는 80번째(인덱스 79)에 `Gourd Mode (0 paint, 1 crack)`를 덧붙였고 이전 79개 인덱스는 유지한다. 그 뒤 81~84번째(인덱스 80~83)에 폭탄 충격파 범위·세기와 폭발 진동 종류·세기 4개(#167)를, 85~87번째(인덱스 84~86)에 결합 소리 크기와 결합 진동 종류·세기 3개(#172)를 덧붙였다. 88번째(인덱스 87)의 기존 색칠 승리 비율 행은 100% 고정(허용 100~100, 읽기 전용·슬라이더 비활성)으로 유지한다. 89·90번째(인덱스 88·89)에 박 폭탄 간격 최소·최대(초, 기본 20·30, 최대 0이면 끔)를, 91번째(인덱스 90)에 도화선 치지직 소리 크기(50 = Inspector)를 덧붙였다(#177). 92~99번째(인덱스 91~98)에 북 멈춤 구간 경계 4개(기본 20·40·60·80%)와 가까운 쪽·가운데·먼 쪽·통과 확률 4개(기본 40·35·15·10%, 합 100)를 덧붙였다(#178). 100~103번째(인덱스 99~102)는 미니맵 켜기/끄기·크기·좌우·상하 위치다(#181). 104·105번째(인덱스 103·104)는 폭탄 소리 크기와 종류(BOOM/PPEONG)다(#183). 기존 0~104번을 유지하고 106~111번째(인덱스 105~110)에 색칠 해상도·초기 면적·반복 공급량·전역 성장 속도·채움 확률·세로 가중치 6개를 덧붙였다(#187). 112~118번째(인덱스 111~117)에 Arc/Straight 폼·직구 출발 오프셋 XYZ·발사각·떠오름 비율·중력 배율 7개를 추가했으며 이전 0~110번 순서를 유지한다(#190). 직구 전용 6개 행은 ARC에서 비활성화하고 STRAIGHT에서 숫자/슬라이더로 조정한다. 17·18번은 #137에서 생성 연출이 바뀌며 북에서 튀어나오는 처음 크기·시간으로 의미가 바뀌었다. 참가자에게 동일 설정을 전파하고 확인을 받은 뒤 START를 허용한다. 로비에서 다시 조정하면 이전 확인을 무효화한다. 전투 도중에는 일시정지한 Host만 설정을 갱신하고 참가자 확인 뒤 새 판으로 재시작할 수 있다. 진행 중인 판의 값은 바꾸지 않으며 원본 설정 에셋도 저장하지 않는다. 솔로 조정 경로는 별도다. |
| 생성·자원 | 시작 구슬 0개. 판마다 Host가 생성 북(기본 1개, DEV 1~5개)을 받을 사람을 무작위로 정한다(북이 인원 이하이면 서로 다른 사람). 북이 있는 사람만 자기 판의 북을 탭해 생성할 수 있다. 북은 구슬처럼 끌고 좌우로 튕겨 이웃에게 넘기며(위로 던져지지 않음), 수명·보관 한도·조합·폭탄의 대상이 아니다. 넘길 때마다 Host가 받는 판의 도착 방식을 정한다(#178): 스와이프는 들어온 가장자리에서 판 폭 20~40%·40~60%·60~80% 구간(40·35·15%)의 한 지점에 멈추거나 그다음 사람에게 통과(10%), 앞 판을 통과해 온 북은 가까운 쪽 구간, 폭발에 밀려 넘어온 북은 제 속도로 미끄러지되 80% 안에서 멈춘다. 받는 화면은 들어온 속도를 이어받아 멈출 자리까지 필요한 만큼만 감속하고(최대 8 판 폭/초², 늦어도 1.2초 안 도착), 통과면 최소 0.9 판 폭/초로 반대편까지 간다. 잡기·폭발·전달 거절이 도착을 끝낸다. 가만히 두면 사방으로 천천히 떠돌고 회전하되, 혼자서는 이웃 화면으로 넘어가지 않는다. 탭 한 번에 Host가 Yin·Yang·아이템 4종(릴레이 구슬·시크릿 상자·회복물약·폭탄) 중 하나를 설정 확률(기본 50/50/0/0/0/0, 아이템은 DEV로 다시 켤 수 있음)로 정한다. 매 생성은 독립 추첨이며 같은 극성이 이어져도 보정하지 않는다. 구슬은 북 위치에서 360° 무작위 방향(Host 추첨)으로 튀어나오며, 향하는 옆 가장자리에 닿기 전에 멈출 속도로 제한한다. 나오는 0.15초 동안은 다른 구슬·북과 부딪히지 않는다. 한 개를 만들 때 개인 스태미나 20 소모. 100에서 시작하고 1.7초당 20(초당 약 11.8) 회복. 유효 명중의 실제 공격자에게만 10 회복. 보유 한도 20개. |
| 조합 | Raw Yin과 Raw Yang을 직접 드래그해 겹쳐 놓거나, 기본적으로 켜진 접촉 자동 결합 조건에서 서로 부딪히면 Combined 한 개를 만든다. 같은 극성 및 아이템은 결합하지 않는다. 두 Raw ID는 사라지고 Combined에 새 ID가 생긴다. 결합 순간 Host가 오행 속성(화·수·목·금·토)을 같은 확률로 정하고 스냅샷으로 모든 화면에 같은 값을 전달한다. 접촉 결합과 속도 기준은 DEV 설정값에 따른다. |
| 아이템 | 폭탄을 뺀 아이템은 잠긴 채 생성되며 잠금 횟수는 설정 범위(기본 2~4)에서 무작위다. 이웃 화면으로 넘어가는 전달을 Host가 승인할 때마다 1씩 줄고 0이면 해금된다. 1인 플레이에는 이웃이 없어 해금되지 않는다. 구슬 정면에 아이콘, 오른쪽 아래에 남은 횟수 배지를 표시하고, 잠긴 동안은 아이콘을 흐리게 하고 자물쇠를 겹친다. 마지막 잠금을 푸는 전달을 받은 화면에서만 자물쇠가 떠오르며 사라지고 금색 원이 구슬로 줄어든 뒤 한 번 반짝인다(약 0.6초). 처음부터 풀린 채 생긴 아이템, 늦게 본 해금, 그 뒤의 전달에는 연출이 없다. 폭탄에는 잠금이 없다(DEV 잠금 횟수와 무관). |
| 아이템 효과 | 해금된 **회복물약·시크릿 상자**는 같은 구슬을 0.35초 안에 두 번 탭해 그 자리에서 사용한다. 물약은 사용자의 개인 HP를 10(설정) 올리며 최대 HP를 넘지 않는다. HP가 가득 차 있으면 거절하고 물약을 남기며, HP 0인 플레이어는 쓸 수 없다. 상자는 양옆에 속성 구슬 2개를 만들고(새 8초 수명) 보관 칸이 하나 더 필요하다. **릴레이 구슬**은 해금 순간 ×1, 이후 이웃 전달마다 ×2·MAX로 오르며 배지 자리에 단계를 표시하고, 던지면 기본 피해 × 1·2·4(설정)를 준다. **폭탄**은 잠금이 없고 던질 수 없으며, 전달해도 도화선이 다시 시작되지 않는다. 몸통에 남은 초를 빨간 숫자로 표시하고, 남은 3초부터 빨갛게 점점 빠르게 깜빡인다. 아이템 수명(기본 15초)이 끝나면 Host가 그 순간 보유자에게 폭탄의 마지막 위치를 담은 폭발 신호를 보낸다. 보유자 화면에서 만화풍 섬광과 "BOMB!", 진동과 함께 폭탄이 사라지고, 범위(기본 판 폭 40%) 안의 구슬·북·잡고 있던 구슬을 거리에 따라 밀어낸다(기본 세기 9 판 폭/초, 범위 끝에서 0). 구슬은 사라지지 않으며, 옆 가장자리를 넘은 것은 보통 전달처럼 이웃에게 가고 잠긴 아이템은 잠금이 1 준다. Host 응답을 기다리는 구슬과 떨어지는 중인 박 폭탄은 밀지 않는다. 폭탄 기믹은 이후 다시 다듬을 예정이며, 지금은 `Bomb Damage Multiplier`와 폭탄 사용 기록이 쓰이지 않는다. |
| 박 폭탄 (#177) | Host가 라운드 시작부터 `Gourd Bomb Interval Min`~`Max`(기본 20~30초, 매번 새로 추첨, 최소 1초, 최대 0이면 끔) 간격으로 무작위 한 명의 판에 폭탄(출처 `Gourd`)을 만든다. 가득 찬 판에도 넣고, 같은 사람 연속을 허용하며, 스태미나를 쓰지 않는다. 대상·착지 위치(판 폭 20~80%)·간격은 세션·라운드 seed의 Host 추첨이다. 모든 화면은 전투 화면 박 옆에 "!" 말풍선(약 1.4초)을 띄우고, 받는 화면은 착지 지점 "!" 경고 0.6초 → 구슬판 위쪽에서 낙하 0.45초 → 두 번 튐 0.45초 뒤에야 잡기·충돌·떠돌기를 허용한다. 폭탄은 몸통·꼭지/도화선 두 장의 그림으로 그리며, 움직인 만큼 굴러 꼭지가 공 둘레를 돌되 몸통 뒤로 숨지 않는다. 혼자 북처럼 떠돌며(북 떠돌기 값 공유) 혼자서는 이웃 화면으로 넘어가지 않는다. 도화선 끝 불꽃과 치지직 소리(마지막 3초에 커지고 빨라짐, DEV `Fuse Sound Volume`)는 보유자 화면에만 있다. |
| 3D 조합판 물리·전달 | PR #154의 종이판·HUD 배치를 유지하며 물리만 보이는 곡선에 맞춘다. `LabOrbAreaProfile`에 저장한 종이판 상하 윤곽과 HUD 불투명 상단 윤곽을 합성해 하단 경계를 계산한다. 그림을 줄이거나 옮기지 않으며 직사각형 HUD 잘라내기·추가 여백은 없다. 구슬·북의 실제 반지름을 반영하고 화면/곡선 변경에는 ID·위치 비율·속도·요청 상태를 보존한다(드래그 중 보류). 소유자 화면의 `Rigidbody`·`SphereCollider`를 XY 평면에 제한하며 상하 곡선의 정적 `MeshCollider`에서 반발한다. 좌우는 열어 Host 승인 뒤 같은 ID·보드 폭 기준 속도·곡선 통로의 상대 높이로 이웃에게 전달한다. 중복 전달은 승인하지 않는다. |
| 투척·피격 | Combined(해금된 릴레이 구슬 포함, 폭탄은 던질 수 없음)를 위쪽으로 움직이며 손을 놓는 입력으로 방향·세기를 구한다. 기본 Arc는 기존 계산을 유지하고 선택 가능한 Straight는 기존 초기 속력·수평 조준을 보존하면서 소유자 자리 기준 출발점·상향각·중력을 조절한다. 카메라와 위로 스와이프하는 입력 판정은 유지한다. 두 폼 모두 표시 구체와 실제 충돌체가 같은 루트의 위치를 따른다. Host의 3D Rigidbody 투사체가 **박 외형 안의 기존 Unity Cylinder MeshCollider**에 실제로 맞아야 HP·명중 보상·색칠을 반영한다. 빗나감은 피해·보상·색칠을 만들지 않는다. Host 모델은 구슬 소모·HP 실제 감소량·명중 효과 값·색칠·승리를 원자적으로 확정하고, 시간 종료를 먼저 판정하므로 종료 시각 이후 명중으로 뒤집지 않는다. Crack은 실제 감소 HP 숫자를, Paint는 숫자를 숨기고 속성색 입자·색칠을 표시한다. Paint의 내부 HP가0이어도 승인 명중의 입자·소리/햅틱·보상은 계속된다. 기존 비행 잔상·ParticleSystem 코어/스파크/충격파와 Host 피격 회전·스냅샷 보정은 유지한다. |
| 박 표현 모드·색칠 | `LabConfig.GourdMode`는 Paint(0, 기본) 또는 Crack(1)이다. 기존 초기/`ConfigApplied` 경로에서 `LabGourdPaint.Attach`·`ApplyMode`가 표현을 연결한다. Paint는 선택한 64×32·128×64·256×128 동일 면적 구면 셀 맵을 사용한다. 새 지점 명중은 초기 면적을 즉시 칠하고, 이미 칠한 곳 명중은 해당 연결 영역에 성장 예산을 공급한다. Renderer 재생성은 Host 진행도를 지우지 않는다. 일반 Retry는 캡처 설정을 유지하고 맵·예산·난수 진행을 초기화한다. 두 모드는 원통 Collider·물리·회전·명중 보상을 공유한다. |

## 수정 지점과 교체 경계

`Assets/Lab/Resources/LabConfig.asset`이 수치 설정 원본이다. 여기서 요괴/개인 HP, 요괴 피해, 시간, 스태미나, 생성 확률, 구슬·아이템 수명, 아이템 잠금 횟수, 조합판 구슬의 3D 접촉 탄성·평면 감속, 투척 파라미터를 바꾼다. 코드는 설정을 읽어 판정하고 UI는 확정된 값을 표시한다. Host 확정 스냅샷만 요괴/개인 HP·시간·구슬 상태·색칠 진행도/목표/승패의 기준이다. 박 표현은 같은 Config의 Inspector `Gourd Mode`에서 선택하며, 저장 필드가 없는 기존 에셋은 코드 기본값 Paint를 사용한다. DEV의 80번째 모드·88번째 고정 목표·106~111번째 성장 설정은 솔로 시작/재시작·Host 방 생성/로비 적용·일시정지 후 적용/재시작 경로로만 적용하고 Client는 Host 설정을 따른다. 진행 중 Inspector 수정만으로 표현을 즉시 전환하는 기능은 아니다.

`Assets/Lab/Scenes/Lab.unity`의 Canvas, RectTransform, 카메라와 컴포넌트 참조는 Hierarchy/Inspector에서 배치한다. `LabHud`는 저장된 UI에 값을 연결하며 UI의 위치를 코드로 다시 만들지 않는다. `LabImpactFeedback`은 같은 Canvas에서 Crack 명중의 속성색 실제 피해 숫자를 그리며 Paint에서는 숫자를 숨긴다. 연결된 `LabImpactParticleVfx`는 별도 월드 공간의 풀링된 `LabImpactParticleBurst` 프리팹으로 코어·스파크·확대 충격파를 낸다. 피격점은 Cylinder의 Hitbox 로컬 좌표로 유지해 흔들리는 대상에 따라가며, 입자는 판정용 Collider나 추가 네트워크 메시지를 만들지 않는다. 표시 수명·풀 크기 등은 각 컴포넌트/프리팹의 Inspector 값으로 조정한다. 조합판 구슬은 ID·`SphereCollider`·`Rigidbody`를 가진 루트와 별도 `Visual` 자식으로 나뉜다. 조합판 구슬과 투사체는 공통 Unity 3D 구체 표현을 사용하지만, 조합판에서는 XY 평면 물리, 투척 뒤에는 3D 비행을 각자의 루트에서 처리한다. 속성별 재질·투척 잔상 머티리얼, 아이템 아이콘·자물쇠·생성 북 이미지와 잠금·해금 연출 값은 `Assets/Lab/Art/Orbs/LabOrbAppearance.asset`에서 교체한다(아이콘·자물쇠 원본은 `Assets/Lab/Art/Items/`). 아이템 아이콘·자물쇠·배지·해금 연출은 구슬 루트에 붙어 굴러도 회전하지 않으며 충돌체를 갖지 않는다. Cylinder 요괴도 피격 Collider와 교체용 시각 Mount를 나눈다. 향후 그림 에셋이 완성되면 **시각 자식만 바꾸고 판정·소유권·물리 루트는 유지**한다.

네트워크의 구슬 상태는 물리 컴포넌트가 아니라 기존의 ID·소유자·정규화한 XY 위치/속도·수명이다. 소유자가 자기 화면에서 물리를 계산하고, 좌우 전달은 Host 승인 뒤 동일 ID와 평면 운동량을 다음 소유자에게 넘긴다. 피격 숫자·입자 효과·회전은 Client 투사체의 독자 충돌이 아닌 Host의 확정 신호(구슬 ID·라운드·속성·실제 피해·별도 명중 효과 값·요괴 기준 피격점·충돌 속도·회전 충격량)로 시작하고, 회전 각도·속도는 Host 스냅샷으로 보정한다. 입자 효과만을 위한 네트워크 메시지는 없다. 아이템 사용 요청·릴레이 단계·해금 시각·폭발 알림과 일시정지 상태, 생성 북의 소유자·위치와 넘겨받을 때의 도착 방식(`arrival`·`stopAt`·`arrivedAt`, 1초 안의 전달만 적용)도 Host 스냅샷에 포함되고, 로비 패킷에는 자동 P번호와 확인된 방 이름이 포함된다. 박 폭탄 신호(받는 사람·폭탄 ID·착지 위치)는 모든 참가자에게, 그 폭탄이 처음 담긴 스냅샷보다 먼저 같은 순서 채널로 보낸다. 박 모드·목표 비율·폭탄 충격파·결합 소리/햅틱·박 폭탄 간격·도화선 소리·북 멈춤 구간·미니맵 켜기/끄기·크기·위치, 폭탄 소리 크기·종류와 성장 6개·직구 폼 7개를 포함한 118개 설정, 셀 delta/체크포인트·색칠 메타데이터·명중 효과 값과 기존 폭발/결합 승인·박 폭탄 알림·북 넘김 이유(스와이프·통과 중·폭발)의 프로토콜은 **5629**이며 이전 빌드와 같은 방에 들어갈 수 없다. 모든 참가자가 같은 새 버전 앱을 사용해야 한다.

Host의 권위 상태는 `LabModel.PaintSurface` 하나이며, 성장 계산은 Host의 전투 시간 진행에서만 한다. Host 화면도 현재 Snapshot과 같은 버전의 `LabNetwork.PaintSurface` 표시 캐시를 사용해 맵과 HUD를 함께 반영한다. Client는 승인 명중 방향을 재생해 성장시키지 않고 Host가 보낸 셀 변경(delta) 또는 전체 체크포인트를 별도 수신 맵에 적용한다. 분할 수신 중에는 기존 공개 표시 캐시를 유지하고, 완성된 맵의 세션·라운드·해상도·Revision·칠한 셀 수·전체 셀 수·명중 수가 Snapshot 메타데이터와 모두 맞을 때 맵과 HUD를 함께 공개한다. 픽셀이 그대로인 반복 명중도 명중 수가 바뀌면 빈 delta를 발행한다.

전송은 프로토콜 **5629**의 `paint_cells`·`paint_resync` 경로를 사용한다. 셀 ID와 RGBA를 담은 delta보다 전체 맵이 작으면 전체 맵을 보낸다. base64 데이터는 조각당 최대 4,096자, 수신 조각 수는 최대 64개이며 기존 패킷 한도 32 KiB 안에서 전송한다. 최대 해상도 전체 RGBA 맵은 131,072바이트이고 base64 174,764자를 43개로 나눈다. 수신 시 헤더·기준 Revision·셀 ID 범위와 순서·payload 크기·알파/색·칠한 셀 수·SHA-256 해시를 검사한 뒤 전체 맵을 한 번에 교체한다. 중복 완료·이전 전송/스냅샷 번호·이전 라운드를 거절하고, 기준 맵 누락이나 손상에는 Host의 마지막 발행 맵 복사본으로 체크포인트를 요청한다. `sequence`는 연결 전체의 색칠 전송 번호, `epoch`는 그 맵을 발행한 게임 Snapshot 번호다. 체크포인트는 같은 맵 버전의 `epoch`를 유지하며 `sequence`는 새 번호로 증가한다.

이 복구는 **현재 라운드에 계속 연결된 Client의 부분 맵 누락**을 복원하는 기능이다. 연결이 끊어진 뒤 전투에 재접속하는 기능은 포함하지 않는다. 실제 다중 앱·기기에서의 전송과 화면 일치는 자동 패킷 fixture와 구분해 검증한다.

`LabGourdPaint`는 공개 표시 캐시의 객체·해상도·Revision 변경 때 같은 RGBA 맵을 linear RGBA32 텍스처로 올린다. Point 샘플링·U 반복/V 고정·mipmap 없음으로 칠한 셀과 같은 범위를 보인다. 성장 셀은 불투명이고 진행도는 정수 셀 수의 양자화된 비율이다. 직접 `Paint`/`ClearPaint`·기존 부드러운 `Stamp`는 연결 전 미리보기 전용이며 연결 중 Host 상태를 변경하지 못한다.

새 코드는 `Core`, `Session`, `Orb`, `Throw`, `UI`로 책임을 나눈다. 과거 `T01`·`T09` 같은 단계별 클래스나 Scene을 새 프로젝트에 쌓지 않는다. 단계 이력은 로컬 Git 커밋으로 추적한다.

- Photon·Relay·인터넷 매치메이킹
- 구 프로젝트의 전체 테스트 이식

이는 새 실험실의 **의도적인 제외 범위**다. 과거 프로젝트의 지원 여부와 동일하다는 뜻은 아니다.

## 투구폼 비교 (#190)

기본값은 기존 `Arc`다. `LabConfig.asset` Inspector의 `Projectile throw form` 또는 DEV의 `Throw form`에서 `Straight`를 고른다. 직구 기본값은 **DEMO_TUNING_VALUE**로 오프셋 `(0.35, 0.4, 0)`, 발사각 오프셋 `3°`, 기존 상승각 비율 `0.1`, 기존 중력 배율 `0.1`이다. 기존 Arc의 최종 초기 속력·수평 방향을 재사용하며 직구 최종 상승각은 `clamp(Arc 상승각 × 비율 + 오프셋, -30°, 60°)`다. 발사 순간 중력·수명을 캡처하므로 이미 날아가는 공은 이후 설정 변경으로 꺾이지 않는다. 입력·자동 조준 여부·물리 충돌·색칠은 기존 경로를 따른다. 모드/설정은 공유 118개 값과 지문에 포함되며 프로토콜 5629로 이전 앱과 분리한다. 범위·사용 순서·극값의 한계는 [투척 조정 가이드](THROW_TUNING_GUIDE.md), 실제 실행 결과는 [검증 기록](VALIDATION.md)을 참조한다.
