| 아이템 효과 | 해금된 **회복물약·시크릿 상자**는 같은 구슬을 0.35초 안에 두 번 탭해 그 자리에서 사용한다. 물약은 사용자의 개인 HP를 10(설정) 올리며 최대 HP를 넘지 않는다. HP가 가득 차 있으면 거절하고 물약을 남기며, HP 0인 플레이어는 쓸 수 없다. 상자는 양옆에 속성 구슬 2개를 만들고(새 8초 수명) 보관 칸이 하나 더 필요하다. **릴레이 구슬**은 해금 순간 ×1, 이후 이웃 전달마다 ×2·MAX로 오르며 배지 자리에 단계를 표시하고, 던지면 기본 피해 × 1·2·4(설정)를 준다. **폭탄**은 잠긴 동안 던질 수 없고, 전달해도 도화선이 다시 시작되지 않는다(#212). 몸통에 남은 해금 횟수를 빨간 숫자로 표시하고, 남은 3초부터 빨갛게 점점 빠르게 깜빡인다. 잠긴 채 아이템 수명(기본 15초)이 끝나면 Host가 그 순간 보유자에게 폭탄의 마지막 위치를 담은 폭발 신호를 보낸다. 보유자 화면에서 만화풍 섬광과 "BOMB!", 진동과 함께 폭탄이 사라지고, 범위(기본 판 폭 40%) 안의 구슬·북·잡고 있던 구슬을 거리에 따라 밀어낸다(기본 세기 9 판 폭/초, 범위 끝에서 0). 구슬은 사라지지 않으며, 옆 가장자리를 넘은 것은 보통 전달처럼 이웃에게 가고 잠긴 아이템은 잠금이 1 준다. Host 응답을 기다리는 구슬과 떨어지는 중인 박 폭탄은 밀지 않는다. 해금된 폭탄은 Combined처럼 던져 `Bomb Damage Multiplier`(기본 3배) 피해를 주고 던진 수는 폭탄 사용 기록에 센다. 빗나가거나 수명이 끝나도 터지지 않는다. |

## 수정 지점과 교체 경계

`Assets/Lab/Resources/LabConfig.asset`이 수치 설정 원본이다. 여기서 요괴/개인 HP, 요괴 피해, 시간, 스태미나, 생성 확률, 구슬·아이템 수명, 아이템 잠금 횟수, 조합판 구슬의 3D 접촉 탄성·평면 감속, 투척 파라미터를 바꾼다. 코드는 설정을 읽어 판정하고 UI는 확정된 값을 표시한다. Host 확정 스냅샷만 요괴/개인 HP·시간·구슬 상태·색칠 진행도/목표/승패의 기준이다. 박 표현은 같은 Config의 Inspector `Gourd Mode`에서 선택하며, 저장 필드가 없는 기존 에셋은 코드 기본값 Paint를 사용한다. DEV의 박 모드·성장·관람 허용 설정은 솔로 시작/재시작·Host 방 생성/로비 적용·일시정지 후 적용/재시작 경로로만 적용하고 Client는 Host 설정을 따른다. 진행 중 Inspector 수정만으로 표현을 즉시 전환하는 기능은 아니다.

`Assets/Lab/Scenes/Lab.unity`의 Canvas, RectTransform, 카메라와 컴포넌트 참조는 Hierarchy/Inspector에서 배치한다. `LabHud`는 저장된 UI에 값을 연결하며 UI의 위치를 코드로 다시 만들지 않는다. `LabImpactFeedback`은 같은 Canvas에서 Crack 명중의 속성색 실제 피해 숫자를 그리며 Paint에서는 숫자를 숨긴다. 연결된 `LabImpactParticleVfx`는 별도 월드 공간의 풀링된 `LabImpactParticleBurst` 프리팹으로 코어·스파크·확대 충격파를 낸다. 피격점은 Cylinder의 Hitbox 로컬 좌표로 유지해 흔들리는 대상에 따라가며, 입자는 판정용 Collider나 추가 네트워크 메시지를 만들지 않는다. 표시 수명·풀 크기 등은 각 컴포넌트/프리팹의 Inspector 값으로 조정한다. 조합판 구슬은 ID·`SphereCollider`·`Rigidbody`를 가진 루트와 별도 `Visual` 자식으로 나뉜다. 조합판 구슬과 투사체는 공통 Unity 3D 구체 표현을 사용하지만, 조합판에서는 XY 평면 물리, 투척 뒤에는 3D 비행을 각자의 루트에서 처리한다. 속성별 재질·투척 잔상 머티리얼, 아이템 아이콘·자물쇠·생성 북 이미지와 잠금·해금 연출 값은 `Assets/Lab/Art/Orbs/LabOrbAppearance.asset`에서 교체한다(아이콘·자물쇠 원본은 `Assets/Lab/Art/Items/`). 아이템 아이콘·자물쇠·배지·해금 연출은 구슬 루트에 붙어 굴러도 회전하지 않으며 충돌체를 갖지 않는다. Cylinder 요괴도 피격 Collider와 교체용 시각 Mount를 나눈다. 향후 그림 에셋이 완성되면 **시각 자식만 바꾸고 판정·소유권·물리 루트는 유지**한다.

네트워크의 구슬 상태는 물리 컴포넌트가 아니라 기존의 ID·소유자·정규화한 XY 위치/속도·수명이다. 소유자가 자기 화면에서 물리를 계산하고, 좌우 전달은 Host 승인 뒤 동일 ID와 평면 운동량을 다음 소유자에게 넘긴다. 피격 숫자·입자 효과·회전은 Client 투사체의 독자 충돌이 아닌 Host의 확정 신호(구슬 ID·라운드·속성·실제 피해·별도 명중 효과 값·요괴 기준 피격점·충돌 속도·회전 충격량)로 시작하고, 회전 각도·속도는 Host 스냅샷으로 보정한다. 입자 효과만을 위한 네트워크 메시지는 없다. 아이템 사용 요청·릴레이 단계·해금 시각·폭발 알림과 일시정지 상태, 생성 북의 소유자·위치와 넘겨받을 때의 도착 방식(`arrival`·`stopAt`·`arrivedAt`, 1초 안의 전달만 적용)도 Host 스냅샷에 포함되고, 로비 패킷에는 Host가 승인한 P번호 점유표와 확인된 방 이름이 포함된다. P번호 선택·해제는 기존 로비 요청/결과 경로로 전달하며, 중복 요청·이미 점유한 번호·전투 중 변경은 Host가 거절한다. 클라이언트는 승인 응답이 지정한 로비 Revision 이상의 확정 점유표까지 받은 뒤 승인 대기를 끝내며, 거절·5초 시간 초과 시 다시 선택할 수 있다. 박 폭탄 신호(받는 사람·폭탄 ID·착지 위치)는 모든 참가자의 제어 통신으로 보내며, 새 보드 상태를 발행하기 전에 알린다. 공동 스냅샷/도색 Bulk와 제어 통신 사이의 도착 순서는 보장하지 않는다. 박 모드·폭탄 충격파·결합 소리/햅틱·박 폭탄 간격·도화선 소리·북 멈춤 구간·미니맵 켜기/끄기·크기·위치, 폭탄 소리 크기·종류와 성장 6개·완성 박 관람 허용을 포함한 166개 설정, 셀 delta/체크포인트·색칠 메타데이터·명중 효과 값과 기존 폭발/결합 승인·박 폭탄 알림·북 넘김 이유(스와이프·통과 중·폭발)의 프로토콜은 **5652**, 연결 토큰은 `C6PhysicsLab/15`이며 이전 빌드와 같은 방에 들어갈 수 없다. 모든 참가자가 같은 새 버전 앱을 사용해야 한다.

#211 후속의 재타격 기본값은 **4% → 1.5%**다. 단일 원본 `LabConfig.asset`의 해당 수치와 같은 코드 기본값을 맞추고 초기2%·성장6%/초를 포함한 다른 설정은 유지한다. DEV의 DEFAULTS로 불러온 뒤 솔로 START/RESTART, Host CREATE ROOM/APPLY TO ROOM 또는 공동 일시정지 뒤 APPLY & RESTART의 기존 경계에서 새 판에 적용한다. Host가 공유한166개 값과 지문을 참가자가 확인한 뒤 시작하며 Client가 독립적으로1.5%를 강제하지 않는다. 진행 중인 판과 이전에 명시적으로 적용한4%는 자동 변경하지 않는다.

Host의 권위 상태는 `LabModel.PaintSurface` 하나이며, 성장 계산은 Host의 전투 시간 진행에서만 한다. Host 화면도 현재 Snapshot과 같은 버전의 `LabNetwork.PaintSurface` 표시 캐시를 사용해 맵과 HUD를 함께 반영한다. Client는 승인 명중 방향을 재생해 성장시키지 않고 Host가 보낸 셀 변경(delta) 또는 전체 체크포인트를 별도 수신 맵에 적용한다. 분할 수신 중에는 기존 공개 표시 캐시를 유지하고, 완성된 맵의 세션·라운드·해상도·Revision·칠한 셀 수·전체 셀 수·명중 수가 Snapshot 메타데이터와 모두 맞을 때 맵과 HUD를 함께 공개한다. 픽셀이 그대로인 반복 명중도 명중 수가 바뀌면 빈 delta를 발행한다.

전송은 프로토콜 **5652**의 `paint_cells`·`paint_resync` 경로를 사용한다. 셀 ID·RGBA·투척자 P번호를 담은7바이트 delta보다 전체 맵이 작으면 RGBA+P번호5바이트 셀의 전체 맵을 보낸다. base64 도색 데이터는 논리 조각당 최대 2,048자, 수신 논리 조각 수는 최대 107개다. 별도 Bulk 스트림이 접두부 포함 900문자 이하로 다시 분할하고, 외부 메시지를 1,200바이트 이하로 보낸다. 순서·누적 ACK·재전송 후 완성된 논리 본문만 적용하며 행동 응답의 NGO 신뢰성 통신과 분리한다. 최대 해상도 전체 색상·투척자 맵은163,840바이트이고 base64 218,456자를107개 논리 조각으로 나눈다. 수신 시 헤더·기준 Revision·셀 ID 범위와 순서·payload 크기·알파/색·투척자 P번호·칠한 셀 수·색상/투척자 통합SHA-256 해시를 검사한 뒤 두 맵을 한 번에 교체한다. 중복 완료·이전 전송/스냅샷 번호·이전 라운드를 거절하고, 기준 맵 누락이나 손상에는 Host의 마지막 발행 맵 복사본으로 체크포인트를 요청한다. `sequence`는 연결 전체의 색칠 전송 번호, `epoch`는 그 맵을 발행한 게임 Snapshot 번호다. 체크포인트는 같은 맵 버전의 `epoch`를 유지하며 `sequence`는 새 번호로 증가한다.

이 복구는 **현재 라운드에 계속 연결된 Client의 부분 맵 누락**을 복원하는 기능이다. 연결이 끊어진 뒤 전투에 재접속하는 기능은 포함하지 않는다. 실제 다중 앱·기기에서의 전송과 화면 일치는 자동 패킷 fixture와 구분해 검증한다.

`LabGourdPaint`는 공개 표시 캐시의 객체·해상도·Revision 변경 때 같은 RGBA 맵을 linear RGBA32 텍스처로 올린다. Point 샘플링·U 반복/V 고정·mipmap 없음으로 칠한 셀과 같은 범위를 보인다. 성장 셀은 불투명이고 진행도는 정수 셀 수의 양자화된 비율이다. 직접 `Paint`/`ClearPaint`·기존 부드러운 `Stamp`는 연결 전 미리보기 전용이며 연결 중 Host 상태를 변경하지 못한다.

새 코드는 `Core`, `Session`, `Orb`, `Throw`, `UI`로 책임을 나눈다. 과거 `T01`·`T09` 같은 단계별 클래스나 Scene을 새 프로젝트에 쌓지 않는다. 단계 이력은 로컬 Git 커밋으로 추적한다.

기본값은 기존 `Arc`다. `LabConfig.asset` Inspector의 `Projectile throw form` 또는 DEV의 `Throw form`에서 `Straight`를 고른다. 직구 기본값은 **DEMO_TUNING_VALUE**로 오프셋 `(0.35, 0.4, 0)`, 발사각 오프셋 `3°`, 기존 상승각 비율 `0.1`, 기존 중력 배율 `0.1`이다. 기존 Arc의 최종 초기 속력·수평 방향을 재사용하며 직구 최종 상승각은 `clamp(Arc 상승각 × 비율 + 오프셋, -30°, 60°)`다. 발사 순간 중력·수명을 캡처하므로 이미 날아가는 공은 이후 설정 변경으로 꺾이지 않는다. 입력·자동 조준 여부·물리 충돌·색칠은 기존 경로를 따른다. 모드/설정은 공유 119개 값과 지문에 포함되며 프로토콜 5630로 이전 앱과 분리한다. 범위·사용 순서·극값의 한계는 [투척 조정 가이드](THROW_TUNING_GUIDE.md), 실제 실행 결과는 [검증 기록](VALIDATION.md)을 참조한다.

## 실제 투척자 고정 무늬 — #206

게임의 명중 확정 시 현재 구슬 소유자인 실제 투척자의 자리에서 P번호(`seat + 1`)를 얻어 성장 잉크에 고정한다. 연결 ID·최초 생성자·원소 색과 독립이다. 셀의 새 도색 시 기존 FIFO 마지막 소비 공급자의 RGBA와 P번호를 함께 저장하며, 이미 칠한 셀은 바꾸지 않는다. 기존 연결 영역 합류·성장량·난수 경로·100% 승리 판정은 보존한다. 미리보기/기존 색상 전용 fixture의 P0은 중립이며 실전 명중은 P1~P5를 기록한다.

P1 점/P2 사선/P3 가로줄/P4 물결/P5 격자는 세션 공통으로 고정된다. 로비와 내·좌우 표본을 기존 Canvas의 자식 Image8개로 저장한다. 박은 같은 Point/linear 좌표의 P번호 텍스처를 색상과 함께 올리고 RGB 밝기만 조절한다. 렌더러는 게임 성장 권한을 갖지 않는다. 결과 감상 복제본은 두 맵을 모두 복사·해제하며, 새 판에는 두 맵이 모두 비워진다. DEV `Gourd`의 **Player Paint Patterns (0 off, 1 on)**은 기존 **138번째/인덱스137** 공유 토글이며 기본 ON이다. 기존 **Completed Gourd Viewer**도 기본 ON으로 변경했다. OFF는 박의 개인 무늬와 Canvas8개 표본을 숨기며 원본 색상·투척자 맵·성장·완료 판정은 유지한다. 관람 ON/OFF와 독립적이며 무늬 OFF 상태의 완성 박도 색상만으로 둘러볼 수 있다. 관람은 결과 버튼으로 수동 진입한다. 코드·저장 원본·DEV DEFAULTS는 두 값 모두 ON이고, Host ACK와 기존 적용 경계는 유지한다. 프로토콜 **5652**에서 166개 값을 공유한다. 개인 무늬의 선택·랜덤 배정·새 게임 수치·새 구슬 조작은 범위 밖이다. 코드·실행 증거와 미검증 범위는 [검증 기록](VALIDATION.md)의 #206 절에 남긴다.


## 재타격의 경계 인접 군집 — #208 / #211

`LabPaintSurface`의 각 반복 공급 `Ink`는 승인 시 한 경계 시작점과 지연 탐색 `GrowthCluster`를 갖는다. 다음 한 셀을 완성하는 최종 FIFO 공급의 군집으로 위치를 정하고 같은 공급의 색상/연결 소유자/P번호를 함께 칠한다. `Merge`는 모든 공급을 보존하며 이미 시작된 군집을 다른 타격으로 대체하지 않는다. #211에서는 초기 얼룩의 즉시 도색이 병합 중 이전 대기 공급을 소비하지 않도록 그 타격의 Ink를 직접 차감한다. 시간 성장은 기존 FIFO를 사용하고 군집은 실제 잉크 잔량을 따른다.

`LabPaintSurface.Clusters.cs`의 고정된 구면 거리·낮은 주파수 굴곡·접촉/빈틈 우대 heap은 인접 셀에서만 넓어진다. #211부터 Broad/Splatter/Flow는 최초와 동일한 마스크 본체의 완만하게 정리한 방사형 윤곽도 선호도로 사용한다. Legacy는 마스크 없는 군집을 유지한다. 작은 위성점·미세한 결손을 재타격의 긴 가시나 떨어진 셀로 복사하지 않는다. 수직/메우기 우대의 기존 전체 경계 선택은 시작점을 한 번 고를 때 적용한다. 빈 셀은 실제 `PaintCell` 확정 후에만 이웃 탐색을 연다. 이미 칠한 같은 root는 무료로 통과하고, 막힌 시작점·분리된 흰 구멍에서도 같은 anchor/heap을 계속 사용한다. 최대 반경·일정 pop 횟수 뒤 전체 경계 재추첨·조건에 의한 영구 제외를 두지 않는다. 마지막 빈 셀까지 도달하며 실행 시간/완료 시각/전역 속도·실제 셀 예산은 기존 경로를 유지한다. 탐색의 최악 범위는 해당 군집에서 전체32,768셀까지다.

Config의 `Paint Cluster Compactness`·`Paint Cluster Irregularity`는 현재138/139번이며 기본0.85/0.25, 범위0~1이다. 현행 전체166개·프로토콜5652를 사용한다. 최초4종과 렌더링/셀 전송 구조는 유지하며 미사용 Flow4필드는 #246에서 제거했다. 실행 검증은 [VALIDATION](VALIDATION.md)의 해당 버전을 구분한다.

#211: `MakePatternFootprint`는 기존 칠을 포함한 전체 마스크로 초기 크기를 정한 뒤 빈 셀만 남긴다. 명중점 성분에 남는 초기 소수 예산과 겹침 정수 예산은 구별해 보관하며, 정수 잔량은 명중점 고정 군집으로 시간 성장한다. 마지막 소수 소비자의 RGBA/P번호 계약과 기존 맵 복제 구조는 유지한다. 최초 SPLATTER의 실제 튀김점은 계속 별도 Region이며, 100%에 가까워 기존 색 사이에 분리된 빈틈만 남으면 새 도색이 나뉘어 보일 수 있다. 이를 기존 칠 덮기로 숨기지는 않는다.

#214 main 통합 시 추가된 **Gourd Visual Size (x)**(인덱스140, 기본1.4·범위0.5~3)와 새 박/요괴 에셋을 보존한다. 현행 공유 설정은166개·프로토콜5652이며(#212 무거운 폭탄 4개·#213 폭발 패널티 3개·#225 건조 4개·#215 넘기기 막기 3개·#222 박 색상 콤보 9개 추가·#241 콤보 예고 1개 추가), 재타격 기본값1.5%와 도색 수정은 이 구조에 함께 적용한다. 위4% 비교 이미지는 통합 전 저장 메시의 회귀 기록이다.


## 근처 명중 건조 확인 범위 — #225

검사 시나리오는 [건조 명세](PAINT_DRYING.md)에 모았다. 코드·설정·패킷 fixture 확인과 실제 독립 앱/기기 실행을 구분하며, 이번 변경의 실행 결과는 [검증 기록](VALIDATION.md)에만 남긴다. 독립 Mac 다중 앱·iOS·핫스팟 실기기 건조 검증은 미실행이다.
