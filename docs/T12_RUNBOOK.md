# T12 실행 절차

현재 수정 검증 대상은 빌드18의 iPhone17 Host와 iPad mini6 Client다. 같은 Wi-Fi·세로 화면·동일 Config를 사용한다. 실제 두 iPhone 결과와 구분한다. 일반 Host Seed로 수행하고 Fixture/Debug 공급·단축 시간은 사용하지 않는다.

1. 양쪽 앱을 실행하고 iPhone에서 CREATE ROOM, iPad에서 FIND ROOMS를 누른다. 발견된 방의 JOIN을 선택한다. 연결된 P1/P2와 좌우 이웃, 같은 방·Config를 확인한다. 직접 IP는 이 단계의 대체 근거가 아니다.
2. 양쪽 I'M READY 후 Host만 HOST START한다. 시작 시 구슬0개·Stamina100·HP100·TIME180을 확인하고 각 기기에서 Generate를 처음 한 번 누른다. Raw1개·비용20과 고유 ID를 요청 영수증으로 확인한다. 시간 회복 때문에 여러 번 탭한 뒤 표시값이 단순 뺄셈과 같지 않을 수 있다.
3. 실제 손으로 Raw를 좌우 끝까지 끌고 손을 뗀다. 잡은 구슬의 확대·빛 효과, 손을 떼기 전 전달되지 않음, 반대쪽 진입·높이 보존·자동 반송 없음·보낸 화면 제거를 관찰한다. 양쪽 송신자와 위/가운데/아래 높이를 포함한다.
4. 받은 Raw와 반대 음양 Raw를 겹쳐 손을 떼어 조합한다. 재료2개 종료·새 Combined1개를 확인한다. 같은 음양의 조합 시도는 거부되고 원본2개가 남는지도 관찰한다.
5. Combined도 양쪽 방향으로 전달하고 실제 수신자가 상단 전투 경계를 넘어 드래그한다. 같은 ID가 발사체로 이어진 뒤 실제 피격으로 종료되는지, HP20 감소·실제 공격자에게만 명중 회복5가 발생하는지 확인한다. 회복 상한 때문에 시험 직전 정상 Generate로 여유를 만들 수 있다. 자동 회복 기록은 명중 보상과 분리한다.
6. Raw의 상단 드래그는 공격을 거부하고 Raw를 보존해야 한다. UI의 실제 손 조작 기록과 자동 명령 요청 결과를 구분한다.
7. 정상 생성 Raw50회·Combined50회 전달을 자동 반복한다. 두 기기가 각 승인 상태를 확인한 뒤 다음 요청을 보낸다. 같은 명령 계획·구슬 ID·살아 있는 ID 집합·속성·전달 횟수·소유자·진입 위치를 비교한다. 방향 계획은 송신자/방향별 총25회가 되도록 구성한다. 반복 횟수를 장기간 안정성 보증으로 확대하지 않는다.
8. 실제 명중5회로 Victory를 만들고 양쪽 결과·숫자 고정을 확인한다. Retry 후 새 라운드 READY·0개·100/100·HP100·TIME180, 양쪽 초기 상태 확인 뒤 Host Start, 첫 Generate1개를 확인한다.
9. 별도 정상 라운드를 실제180초 진행해 Defeat와 결과 고정을 확인한다. 두 기기의 같은 세션·라운드·상태 번호 지문과 시간 표시 오차1초 이내를 비교한다. 중도 앱 중단이나 연결 상실은 시간 만료 Defeat의 증거가 아니다.

진단은 명시한 실행 식별자가 있어야 활성화한다. 명령파일은 고정 schema의 허용된 게임 요청만 지정하며 임의 파일 접근이나 코드 실행을 제공하지 않는다. 자동 조작 중에는 사람의 구슬 입력을 잠시 막아 계측이 섞이지 않게 하고, 완료 또는 실패 후 복원한다. 실행 실패·시간 초과·누락은 PASS로 기록하지 않는다.

실행마다 새 증거 폴더를 사용하고 앱 빌드·Config 지문, 설치·실행 결과, 정상 요청/승인·실제 피격·회복 이벤트, 화면, 사용자 관찰, 각 AT 상태를 남긴다. 세부 명령 사용법과 실행 경로는 최종 검증 문서에 기록한다.


## 상태바 수정 확인

새 빌드에서 정상 방 검색·Ready·Host Start 후 iPhone 상태바/제어 센터를 10–15초 열었다가 닫는다. iPad는 전경에 유지한다. 같은 방·세션을 유지하고 양쪽 타이머가 실제 경과 시간만큼 줄었는지 확인한다. iPad에서도 같은 검사를 한다. 전경 inactive/active 로그와 같은 세션의 연속 시간·snapshot을 대조하며, 과거 빌드17의 정상 결과 화면 관찰을 빌드18 상태바 수정 성공으로 대신하지 않는다.

가장자리 전달은 중앙으로 먼저 옮기는 준비 동작 없이, 최초 또는 수신 위치의 구슬에서 새 터치를 시작해 가까운 좌/우 끝으로 끌고 손을 뗀다. 탭만 하거나 잡고 가만히 있을 때 자동 반송되지 않는지도 확인한다. 자동 전달 요청은 이 실제 손떼기 검사의 근거로 세지 않는다.
