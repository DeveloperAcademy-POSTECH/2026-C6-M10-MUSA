## 실패와 수정 기록

최초 EditMode의17개 실패를 지우거나 최종 PASS로 덮어쓰지 않았다.

- **버퍼 크기1개:** 실제 속도·중력·시간 필드가 추가되어 기존32KiB 인벤토리 한도를 넘었다. 큰 인벤토리 snapshot에만 유한64KiB 한도를 적용했다. 일반 요청·응답은16KiB를 유지하고, 최대 용량과 한도 초과 검사를 최종 실행했다.
- **NaN 재전송 비교1개:** 동일한 잘못된 NaN X 입력이 `Vector2.Equals`에서 같지 않게 처리되어 거부 영수증을 그대로 조회·재사용하지 못했다. 성분별 float 비교로 동일한 잘못된 입력의 거부 결과를 안정적으로 유지하고, 변조 입력은 계속 거부한다. 해당 사례는 최종 XML에서 PASS다.
- **이전 설정 시험 데이터15개:** GameWire 시험 데이터에 schema2의 필수 투척·표적·바닥·구도 값이 빠져 `INVALID_EXPECTED_CONTEXT`가 발생했다. 현행 승인 설정을 제공하도록 시험 데이터를 보완했다. 같은15개 사례 이름이 모두 최종 실행에서 PASS다.

최초 Mac 앱 빌드는 별도의 **FAIL** 기록이다. 자동 진단용 `P2ThrowProbe.cs`가 `in` 매개변수에 `ref`를 전달해 Unity의 C#9 환경에서 `CS9194` 컴파일 오류가 발생했다. 언어 버전이나 Unity를 올리지 않고 해당 호출을 설치 환경에 맞게 수정했다. 후속 Mac 빌드 영수증은 `Succeeded`, 오류0·경고13, 출력 검사 PASS를 기록한다. 최초 빌드 영수증의 오류2·경고16도 보존했다. 이 빌드의 성공을 Mac 게임 실행이나 실기기 성공으로 간주하지 않는다.

## Mac 두 앱 실행의 별도 근거

최초 `Logs/P2/mac-pair` 실행은 **FAIL**로 보존한다. Client 진단이 이미 꺼졌지만 Unity의 지연 삭제를 기다리는 Collider까지 물리 참여로 잘못 판단해 종료했고, 이후 Host도 HP80 공유 대기 시간 초과로 실패했다. 활성·켜진 Collider만 검사하도록 진단을 수정했다. `Logs/P2/mac-pair-r2`의 build22-r3 두 앱은 PASS이며, 원본 양쪽 증거를 직접 비교한 공통 상태는 111개, 불일치는 0개였다.

그 뒤 취소 후 `THROW READY` 문구가 남는 UI 문제를 수정했다. 앞의 관련 입력 6개 재실행과 최종 Mac 앱 재빌드에 이어, `Logs/P2/mac-pair-final`을 별도로 실행했다. 최종 앱 두 개는 모두 **PASS**이며 원본 양쪽 기록에서 공통 상태 113개·불일치 0개를 다시 계산했다. 실제 Host 3D 명중 1회와 공격자 회복 5, 유효한 옆 방향 빗나감 1회, 바닥 충돌 2회와 반발 후 소모, Client 표시 5,393프레임이 기록됐다. 양쪽의 취소·들고 있기 유지와 최종 발사체 정리도 PASS다. 최종 실행 파일 SHA-256은 `4c5abb91e9f1086a9c22da082e5b97c2bab2b2cbf8e831b3127415d28a2129fd`다.

이 실행은 실제 Mac 앱 두 개의 직접 IP 연결과 일반 유료 Generate 3회, 별도로 공급한 Combined 2개, 합성 컨트롤러 입력을 사용했다. 화면 크기는 390×844와 560×746이며, 물리 터치·Bonjour 발견·실제 iPhone/iPad 검증으로 해석하지 않는다. 수치 근거와 원본 해시는 `tests.json`의 `reviewedMacRuns`에 함께 보존했다. 화면 이미지의 시각 검토는 최종 담당 보고에서 별도로 정리한다.

## 검증 범위 경계

최종 전체 PlayMode는 UTC03:39:01에 종료됐다. 이후 standalone 진단 코드 `P2ThrowProbe.cs`, 진단 컴포넌트를 연결한 `ThrowBattle.unity`, 취소 안내를 수정한 컨트롤러·관련 검사 및 빌드 과정의 렌더링·프로젝트 설정 파일에 더 늦은 수정 시각이 관측됐다. 수정 시각은 시험 당시 소스 해시의 대체 증거가 아니다. 관측 파일과 현재 해시는 집계 JSON에 분리했다.

따라서 **1,192개 PASS는 해당 전체 XML 실행 시점의 검사 결과**다. 이후 변경에 대해서는 관련 입력 6개와 최종 Mac 두 앱을 재실행한 근거를 따로 사용하며, 전체 EditMode/PlayMode를 다시 실행했다고 기록하지 않는다. iOS 내보내기·서명·설치·실기기는 각각 해당 단계의 실행 증거로 추가해야 한다.

이 집계는 P2 최종 실기기 Gate, 최대5인 P3, 과거 미실행 항목을 PASS로 변경하지 않는다.
