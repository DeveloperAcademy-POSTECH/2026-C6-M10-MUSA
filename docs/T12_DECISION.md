# T12 실기기 전체 전투 검증 결정

2026-09-13 사용자의 다음 작업 요청에 따라 T12 하나를 진행한다. 선행 T11은 코드 시험914개, Mac 두 프로세스 전달17회와 실제 피격, iOS 빌드16 생성·서명까지 확인됐다. 빌드16의 설치·실기기 기록은 없으며 이번 빌드에 과거 기기 PASS를 승계하지 않는다.

- 장비는 사용자가 제공하고 연결·잠금 해제를 확인한 iPhone17 + iPad mini6 조합이다. iPad 대체 승인과 이번 두 기기 준비 확인을 T12에도 적용한다. 원문 두 iPhone 조건의 화면 QA와 구분하며 두 iPhone 실행으로 기록하지 않는다.
- 게임 규칙은 최신 사용자 결정인 시작 구슬0개·Stamina100, Generate당 Raw1개/비용20, 3초당20 시간 회복, 실제 공격자 유효 명중 회복5를 유지한다. 하단 전체 조합, 상단 경계 통과 발사, 잡을 때 확대·빛 효과, T11의 좌우 끝 손떼기 전달을 유지한다.
- 신규 IntegratedDeviceBattle 씬은 저장된 T11 씬에서 파생한다. 기존 씬·Config·카메라 구성·Rigidbody/Collider 피격·Host 권한 구조를 보존하고 빌드17을 구분한다. 기존 빈 build override는 15/16 동작을 유지한다.
- 개발용 진단은 명시한 실행 식별자가 있을 때만 활성화한다. 정상 앱 실행에서는 명령파일을 읽거나 요청을 자동 전송하지 않는다. 진단은 정상 생성·조합·전달·발사 요청과 Host 승인 경로를 사용하며 구슬/스태미나/HP/시간을 직접 주입하지 않는다.
- 반복 전달은 두 기기가 같은 전달 결과를 확인한 뒤 다음 요청을 보내도록 진단 전용 확인 메시지를 사용한다. 자동 요청은 실제 Touch 입력의 증거로 계산하지 않는다. 실제 손 조작·Bonjour 방 검색/선택·화면 관찰은 별도 확인한다.
- Compile, EditMode, PlayMode, Mac 사전 실행, Xcode 생성, 앱 빌드·서명, 두 기기 설치·실행, 각 AT 및 Gate 판정을 분리한다. 실행 실패와 중간 시도도 보존한다. T13은 이번 범위가 아니다.

현재 파일은 실행 전 결정 기록이다. 실행 결과는 최종 T12_VALIDATION 및 기기 증거를 따른다.


## 빌드18 수정 결정 · 2026-09-13

빌드17의 실제 조작에서 왼쪽 가까이에 생성·수신한 구슬을 왼쪽 끝으로 보내기 어렵다는 사용자 관찰을 확인했다. 기존 최소 이동거리 18% 전체 화면폭이 구슬부터 화면끝까지 가능한 이동거리보다 컸다. T12 씬만 새 옵션을 켜 시작점에서 진행 방향 끝까지의 거리도 반영한다. 중앙 시작은 기존 18% 기준을 유지하며 가장자리 띠에서 손을 떼기·수평 우세·최소 움직임·새 제스처 조건을 유지한다. 공유 Config와 이전 씬은 변경하지 않는다.

사용자는 결과 화면이 정상이며 상태바를 열 때의 중단 처리만 고치도록 지시했다. 첫 자동 복귀 의심 사례의 기기 로그에는 내부 버튼 클릭 경로가 있으나, 사용자의 의도적 클릭으로 단정할 수 없다. 이후 상태바를 내린 재현에서는 남은 시간 103.222초에 iPhone의 OnApplicationPause → Leave가 먼저 실행됐다. 조작 없이 다시 진행한 세션은 실제180초 Defeat 뒤 결과가 유지됐고, 사용자가 화면을 확인했다. 결과 UI나 보호 버튼을 추가하지 않는다.

수정은 빌드18 T12 iOS 출력에서 전경 비활성 상태의 Unity 일시 정지를 생략해 시간·통신 루프를 계속 진행하는 것이다. 실제 백그라운드 진입의 pause·연결 종료 정책은 보존한다. Unity 설치 파일과 과거 출력은 수정하지 않으며, 설치한 6000.5.7f1 템플릿에만 검증된 후처리를 적용한다. 타이머 원본은 이미 Host 절대시간 기준이므로 시간을 주입하거나 타이머 규칙을 바꾸지 않는다. 상태바를 10–15초 열어둔 실제 양쪽 연결·시간 진행은 새 빌드에서 별도로 확인한다.

Apple은 전경 focus 상실과 background 진입을 별도 이벤트로 설명한다. [WillResignActive 알림](https://developer.apple.com/documentation/uikit/uiapplication/willresignactivenotification?language=objc). 이번 Unity pause 경로의 원인 판단은 설치된 Unity가 생성한 UnityAppController.mm 및 실제 기기 콘솔을 근거로 한다.

빌드17 실행 근거와 소스 체크포인트를 보존하고, 빌드18의 컴파일·시험·출력·서명·실기기 결과는 따로 기록한다. 소스 수정이나 빌드 성공을 실기기 수정 완료로 기록하지 않는다.
