## 01. 기획 요약

### 지귀 콘셉트

**[확정 방향] “선덕여왕 사랑해요!!!”라고 샤우팅하며 불을 터뜨리고, 플레이어는 불의 근원을 맞혀 칠할 곳을 되찾는 지귀.**

게임플레이의 소재는 불이다. 락스타 같은 에너지는 음악·보이스·샤우팅·화면 반응으로 표현한다. 기타 연주, 공연 진행, 관객 호응, 콜 앤드 리스폰스, 박자 맞추기, 동시 타격은 새 핵심 기믹에 포함하지 않는다.

### 플레이어가 경험할 핵심 장면

- **A — 발화 [기준 초안]:** P1 앞의 박 일부가 달아오르고 큰 근원 불씨가 나타난다. P1이 기존 투척으로 근원을 맞히면 연결된 불이 걷히고, 그 구슬의 평소 색칠이 한 번 적용된다. 근원 하나일 때의 과제는 발견·조준·피드백이다.
- **B — 불장막 [기준 초안]:** P1의 박 일부가 불장막에 가려진다. P1 화면에는 `P2가 도와줄 수 있어요`, P2 화면의 큰 근원에는 `P1의 불장막`이 표시된다. P2가 근원을 맞히면 P1의 장막이 즉시 걷힌다. P1은 기다리는 동안 열린 곳을 칠하거나 필요한 구슬을 전달할 수 있다.
- **엔드게임 [확정 방향]:** 100초에 방해가 정리되고 마지막 20초는 피버로 칠하기에 집중한다. 자동 스태미나 회복 속도2배는 확정 규칙이다. 별도 소모값 감소의 대상·수치는 아직 미정이다.

### 경험과 시간 틀

| 구간 | 경과 시간 | 목표 감정 | 구성·의도 | 상태 |
| --- | --- | --- | --- | --- |
| 워밍업 | 0~40초 | 호기심 | A·B 각각 정보성 1회. 표적과 도움 관계를 알아봄 | 확정 방향 |
| 본게임 | 40~100초 | 성취·지략 | A·B 각각 실전 3회. 위치·역할 변화, 마지막에 기믹 수/상호 도움 변주 | 확정 방향. 각 변주의 구체적 배치는 기준 초안 |
| 엔드게임 | 100~120초 | 급박함·긴장감 | 고유·공통 패턴 없이 피버 | 확정 방향. 자동 회복 속도2배 확정, 별도 소모 감소는 미정 |

별도의 감정 곡선을 추가하지 않는다. 모든 등장마다 강도를 올리지 않는다. 실전 3의 두 근원·상호 도움이 혼란만 늘리면 실전 2의 다른 배치로 대체한다.

### 유지할 기본 플레이

**[확정 방향]** 각자의 모바일 조합판에서 생성·조합·전달하고, 위로 던져 공유된 3D 박을 칠한다. 봉인 목표와 투척의 흐름을 유지한다. 파훼에는 현재 박을 칠할 수 있는 유효한 구슬을 사용하며, 특정 오행 플레이어가 있어야만 해결되는 조건을 넣지 않는다.

지시서의 ‘플레이어마다 고정 오행 속성이 있다’는 기획 전제는 유지해서 읽되, 기준 코드에서는 해당 고정 선택·공격 자격을 확인하지 못했다. 현재 일반 협동의 Combined 속성은 Host가 정한다. 이 차이를 이유로 이번 지귀 문서의 범위를 속성 선택 기능 개발까지 확대하지 않는다.

## 03. 공통 불·근원·색칠 판정 명세

### 3-1. 개체와 관계 [기준 초안]

| 개체 | 식별·역할 | 수명과 관계 |
| --- | --- | --- |
| 패턴 인스턴스 | 한 슬롯에서 생성한 A 또는 B. 판/스테이지/슬롯으로 구분 | 예고 → 활성 → 파훼/만료/취소. 종료된 ID는 재사용하지 않음 |
| 불 그룹 | 하나의 근원에 연결된 차단 구역 묶음 | 대상 P 한 명, 근원 하나에 연결. 근원 해제 시 이 그룹만 정리 |
| 근원 불씨 | 큰 외곽선·중심 표식이 있는 타격 대상 | 도움받는 P와 타격 가능한 P를 별도로 보유. 시작값은 유효 구슬1회 명중 **[테스트값]** |
| 불 구역 | 박의 칠하기 표면에 대응하는 유한한 패치/셀 집합 | 예약 순서에 따라 활성화. 단순 화면 사각형과 실제 판정을 분리하지 않음 |
| 도움 관계 | `돕는 P → 도움받는 P → 근원 ID → 불 그룹 ID` | B의 한 방향 해제 관계. 쌍방 B는 독립된 두 관계 |

A에서 돕는 P와 도움받는 P는 같은 사람이다. B에서는 서로 다르다. A 실전 3의 두 불 그룹도 각각 독립된 근원·ID를 가진다. 한 근원을 맞혔다고 다른 그룹까지 꺼지지 않는다.

### 3-2. 개인 방해와 공유 박의 연결 [확정 규칙 — 사용자 승인]

**확정 규칙은 ‘불을 받은 P의 새 도색만 해당 구역에서 차단’이다.** 박의 도색 지도와 봉인 진행률은 기존처럼 하나를 공유한다.

- P1의 불 구역이어도 P2는 정상적인 도색을 할 수 있다. 이 경우 실제 추가된 칠은 모두에게 공유된다.
- P1도 열린 표면에서는 평소처럼 칠할 수 있다. 불장막 때문에 조합·전달·타이머가 가려지지 않는다.
- 불이 올라올 때 기존 칠을 지우거나 도색 진행률을 낮추지 않는다.
- **기존 건조는 그대로 적용하는 확정 규칙**이다. 불로 인한 삭제와 기존 건조를 구분한다. 불 때문에 건조를 새로 가속하거나 일괄 중지하지 않는다.
- 영향을 받지 않는 사람에게는 필요할 때 P번호/도움 안내를 표시하되, 실제로 막히지 않는 표면을 자기 색칠 금지 구역처럼 표시하지 않는다.

이 범위는 개인 대응 A와 협력 B를 살리기 위해 구체화한 초안이며, 사용자가 그대로 채택했다(Q-03 해결). 공유 표면 전체를 전원에게 막는 규칙으로 바꾸는 경우에는 별도 기획 변경이 필요하다.

### 3-3. 근원의 배치·조준 전제 [기준 초안 / 검증 필요]

- 첫 시제품은 박 표면의 사전 정의된 후보 패치를 사용한다. 후보마다 대상 P·돕는 P의 시점에서 보이는 정도, 실제 투척 가능한 표면 앵커, 연결할 인접 패치를 기록한다.
- A는 대상 본인의 전방, B는 돕는 사람의 전방에서 큰 표적으로 보이게 배치한다. 화면 안내만 있고 실제 물리로 맞힐 수 없는 표적은 사용하지 않는다.
- 근원 표식은 박 표면 앵커와 연결한다. 기존 ‘박 앞의 구형 불 트리거’를 그대로 색칠 좌표로 쓰지 않는다. 별도 트리거를 재사용할 경우에도 실제 박 셸에 대응하는 명중 좌표를 Host가 검증해야 한다.
- **근원을 맞힌 같은 투척에 정상 박 색칠 좌표를 부여할 수 있어야 한다.** 대응 좌표가 성립하지 않는 배치는 완료 판정을 주지 않고 프로토타입의 기술 검증 단계에서 수정한다. 빈 공간을 맞힌 것을 임의의 박 명중으로 바꾸지 않는다.
- 박 회전·흔들림 중에도 돕는 사람이 근원을 보고 맞힐 수 있어야 한다. 후보 앵커를 실제 운동 조건에서 검증한다. 가시성을 유지할 수 없는 배치는 탈락시키며, 근원 배치/추종 표현 대안을 먼저 검토한다. 검증 없이 박 물리를 정지시키지 않는다.
- B의 피해자가 우연히 반대편 근원을 맞히거나 회전으로 볼 수 있게 되어도, 지정된 도움 관계를 혼자 처리할 수 없어야 한다. 타격 자격은 표시와 함께 Host가 확인한다.
- 음악 없이도 근원과 도움 관계를 이해할 수 있어야 한다. 작은 오행색 점 대신 중심 문양·굵은 외곽선·연결된 불의 맥동을 함께 사용한다.

**[테스트값]** 처음에는 근원 하나의 화면상 가로 크기를 ‘해당 화면에 투영된 박 가로 폭의 약30%’에서 시작한다. 이는 월드 콜라이더 크기를 확정한 값이 아니다. 실제 박과의 겹침·도달 가능 범위·두 근원 구분을 보며 조절한다. 실패 시 타격 횟수를 늘리기보다 표적 크기·위치부터 바꾼다.

### 3-4. 명중·소비·피드백 처리

다음 순서는 **[기준 초안]**이다. 추가 속성 제한을 넣지 않고 현행 ‘박을 칠할 수 있는 구슬’ 자격을 재사용한다. Raw나 잠겨서 던질 수 없는 아이템을 새 파훼 도구로 인정하지 않는다.

1. Host가 진행 중인 전투·패턴 세대·구슬 소유/비행·실제 충돌과 유효 구슬을 확인한다.
2. 같은 투척 ID가 이미 처리되었는지 확인한다.
3. 충돌 지점이 유효한 근원이고 지정된 타격자가 맞는지 **색칠 차단보다 먼저** 판정한다.
4. 근원 명중이면 해당 근원과 연결 불 그룹·예약된 번짐을 즉시 해제한다.
5. 같은 구슬의 정상 박 명중·통상 색칠 **처리**를 실제 표면 좌표에 정확히 한 번 적용한다. 이때 다른 불 그룹의 차단은 여전히 유효하다. 새 면적의 증가를 보장하는 뜻은 아니며, 다른 그룹의 셀 차단이나 기존 예산/완료 조건을 그대로 따른다.
6. 근원이 아닌 일반 불 구역 명중이면 아래 표의 차단 처리를 적용한다.
7. 근원/불과 관계없는 열린 곳의 박 명중은 기존 처리를 유지한다.

| 명중 결과 | 구슬·색칠 | 보상·표시 | 상태 |
| --- | --- | --- | --- |
| 유효한 근원 명중 | 투척 구슬 1개 소비. 연결 불 해제 후 통상 색칠 1회 | 기존 통상 명중 처리 1회. 불 해제 추가 점수·구슬·성장량 없음 | 기준 초안 |
| 대상 P가 일반 불에 막힌 표면을 명중 | 투척 구슬은 기존 명중처럼 소비. 새 칠·성장량 공급·그 명중의 건조 보호 갱신 없음 | ‘불에 막힘’ 피드백. 기존 통상 명중의 스태미나 회복·명중 기록은 1회 유지 | 확정 규칙. 무시가 유리한지는 계속 검증(Q-03 해결) |
| 대상 P가 열린 곳을 명중 | 통상 최초 칠 또는 재타격 성장 공급 | 기존 통상 명중 피드백 | 기준 초안 |
| 영향받지 않는 P가 다른 사람의 불 구역을 명중 | 정상 도색 후 공유 지도 갱신 | 자기 화면에서 차단 실패처럼 표시하지 않음 | 기준 초안 |
| 빗나감·타격 자격 없는 근원 접촉 | 기존 실제 박/바닥/미스 판정을 따름. 자격 없는 근원만으로 불 해제·강제 색칠 없음 | 누구의 근원을 맞힐 수 있는지 안내로 구분 | 기준 초안 / 구현 검증 필요 |
| 같은 투척의 중복 callback·중복 메시지 | 소비·해제·도색·보상 재적용 없음 | 중복 파훼 효과 없음 | 개발 완료 조건 |

‘불에 막혔다’는 이유로 별도 HP 피해·시간 벌점·추가 구슬 소각을 넣지 않는다. 일반 명중 보상 유지는 추가 보상이 아니지만, 불을 무시할 유인이 될 수 있으므로 PT-08에서 함께 관찰한다. 근원 파훼 자체의 정상 색칠과 해제 연출이 거대한 추가 도색처럼 보이지 않게 한다.

### 3-5. 최초 얼룩·재타격 성장과 차단의 연결 [기준 초안]

불은 ‘명중점 검사’만으로 구현하면 안 된다. 열린 지점에서 시작한 최초 얼룩이나 이전에 공급된 군집 성장도 불 구역으로 들어갈 수 있기 때문이다.

- Host가 **실제로 새 셀을 추가하는 시점**에 해당 도색의 투척자와 불 차단 구역을 함께 확인한다. 초기 Splatter의 주변 점과 후속 군집 확장 모두 포함한다.
- 기존 `LabPaintSurface`의 `Ink.Owner`·`PainterSlot`과 예산을 우선 재사용한다. 여러 사람의 소수 예산을 합쳐 1셀을 만드는 경우 현재 색·P 귀속 규칙과 차단 자격의 일치를 검토한다. 차단을 피하려고 귀속자를 바꾸지 않는다.
- 최초 Splatter의 기존 독립 튀김점은 유지하되, 그중 불에 막힌 셀만 새 칠에서 제외한다. 제외된 면적을 메우려고 원래와 무관한 새 튀김점을 추가하지 않는다.
- **후속 군집 성장**은 같은 연결 영역의 열려 있는 인접 후보를 찾는다. 불에 막힌 중간 셀을 건너뛰어 연결되지 않은 곳에 새 성장 시작점을 만드는 우회는 금지한다.
- 유효한 인접 후보가 없으면 해당 예산을 보류한다. 새 셀을 칠하지 않았는데 성장량을 소모하거나 진행률을 올리지 않는다. 다른 사람의 성장과 전역 업데이트는 계속 가능해야 한다.
- 보류된 예산은 차단 해제 뒤 기존 속도·기존 잔량으로 재개한다. 해제 보상으로 면적을 새로 공급하거나, 막힌 동안 누적한 시간 크레딧을 한 프레임에 폭발시키지 않는다.
- 대상 P의 성장만 막힌다고 해서 다른 P의 FIFO 예산까지 멈추지 않게 한다. 무한 탐색·예산 손실·색/P 귀속 변경은 실패 조건이다.
- 고해상도 그림도 확정 지도와 일치해야 한다. 도색이 금지된 셀에 시각 스탬프만 불투명하게 그려 진행된 것처럼 보여서는 안 된다.

기획 초안 작성 당시 기준 main에는 이 불 차단 분기가 없었다. #332의 예산·셀 귀속·고해상도 연결 및 검사 범위는 11절에 기록한다.

### 3-6. 유한 번짐과 의미 있는 차단 [기준 초안 / 테스트값]

- 한 불 그룹은 사전 정의한 인접 패치 목록 안에서만 번진다. 무한 증식·추가 근원 자동 생성은 없다.
- **[테스트값]** 정보성/기본형은 시작 패치 1개와 인접 패치 최대2개, 활성 후 1초 간격의 순차 표시로 시작한다. 처음부터 근원은 보이며 번짐 완료까지 기다릴 필요가 없다.
- A 실전 2는 같은 패치 수로 시작 위치·번짐 방향만 바꾼다. A 실전 3은 기본형 두 그룹이며 각 그룹을 독립적으로 끈다.
- B의 장막은 박의 일부를 가리는 형태로 표시하고 열린 투척 표면을 남긴다. 장막의 총 차단 면적·불투명도는 배치에 따른 **테스트 변수**이며 전면을 가리지 않는다.
- Host는 사전 후보 중 대상 화면에서 보이고 미도색 구역 또는 진행 중 성장의 경로와 겹치는 배치를 우선 선택한다. 정보를 가르치는 회차에서도 이미 완성된 칠만 가리지 않았는지 기록한다.
- 의미 있는 후보가 없으면 억지로 칠을 지우거나 불을 늘리지 않는다. **해당 발생 시도는 무효 배치로 건너뛰고 이유를 기록하는 초안**이다. 슬롯을 뒤로 누적하지 않는다. 빈번하면 배치 설계를 수정한다.
- 타임테이블은 예정된 발생 기회다. 조기 승리·게임 오버·유효 배치 없음으로 실제 발동하지 않은 경우를 별도로 집계하며 A·B를 각4회 플레이한 것으로 기록하지 않는다.

### 쌍방 도움의 독립 처리 [기준 초안]

| 사건 | P1의 장막 | P2의 장막 |
| --- | --- | --- |

동시 명중·연속 성공·콤보 성립을 요구하지 않는다. 각자 도울 근원이 자기 장막에 가려지면 배치 실패다.100초 취소나 수명 만료는 ‘동료가 성공했다’는 메시지와 구분한다.

### 인원수와 역할 균형

- **[기준 초안]** P번호는 Host/Client 역할이 아니라 실제 플레이어 식별로 사용한다. 고리의 이웃은 현재 실제 자리 기준으로 찾는다.
- 2인 설명 예시에서 A는 각2회 대상이지만 마지막 대상은 근원2개다. B도 도움받기/돕기 횟수가 완전히 같지 않다. 이를 균등 작업량으로 기록하지 않는다.
- 3~5인은 고정 P1부터 매판 반복하지 않는다. 초기 P와 쌍을 판별로 변경하고, 대상 횟수·helper 횟수·근원 수·대기 시간을 기록한다.
- 모두에게 같은 슬롯 수를 주려고 발생 횟수를 늘리지 않는다. 한판의 경험과 여러 판의 편향을 따로 관찰한다.
- 1인 DEV는 A와 표현·정리 검사의 보조 경로다. B의 협력 성립 검증은 실제2인 이상에서 수행해야 한다. 솔로에서 B를 생략해도 협동 검증 통과로 기록하지 않는다.

### 6-4. 공통 패턴의 무작위 배정·기존 지속 규칙·중첩 [확정 규칙]

공통 종류는 폭탄·스와이프 금지(좌우 전달 차단)다. 사용자가 다음 규칙을 확정했다(Q-02 해결).

- **20/40/60/80초 각 슬롯에서 하나를 무작위 선택**한다. 현행 Host의 활성 스위치·선택 비중·유효 대상 추첨을 재사용하는 기준으로 구체화하며, 강제 교대나 연속 보정을 추가하지 않는다. 무작위는 반드시50:50이라는 뜻이 아니다. 실제 유효 비중과 대상 후보를 검사 기록에 남긴다.
- **발생 시각은 지귀 전용20/40/60/80초만 사용**한다. 기존 추첨·효과 코드를 재사용하되 일반 공통 반복 타이머를 함께 실행하지 않는다. OFF·비중0·유효 대상 없음으로 선택 불가한 종류는 제외하고, 두 종류 모두 불가하면 그 슬롯을 건너뛰며 나중에 몰아서 실행하지 않는다.
- **폭탄은 현재의 유지·해금·만료 패턴을 재사용**한다. `DropGourdBomb`의 생성 시각/잠금/출처, `LifetimeFor`·`ItemLifetimeSeconds` 등에 따른 실제 수명 규칙을 확인한다. 전달할 때 도화선이 새로 시작하는 기능을 추가하지 않는다.
- **전달 차단도 현재의 지속시간 규칙을 재사용**한다. 현재 `StartSwipeBlock`은 시작 시각+`SwipeBlockSeconds`로 종료한다. 두 효과의 지속시간 숫자를 서로 같게 만들라는 의미로 확장하지 않는다. 슬롯 간격과 효과 수명은 별개다.
- **A/B와 공통 효과의 동시 적용을 허용**한다. 피해자나 helper라는 이유만으로 공통 추첨 대상에서 제외하거나 반드시 다른 사람에게 보내지 않는다. 기존 규칙상 가능한 폭탄·전달 차단의 겹침도 허용한다. 같은 효과의 재발동·대상 제한은 기존 정책을 따른다. 예를 들어 전달 차단이 이미 활성이라 새 차단을 제외하는 정책이나 직전 공통 대상 제외까지 일괄 해제하는 의미는 아니다. 새 A/B 활성만으로 피해자/helper를 제외하지 않도록 구분한다.
- 불가능한 입력 조합 여부는 계속 검증한다. 현재 전달 차단은 위 투척을 직접 막지 않는다.100초에는 남은 방해를 종료하므로 기존 수명이 그 이후까지 남더라도 이 스테이지의 종료 전환이 우선한다.

| 폭탄/잔류 효과가 다음 고유 슬롯까지 지속 | 발생 시점과 수명은 다름. 다음10초 슬롯이 자동 휴식 경계가 아님 | 현행 유지시간을 재사용한 실제 종료 시각과 다음 예고 간격 측정. 같은 대상 중첩까지 포함해 관찰하며, 기존 수명 변경이 필요하면 별도 변경으로 기록 |
| 폭탄 불과 근원 불씨를 혼동 | 기존 폭탄은 조합판·구슬 주변에도 불 표현이 있음 | 폭탄은 몸통/도화선/숫자, 근원은 박 위 큰 외곽선·연결 문양·P번호로 구분 |
| 기존 지귀 자동 추첨도 함께 실행 | 새 A/B와 구형 물 전용 화재·과열이 중복될 위험 | 새 정책을 적용할 때 지귀 자동 경로의 단일 소유를 확인. 구형 효과를 추가 슬롯처럼 함께 실행하지 않음 |

**[코드 확인]** 기준 설정의 잠긴 폭탄 수명은15초, 전달 차단은10초다. 폭탄은 마지막 잠금이 해제되면 일반 구슬 수명 경로로 바뀌므로 항상 생성15초 뒤 폭발하는 것으로 단순화하지 않는다. 이 값은 기존 설정 확인값이며 지귀 전용 하드코딩 사양이 아니다. 기존15초 잠금 폭탄이 유지되는 경우20초 슬롯은30초 B,40/60/80초 슬롯은50/70/90초 B와 겹칠 수 있다. 따라서 A와 같은 시각뿐 아니라 **이전 공통 효과가 다음 B까지 이어진 경우**도 승인된 중첩으로 검사한다.

고유 패턴만 보면 다음 슬롯까지 최대2초 여유가 있지만, 공통 효과까지 없는 완전한 휴식이라고 표현하지 않는다. 공통 검증을 마치기 전에는 ‘120초 통합 검증 완료’로 표시하지 않는다.

### 6-5. 100초 정리와 피버

**[확정 방향]** 100초 이후 새 고유·공통 패턴은 없다. 다음 순서의 전환을 **[기준 초안]**으로 개발한다.

1. 새 슬롯 발동과 예약된 번짐을 차단한다.
2. 남은 근원·도움 관계·불장막·색칠 차단을 취소한다.
3. 공통 전달 차단·기믹 폭탄과 그 파생 방해를 취소한다. 취소 때문에 폭발·실패 과열·추가 피해·시간 벌점이 발생하지 않게 한다. 같은 시각의 자연 만료 벌점보다 전환 취소를 우선한다.
4. 기믹에서 파생된 잔류 화상 등 정리 대상을 식별한다. 기믹 폭탄과 일반 생성 아이템은 출처로 구분한다. 출처 추적이 부족하면 개발 항목으로 보완하며 모든 일반 구슬/아이템을 임의로 삭제하지 않는다.
5. 차단에 보류됐던 기존 성장 예산을 정상 속도로 재개한다. 면적 보상을 새로 추가하지 않는다.
6. 아직 전투가 진행 중이면 피버 자원 규칙과 음악·화면 신호를 적용한다.

- 이미 정상 발사된 구슬은 비행을 유지한다. 삭제된 근원의 오래된 ID로 새 불을 끌 수 없다. 실제 박 명중은 열린 상태에서 기존 규칙으로 처리한다.
- **100초 취소와 근원 충돌의 전투 시각이 같으면 취소가 우선**이다. 해당 충돌을 근원 파훼로 인정하지 않고 실제 박 접촉이 있으면 정상 박 판정, 없으면 기존 미스로 처리한다. 사라진 전방 표적의 위치를 강제 색칠 좌표로 사용하지 않는다.
- 소화·자연 만료·100초 취소의 이유를 구분해 ‘동료가 성공했다’는 가짜 메시지나 보상을 만들지 않는다.
- 100초 이전에 봉인 완료·Defeat·게임 오버가 확정되면 남은 패턴을 정리하고 기존 결과 흐름을 따른다. 종료 후 피버가 다시 켜지지 않는다.

| 피버 항목 | 결정 상태 | 개발 전제 |
| --- | --- | --- |
| 구간 | **확정 방향:**100~120초 | 조기 종료 시 함께 종료 |
| 스태미나 ×2 | **확정 규칙:** 시간에 따른 자동 회복 속도2배 | `R_fever = 2 × R_base`. 최대량·현재량을 즉시 늘리거나 명중1회의 회복량을2배로 바꾸지 않음 |
| 구슬 소모값 감소 | **미정:** 어떤 소모의 어떤 값인지와 감소량 | 비용 절반·구슬 무한 사용으로 임의 대체하지 않음 |
| 기존 구현과 접점 | **코드 확인:** 일반 생성의 스태미나 비용과 투척 구슬 소비는 서로 다름 | 자동 회복2배와 별도 소모 감소를 분리한다. 기존2:2 피버를 지귀에 그대로 적용하지 않음 |
| 복원 | **기준 초안:** 결과·새 판·로비에서 전용 변경을 제거 | 원본 LabConfig·다른 스테이지 값을 저장/오염하지 않음 |

회복 규칙의 기준은 다음과 같다. 전투가 진행된 시간 `Δt`에 대해 자동 회복은 `min(기존 최대량, 현재량 + 2 × 기본 자동회복량/초 × Δt)`로 계산하고, 기존 소비·명중 회복은 각각의 사건으로 처리한다.100초를 가로지르는 시간 구간은 전후를 나눠100초 이후에만2배를 적용한다. 공동 Pause에서는 회복 시간도 진행하지 않는다. 진입 즉시 충전이나 최대량 변경은 없다.

Q-01 중 자동 회복 속도는 해결됐으며 **별도 소모값 감소의 대상·수치만 미정**이다. 미정값을 임의로 적용하지 않는다. 자동 회복 속도 2배는 #332에서 구현하고 자동 검사했다(11절). 실제 기기에서의 검증은 미실행이다.

### 6-6. 조기 봉인과 기한 종료

**[코드 확인]** 일반 협동은 실제 도색100%를 Host가 확정하면 Victory, 기한까지 미완료하면 Defeat다. 새 지귀도 이를 연결하는 **[기준 초안]**으로 한다. 피버를 보여주기 위해 이미 끝난 판을120초까지 유지하지 않는다.

기존 공동 완료 연출과 결과 이동은 유지 대상이다.120초의 성장 완료·투척 충돌·기한 판정이 같은 시각에 있는 경계는 기존 Host 처리와 맞는지 자동 검사로 확인해야 하며, 클라이언트의 화면상 충돌만으로 승리하지 않는다.

## 08. 개발 To-do와 완료 조건

체크한 항목은 #332 코드와 관련 자동 검사로 완료 조건을 확인한 기술 항목이다. 미체크에는 실제 조작·재미·음성 에셋·미정 조건이 남아 있다. 사람의 플레이테스트를 자동 검사로 대체하지 않으며 상세 근거는 11절에 기록한다.

### 1단계 — 공통 불·근원·색칠 차단과 명중 처리

- [x] **패턴·그룹·근원·도움 관계 데이터 정의** — 완료 조건: 판/스테이지/슬롯 ID와 대상P/helper P가 분리되고, 중복/이전 세대 요청을 거절한다.

- [x] **큰 근원1개와 인접 번짐 프리셋** — 완료 조건: 유한 목록만 번지고, 근원은 첫 활성부터 표시한다. 근원을 맞히면 미래 번짐도 취소한다.
