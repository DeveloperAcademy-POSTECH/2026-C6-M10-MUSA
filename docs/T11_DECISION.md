# T11 · 좌우 전달 결정

작성일: 2026-09-13. 대상은 T11 하나이며, 이 문서는 사양과 검증 기준이다. 문서 작성·승인은 구현, 빌드 또는 실기기 검증 완료를 뜻하지 않는다. 실제 실행 결과는 [T11_VALIDATION.md](T11_VALIDATION.md)에 증거와 대조해 기록한다.

## 적용 우선순위와 제스처 변경

최신 사용자 지시인 “하단 전체에서 자유롭게 조합”을 통합본 T11 및 T05의 기존 수평 제스처보다 우선한다. T05처럼 드래그 도중 수평 거리만 충족하면 즉시 전달하는 동작은 자유 배치·조합을 방해하므로 새 T11 씬에서만 다음 방식으로 적용한다.

- 잡은 구슬은 하단 전체에서 움직일 수 있다. 화면 가운데에서 손을 떼면 자유 배치이며 전달하지 않는다.
- 보내려는 쪽의 화면 가장자리에서 손을 뗄 때 전달 후보를 만든다. 들고 가장자리에 도달했거나 수신 직후 가장자리에 놓였다는 이유만으로 전달하지 않는다.
- 기존 Config의 수평 거리 `화면 너비 × 0.18` 이상과 방향 우세 `|dx| ≥ |dy| × 1.25`를 함께 요구한다. 별도의 속도·가속도 판정은 추가하지 않는다.
- 가장자리 판정 폭은 기존 `OrbRadiusScreenFraction = 0.055`를 사용하여 실제 하단 화면 너비의 5.5%로 정한다. 별도 Config asset이나 두 번째 조정값 원본을 만들지 않는다. 이는 기존 표현 값을 재사용한 T11의 `DEMO_ASSUMPTION`이다.
- 다른 구슬에 내려놓는 동작이 가장자리 전달보다 우선한다. 같은 Yin처럼 조합할 수 없는 상대를 겹쳐 놓아도 의도와 다르게 전달하지 않고 기존 조합 거부로 처리한다.
- Combined가 하단에서 실제 상단 전투 경계를 처음 넘으면 기존 자동 발사가 우선한다. Raw는 공격할 수 없다. 구슬을 잡았을 때의 확대·빛 효과를 유지한다.

기존 T05/T09/T10-B 씬에는 전달 활성화를 저장하지 않는다. 새 `OrbTransferBattle.unity`에서만 명시적으로 활성화하며 새 앱은 빌드16이다. T10-B의 기본 모드·빌드15와 기존 씬 및 증거는 보존한다.

## Host 승인과 동일 구슬 유지

P1은 Host, P2는 Client다. 두 사람 구조에서는 왼쪽·오른쪽 이웃이 같은 상대지만 요청 방향을 보존한다. Left는 상대 Right Edge, Right는 상대 Left Edge에 도착한다.

Host는 실제 송신자, session/round/request, 소유자, OrbId, 사용 가능한 Idle 상태, 상대 연결과 보관 상한을 확인한다. Raw와 Combined 모두 전달할 수 있다. Pending·Launching·Projectile·Consumed는 재전달하지 않는다. 성공은 같은 OrbId·종류·음양을 유지한 소유권 변경 한 번이며 생성·조합·명중으로 계산하지 않는다. 살아 있는 ID 집합과 개수도 바뀌지 않는다.

`transferCount`는 승인된 소유권 변경 횟수이고 `lastTransferSequence`와 `entrySide`는 마지막 전달을 식별한다. 일반 동기화에서는 로컬 드래그 위치를 유지한다. 새로운 전달 횟수가 확인된 경우에만 수신 위치를 적용한다. 상대에게 갔다가 다음 화면 갱신 전에 되돌아온 경우도 이 값으로 구분한다. 지연된 과거 전송 응답이 나중의 정상 반환 구슬을 삭제하지 않아야 한다.

화면 높이는 구슬 중심이 실제로 이동할 수 있는 영역을 기준으로 정규화한다. HUD, 구슬 반지름과 잡았을 때 문구의 여백을 제외한 범위를 송신·수신에 함께 사용한다. 각 화면의 픽셀 높이를 직접 전달하거나 송신 기기의 여백을 상대에게 적용하지 않는다. 서로 다른 화면 비율에서도 동일한 정규화 높이와 반대 경계 안쪽의 배치를 확인한다.

Pending은 Host 응답과 승인 상태를 기다린다. 응답 누락 시 기존 요청을 조회하며, 끝내 확정되지 않으면 세션을 오류로 종료한다. 로컬 시간 초과만으로 구슬을 다시 만들거나 같은 행동을 새 요청으로 재전송하지 않는다. 조합·발사·전달이 경합해도 하나의 구슬을 두 번 소비하지 않는다.

## 검증 범위와 기록

T11은 AT-07/08/18에 해당하는 전달, 잘못된 owner, 상대 만원·이탈, 중복 이벤트, 응답 누락과 행동 경합을 확인한다. 기존 시작 구슬0·스태미나100, 생성 비용20, 시간 회복20/3초, 실제 명중 공격자 회복5는 변경하지 않는다.

같은 Mac의 두 별도 앱 프로세스에서 일반 Host Seed와 자동 포인터로 Raw 8회·Combined 9회, 총17회 전달을 실행하는 진단 절차를 준비한다. 반환된 Raw를 실제 조합 재료로 쓰고, 수신한 Combined를 Client가 발사해 Host의 실제 피격을 확인한다. 첫 Client 전달 응답을 1.5초 동안 폐기와 동일 요청 중복 주입은 명시적인 오류 시험으로 분리한다. 자동 포인터는 실기기 Touch 증거가 아니다. 다른 화면 비율의 Mac 창도 실제 iPhone/iPad 화면 검증을 대신하지 않는다.

T12의 총100회 전달은 별도 요청과 실행이 필요하다. 양쪽 송신자·좌우 방향 각각25회, Raw50·Combined50으로 분배하는 절차는 `T11_RUNBOOK.md`에 준비한다. 반복 횟수는 안정성 보증이 아니다. 사용자에게 100번 수동 조작을 요구하는 방식으로 자동 진행하지 않는다. 향후 T12에서 명시적인 DEV 자동 요청 송신을 추가하는 방법을 선택할 수 있으나, 현재 T11의 Mac 진단 기능을 기기용 자동100회 기능으로 기록하지 않는다.

T12 정식 조건은 실제 iPhone 두 대다. 과거 확인된 가용 기기는 iPhone17과 iPad이며 iPad는 G2에서만 대체 승인을 받았다. T12에서 대체를 선택하려면 그때 별도 사용자 지시를 확인하고 적용 범위와 제한을 기록한다. 이번 작업은 T12·전체 G5 완료 또는 기기 PASS를 선언하지 않는다.
