## 발견한 문제와 수정

- **Ready 요청 경쟁:** 명단이 그대로인데 다른 사람의 Ready 때문에 전체 갱신 번호가 증가하면 늦게 도착한 유효 Ready가 거부됐다. 명단 변경 번호·참가자의 입장 번호와 요청 순서를 각각 검사하도록 수정했고, 이전 명단·중복 요청 거부는 유지했다. 회귀6개와 최종 실제 통신 결과를 남겼다.
- **좁은 화면의 자원 표기:** 320px 폭에서 P5 스태미나가 잘려 `P1:100 … P5:100`으로 줄였다. 최종 P5 화면과 다섯 값의 실제 텍스트 폭을 확인했다. 실기기 가독성은 별도다.
- 진단 코드의 초기 상태·Ready·Retry 대기 순서와 종료 해시 비교에도 경쟁 조건이 있었다. 참가자별 대기 지점을 보완했다. 결과 고정 검사는 HP·구슬·자원·라운드를 그대로 비교하고, 계속 갱신되는 전송 번호·Host 시각만 제외한다. 원본 전후 JSON을 보존한다.

실패했던 r1~r6 기록은 FAIL로 남겼다. r7 네 시나리오 PASS는 화면 수정 전 중간 결과이며, 최종 판정은 r8만 사용한다. 자동 실행 기록 수를 수동 검증 횟수로 부풀리지 않았다.
