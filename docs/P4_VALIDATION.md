자동 검사는 **1,427개**(기존1,311+신규116)다. 최종 자동 검사 뒤 드래그 안내 문구 한 줄과 명시적 Mac 검증 프로브 순서를 바꿨으며, 이후 최종 앱 빌드와 실제 Mac2~5인 실행으로 확인했다. 일반 게임 코드는 iOS ios-r1과 최종 Mac mac-r2가 동일하다. Mac 전용 프로브의 추가5회 실제 투척은 iOS에서 컴파일 제외되므로 iOS 검증으로 계산하지 않는다.

## 실제로 확인한 동작

Mac 각각의 시험에서 Raw 오른쪽과 Combined 왼쪽을 한 번씩 밀었다. 각 구슬은 추가 입력 없이4회 경계를 통과한 후 멈췄다. 320×700과390×700 화면을 함께 사용했으며, 매 경계의 같은 ID·반대쪽 진입·상대 높이·방향과 속도 감소를 대조했다. 경계를 넘으며 측정된 속도 증가는0이다. 총32회 자동 전달과1,449개 공통 상태에서 불일치0을 확인했다.

각 Mac 시험은 실제 Host 3D 피격5회→Victory→Retry로 정상 종료·초기화를 확인했다. 수신자의 보관20개를 채운 명시적 Fixture에서는 요청1회 거부 후 원래 소유자의 구슬1개가 끝에 정지했고 반발·복제·자동 재요청이 없었다. 이 실행은 직접 IP·DEBUG_POINTER·명시적 Raw/Combined/용량 Fixture이며, 실제 Touch·Bonjour·일반 Seed 생성의 결과로 확대하지 않는다.

실기기에서는 일반 Generate로 Raw1개를 만들었다. iPhone의 Touch 두 번 외에는 iPad에서 추가로 잡지 않았으며, 같은 OrbID `66e5691c1775452393f2619bbdbb98f6`가 오른쪽4회·왼쪽4회 이동했다. 매 경계의 속도 벡터와 수신 높이를 대조했다. 사용자 답변은 “여러 화면을 자동으로 오가다 멈춤, 화면도 정상”이다. 최종 정지와 확대·빛 효과·화면은 사용자 관찰 증거이며, 최종 로컬 속도0을 기기 텔레메트리로 직접 측정했다고 쓰지 않는다. 로그의 `TRANSFER_DISABLED`는 새 모드에서 옛 수동 손떼기 전달을 껐다는 뜻이고, 이어지는 PHYSICS 요청8회는 모두 승인됐다.

## 실패·환경 제한 보존

- 첫 CLI Prepare는 내부 바이너리 경로 대신 `.app` 번들을 요구하여 Editor 실행 전에 거부됐다. 지원 경로로 수정 후 성공했다.
- EditMode r1은1,286개 중1개 실패: 기존 씬 검사에 P4 중단 처리 유지 조건이 빠져 있었다. 기대값을 추가한 r2는 전부 통과했다.
- PlayMode r1은141개 중1개 실패: 물리 모드를 바꾸며 구슬이 과거 표시 위치로 돌아가는 실제 문제를 발견했다. 경계 대기·거부 때 Rigidbody와 화면 위치를 함께 동기화하고 검사도 강화했으며 r2 전부 통과했다.
- Mac2 r1은 연속 이동 자체는 확인했지만 Playing 중 Retry를 호출해 전체 FAIL이다. 게임의 정상 거부 조건을 유지하고, 프로브가 실제5회 명중·Victory 후 Retry하도록 수정한 r2와3/4/5인 최종 실행이 통과했다.
- 기기 목록·서명 검사의 제한된 환경 접근은 실패했으나 시스템 환경에서 다시 읽어 연결과 엄격 서명을 확인했다. 인증서 검증을 끄거나 프로세스를 강제 종료하지 않았다.

## 이번에 실행하지 않은 항목

실기기의 Combined 연속 전달·새 빌드의 직접 조합/3D Touch 재검사, 실제3~5대 기기 연속 이동, 전체 실기기 세션 상태 해시 비교, 실제 무선 지연/손실 주입, 실제 기기 수신20개 한도 시험은 **NOT_RUN**이다. 지연 마찰·용량·조합 유지·3D 피격은 자동/실제 Mac의 명시한 범위에서 검증했다. 원문 전체Gate나 과거 미실행 항목을 완료로 승계하지 않는다.
