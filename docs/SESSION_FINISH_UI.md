# 방 자동 입장·페인트 완료·UI 일관성 (#315·#367)

이 문서는 main dc45c4da에서 시작한 #315의 구현 설명에 #367의 현행 완료·결과 경로를 반영한다. 각 도입 당시 실행 결과와 #367의 실제 수행 여부는 VALIDATION.md의 해당 절에서 구분한다.

## 방 만들기

Hapio Home에서 인원/모드 선택 후 CREATE를 한 번 누른다. GameSession.RoomCreation은 광고가 확정될 때까지 안정적인 내부 handle로 추적하며, 같은 세션 이름·포트로 실제 Host에 인계한다. 등록 중 중복 생성·다른 방 입장·DEV 수정은 차단하고 취소·시간 초과·실패 시 이번 요청의 자원만 해제한다. Host의 P번호는 미선택으로 남는다. Lab의 별도 대기방 실험 경로는 유지한다.

## 페인트 전용 완료 연출

크랙 선택과 구식 박 분리 피니셔·실험 Scene·재생성 메뉴는 제거한다. 페인트의 기존 판정·성장·건조·통계·100% 목표는 유지한다. 옛 DEV79는 고정0 예약 슬롯으로 숨기고, 나머지0~204의 번호를 이동하지 않는다. 구형 모드1 값은 원자적으로 거절한다. #315 도입 당시 규약은 프로토콜5666·Lab27·Game10이었다. 현재 #367은 게임 토큰만 `C6HapioGame/22`로 올리고 프로토콜5677·`C6PhysicsLab/38`·공유 설정251개를 유지한다.

Hapio의100% Victory 및 완성 지도 commit → 예약 시각을 포함한 prepare → 각 기기의 최종 지도·고해상도 표현 준비와 예약 수신을 한 ACK로 확인 → 공통 NGO 시각 확정 → 완료 연출 → 전원 완료 확인 → 결과 Scene 순서다(#367). 도색이 시간차로 퍼져 완성된 경우도 같은 경로다. 멀티는0.75초의 예약 여유를 유지하고, 솔로는 이 여유만 생략한다. 실행 중인 물리 오브젝트·Collider 대신 mesh-only 표현 사본을 사용하며 전역 Time.timeScale과 원본 판정을 바꾸지 않는다.

연출 기본값은 LabPaintFinishPresentation.Duration=1.2초, PresentationSpeed=.2다. 완성 박의 잔여 회전을 느리게 보여주고 작은 완료 입자를 표시한다. 추가 명중/보상을 재실행하지 않으며 최종 paint·결과 통계는 그대로 관람에 전달한다. Defeat·2:2 종료·DEV 다음 스테이지는 이100% 연출에서 제외한다. Lab 단판은 같은 효과를 기존 로컬 경로로 재생한다.

Host가 최초 Victory를 관측했을 때 NGO 서버 시각 기준12초 deadline을 정하고 prepare와 진행 상태에 공유한다. 최종 지도 준비·재예약·반복 메시지·결과 사본 확보가 이 한도를 새로 시작하지 않는다. 완료 연출 중 결과 스냅샷과 관람 사본을 미리 확보해 결과 전환에서 재사용하므로 Story 결과 사본을 위해 추가30초를 기다리지 않는다. 한도에 도달하면 완료 연출을 생략한다. 이후 결과 전환에서도 최종 지도가 일치하지 않으면 중간 StageResult는 기존 정책대로 GameOver가 되고, 최종 Completed만 클리어를 보존하며 지도 미동기화 안내와 함께 결과로 이동한다.

CPU 최종 지도 일치 확인과 GPU 관람 사본 생성은 별개다. CPU 지도 조건을 만족해도 GPU 사본 생성이 실패하면 현재는 별도 오류 안내 없이 관람이 비활성화될 수 있다. 이 기존 제약은 #367에서 변경하지 않으며 없는 도색이나 결과를 만들어내지 않는다.

1·2스테이지 결과에서는 전원 결과 수신 ACK 후 누구도 관람하지 않을 때 Host가 **다음 스테이지**를 누른다. 별도 Ready 입력과10초 자동 진행은 없다. Hapio Battle의 독립 Lab 결과 카드·대시보드는 숨기며, 공유 통계·관람 기능과 기존2:2 결과·같은 방 로비 복귀는 유지한다. 결과 화면의 세부 동작은 [결과 UI 안내](STAGE_RESULT_UI.md)를 따른다.

결과 화면은 OnEnable에서 내용을 초기화한다. 최소 다음 프레임을 지나고 모든 마우스·터치가 해제되기 전에는 NEXT/HOME/관람 버튼과 해당 콜백을 차단한다. 이후 새 입력으로 결과 행동을 시작하며 입력 보호를 위한 고정 초 대기는 없다.

## UI와 방향

스태미나 위치·크기·부모와 구슬 입력 카메라는 유지하고 LabOrbHudComposition이 뒤 HUD → 구슬 합성 이미지 → 전경 HUD 순서를 복원한다. 결과 화면의 GamePreviewAspect는 저장된 바깥 표시 영역을 유지하고 내부 RawImage만 texture 비율에 맞춘다.

#360에서 내 `LocalPlayerCircle`과 자식 도색 패턴도 기존 뒤 HUD에 포함했다. 2:2에서 나중에 만들어지는 Team Ring은 내 P 바로 뒤에 함께 둔다. 따라서 조합판 → 내 P·패턴·팀 고리 → 구슬 순서이며, 원래 Image/RectTransform의 위치·크기·번호 갱신을 유지한다. 기존 합성 카메라·RenderTexture를 재사용하며 좌우 이웃·미니맵·로비 P와 버튼·정지·결과 화면의 순서는 바꾸지 않는다. 실제 실행 여부는 VALIDATION.md의 #359/#360 기록을 따른다.

일반 협동에서 P1→P2→…는 위에서 내려다본 시계방향이다. 내 자리를 아래에 놓았을 때 다음 P가 왼쪽, 이전 P가 오른쪽이다. LabPlayerSlots의 동일 이웃 계산을 Host 실제 전달·HUD·매혹 표시가 사용하고, 미니맵·카메라·투척도 맞춘다. 손짓의 실제 좌우와 반대편 입구/속도는 유지한다. 2:2는 기존 팀 배치·팀 전달·외벽 규칙을 따로 유지한다.

## iPhone 확인

기존 가장자리 구슬의 안쪽 밀어주기와 세로 고정을 유지한다. 실제 조작 가능한 전투에서 좌우/하단 제스처를 유예하고 메뉴·정지·결과에서는 원복한다. 복귀 시 native view에 재적용하며 Development 로그에서 desired/applied 값을 확인할 수 있다. 첫 하단 스와이프로 인한 오이탈을 줄이는 방식이고 홈 이동을 완전히 막지는 않는다.
