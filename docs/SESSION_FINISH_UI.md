## 방 만들기

Hapio Home에서 인원/모드 선택 후 CREATE를 한 번 누른다. GameSession.RoomCreation은 광고가 확정될 때까지 안정적인 내부 handle로 추적하며, 같은 세션 이름·포트로 실제 Host에 인계한다. 등록 중 중복 생성·다른 방 입장·DEV 수정은 차단하고 취소·시간 초과·실패 시 이번 요청의 자원만 해제한다. Host의 P번호는 미선택으로 남는다. Lab의 별도 대기방 실험 경로는 유지한다.

## 페인트 전용 완료 연출

크랙 선택과 구식 박 분리 피니셔·실험 Scene·재생성 메뉴는 제거한다. 페인트의 기존 판정·성장·건조·통계·100% 목표는 유지한다. 옛 DEV79는 고정0 예약 슬롯으로 숨기고, 나머지0~204의 번호를 이동하지 않는다. 구형 모드1 값은 원자적으로 거절한다. 프로토콜5666, Lab 연결 토큰27, Hapio 연결 토큰10을 사용하며 참가 앱은 같은 규칙 버전이어야 한다.

Hapio의100% Victory 및 완성 지도 commit → 각 기기의 최종 고해상도 표현 준비 → 전원 준비 확인 → 공통 NGO 시각 예약/확인 → 완료 연출 → 전원 완료 확인 → 결과 Scene 순서다. 도색이 시간차로 퍼져 완성된 경우도 같은 경로다. 실행 중인 물리 오브젝트·Collider 대신 mesh-only 표현 사본을 사용하며 전역 Time.timeScale과 원본 판정을 바꾸지 않는다.

연출 기본값은 LabPaintFinishPresentation.Duration=1.2초, PresentationSpeed=.2다. 완성 박의 잔여 회전을 느리게 보여주고 작은 완료 입자를 표시한다. 추가 명중/보상을 재실행하지 않으며 최종 paint·결과 통계는 그대로 관람에 전달한다. 준비·동기화가12초 안에 완료되지 않으면 연출만 건너뛰어 무한 결과 대기를 피한다. Defeat·2:2 종료·DEV 다음 스테이지는 이100% 연출에서 제외한다. Lab 단판은 같은 효과를 로컬로 재생한다.

## UI와 방향

스태미나 위치·크기·부모와 구슬 입력 카메라는 유지하고 LabOrbHudComposition이 뒤 HUD → 구슬 합성 이미지 → 전경 HUD 순서를 복원한다. 결과 화면의 GamePreviewAspect는 저장된 바깥 표시 영역을 유지하고 내부 RawImage만 texture 비율에 맞춘다.

#360에서 내 `LocalPlayerCircle`과 자식 도색 패턴도 기존 뒤 HUD에 포함했다. 2:2에서 나중에 만들어지는 Team Ring은 내 P 바로 뒤에 함께 둔다. 따라서 조합판 → 내 P·패턴·팀 고리 → 구슬 순서이며, 원래 Image/RectTransform의 위치·크기·번호 갱신을 유지한다. 기존 합성 카메라·RenderTexture를 재사용하며 좌우 이웃·미니맵·로비 P와 버튼·정지·결과 화면의 순서는 바꾸지 않는다. 실제 실행 여부는 VALIDATION.md의 #359/#360 기록을 따른다.

일반 협동에서 P1→P2→…는 위에서 내려다본 시계방향이다. 내 자리를 아래에 놓았을 때 다음 P가 왼쪽, 이전 P가 오른쪽이다. LabPlayerSlots의 동일 이웃 계산을 Host 실제 전달·HUD·매혹 표시가 사용하고, 미니맵·카메라·투척도 맞춘다. 손짓의 실제 좌우와 반대편 입구/속도는 유지한다. 2:2는 기존 팀 배치·팀 전달·외벽 규칙을 따로 유지한다.

## iPhone 확인

기존 가장자리 구슬의 안쪽 밀어주기와 세로 고정을 유지한다. 실제 조작 가능한 전투에서 좌우/하단 제스처를 유예하고 메뉴·정지·결과에서는 원복한다. 복귀 시 native view에 재적용하며 Development 로그에서 desired/applied 값을 확인할 수 있다. 첫 하단 스와이프로 인한 오이탈을 줄이는 방식이고 홈 이동을 완전히 막지는 않는다.
