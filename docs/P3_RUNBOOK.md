# P3 최대 5인 프로토타입 · 빌드와 사용 안내

이 문서는 빌드23 `FivePlayerBattle`의 사용 절차다. 작성된 절차나 테스트 코드가 실행 완료를 뜻하지 않으며, 실제 결과는 [P3 검증 기록](P3_VALIDATION.md)에서 확인한다. 기본 Unity·Xcode 사용법은 [직접 빌드 README](../BUILD_README.md)를 함께 참고한다.

## Unity에서 준비하기

1. Unity Hub에서 `/path/to/2026-C6-M10-MUSA`을 **Unity 6000.5.7f1**로 연다. 현재 패키지와 렌더러를 유지한다.
2. 열어 둔 씬에 수정한 내용이 있으면 저장한다. **C6 → Next Phase → P3 → Prepare Five Player Battle**을 선택한다.
3. `Assets/_Project/HapioMVP/Scenes/FivePlayerBattle.unity`를 연다. 처음 준비할 때 저장된 `ThrowBattle`을 바탕으로 별도 씬을 만들며, 이미 P3 씬이 있으면 덮어쓰지 않고 참조와 설정을 검사한다.
4. 이 씬의 Lobby·Game·Battle Controller는 최대 인원5를 사용한다. 기존 `ThrowBattle` 등 이전 씬은 기존 2인 모드를 유지한다. 이전 씬을 열었다고 P3 모드로 바뀌지 않는다.
5. Play를 눌러 로비를 살펴볼 수 있다. 다른 실행본과 연결하려면 모든 참여자가 빌드23·같은 P3 모드를 사용해야 한다.

프로젝트의 원본 설정은 `Assets/_Project/HapioMVP/Config/ScreenLayoutConfig.asset` 하나다. 카메라·몬스터·구슬 동작을 개인별로 임의 변경한 실행본을 섞지 않는다. 같은 프로젝트의 Editor가 실행 중일 때 그 폴더에 별도 Unity 일괄 빌드를 동시에 실행하지 않는다.

## Mac 또는 iOS로 빌드하기

Build Profiles에서 먼저 실제 빌드 플랫폼을 선택한 뒤 다음 메뉴를 사용한다.

| 대상 | 메뉴 | 기본 출력 |
|---|---|---|
| macOS | C6 → Next Phase → P3 → Build macOS Five Player Battle | `Builds/NextPhase/P3/macOS/C6FivePlayer.app` |
| iPhone·iPad | C6 → Next Phase → P3 → Export iOS | `Builds/NextPhase/P3/iOS/Unity-iPhone.xcodeproj` |

기존 출력이 있으면 새 출력 위치를 사용한다. `C6_P3_OUTPUT_ROOT` 환경 변수가 지정되어 있으면 그 폴더 아래에 출력한다. 기존 결과를 지워서 다시 빌드할 필요는 없다.

최종 검증 출력의 로컬 보관 위치는 `Builds/NextPhase/P3/build23-final/`이다. 그 안의 iOS 프로젝트 위치는 `iOS/Unity-iPhone.xcodeproj`, 서명 앱 위치는 `C6Prototype.app`이다. 해당 파일이 실제로 만들어졌는지와 최종 경로는 검증 기록에서 확인한다.

iOS 출력 뒤 Xcode에서 `Unity-iPhone`을 열고 **본인 Apple 개발 Team 개인 Team**과 실제 연결 기기를 선택한다. iPhone과 iPad를 모두 지원한다. 잠금 해제·Mac 신뢰·개발자 모드가 준비된 기기에서 설치하고 실행한다. 앱 빌드와 서명, 기기 설치와 실행, 실제 화면·터치 확인은 각각 별도 결과다. Android 빌드나 Android 연결은 이번 구현 범위에 포함하지 않는다.

## 2~5명이 방에 입장하기

모든 기기를 같은 Wi-Fi에 연결하고 C6 앱을 전경에 둔다. Mac 실행본도 한 명으로 참여할 수 있다.

1. Host가 **CREATE ROOM**을 누른다. Host는 P1이다.
2. 나머지는 **FIND ROOMS**에서 같은 방을 찾아 **JOIN**한다. 발견되지 않으면 **DIRECT IP**를 열어 Host의 실제 Wi-Fi IPv4와 동일한 Port를 입력한다. 기본 Port는7777이다. 로컬 네트워크 권한 알림이 나오면 허용한다.
3. 입장 순서대로 P2~P5가 정해진다. 로비의 전체 참가자 목록, 자기 번호, LEFT·RIGHT 이웃을 확인한다. `CHECKING SETTINGS`가 끝나야 해당 참가자의 Ready가 가능하다.
4. 참여할 사람이 모두 들어온 뒤 각자 **I'M READY**를 누른다. 최소2명·최대5명이며, 현재 연결된 사람 전원이 설정 확인과 Ready를 마쳐야 Host의 **HOST START**가 활성화된다.
5. Host가 시작하면 각 Client가 최초 게임 상태까지 확인한다. **마지막 Client의 확인 응답이 도착할 때까지** 게임 조작은 열리지 않는다. 이후 모두 같은 전투에 들어가며 시작 구슬0개·스태미나100·몬스터 HP100·시간180초를 사용한다.

P1·P2·P3이 있으면 P1의 왼쪽은 P3, 오른쪽은 P2다. P2의 왼쪽은 P1, 오른쪽은 P3다. 2명일 때는 양쪽 이웃이 같은 상대다. 6번째 참여자는 방이 가득 찼다는 안내와 함께 입장이 거부된다.

로비에서 Client가 나가면 남은 사람의 순서를 유지하며 번호를 빈자리 없이 정리한다. **전원의 Ready를 해제**하므로 다시 확인해야 한다. 나갔다가 다시 입장하는 사람은 마지막 자리에 배치된다. 전투가 시작된 뒤에는 좌석을 바꾸거나 새 사람을 받지 않으며, 참가자가 이탈하면 기존 방 종료 정책을 따른다. 자동 재접속이나 Host 이전 기능은 없다.

## 구슬과 공격 조작

- **GENERATE / 20**은 스태미나20을 사용해 Raw 하나를 만든다. 스태미나는100까지 시간에 따라 회복하며, 회복 속도는3초당20이다.
- 하단 구슬은 평면 위에서 밀리고 튕기며 마찰로 서서히 멈춘다. 자연스럽게 닿은 것만으로 합쳐지지 않는다. 반대 음양 Raw를 직접 드래그해 겹친 뒤 정상적으로 손을 놓아 Combined를 만든다.
- 하단 왼쪽 또는 오른쪽 끝으로 끌고 **손을 놓으면** 그쪽 이웃에게 전달된다. 받는 쪽의 반대 가장자리에 같은 ID의 구슬이 정지한 상태로 도착한다. 손을 잡고 있는 동안에는 전달되지 않는다.
- Combined를 상단 전투 영역으로 올리면 투척 준비가 된다. 위쪽 움직임을 주면서 손을 놓는 순간 방향과 빠르기를 계산해 던진다. 상단에서 멈췄다가 놓거나 취소하면 발사되지 않는다. Raw는 공격할 수 없다.
- Host가 실제 3D 충돌을 확인했을 때만 공통 몬스터 HP가20 줄고 **실제 공격자에게만 스태미나5**가 회복된다. 다른 참가자에게 보이는 비행은 Host 결과를 따라 표시한다.

개인 보관 한도는20개다. 비행 중인 구슬에는 별도로 개인20개의 개발 상한이 있다. 따라서5명 기준 보관100개와 비행100개까지 검사하도록 구성했다. 발사 상한에 걸린 구슬은 하단에 남는다. 이 숫자는 자동으로 구슬을 주거나 생성 비용을 면제한다는 뜻이 아니다.

## 개발자가 Mac 여러 실행본으로 확인하기

`tools/p3_mac_smoke.py`는 새 P3 Mac 앱 여러 개를 실행해 확인하는 개발 도구다. `--count`에는2·3·4·5를 지정한다. `--app`에는 `.app` 폴더 자체가 아니라 **내부 실행 파일**의 절대 경로를 전달하고, `--output`에는 아직 존재하지 않는 절대 경로를 사용한다.

최종 출력이 위 경로에 준비된 경우의 예시는 다음과 같다.

```bash
cd /path/to/2026-C6-M10-MUSA
python3 tools/p3_mac_smoke.py \
  --app '/path/to/2026-C6-M10-MUSA/Builds/NextPhase/P3/build23-final/macOS/C6FivePlayer.app/Contents/MacOS/C6 Prototype' \
  --output '/private/tmp/c6-p3-five-player-check-01' \
  --count 5 \
  --port 25153
```

이 도구는 같은 Mac의 직접 IP 연결, 정상 비용을 낸 Generate, 시험용 Raw·Combined·최대 수량 주입, 자동 포인터를 구분해 기록한다. 5인 경우에는6번째 입장 거부도 확인하도록 구성되어 있다. 생성된 `summary.json`, 각 참여자의 `result.json`과 화면 이미지, 원시 로그에서 해당 실행 결과를 확인한다. 진단 앱은 제한 시간 후 스스로 종료하며, 기존 Editor나 다른 앱을 강제로 종료하지 않는다.

**시험용 주입은 일반 플레이로 획득한 결과가 아니며, 자동 포인터는 실제 Touch가 아니다.** 직접 IP 결과로 Bonjour 탐색이 완료됐다고 판단하지 않는다. 전체 프로그램을 실행하지 않았거나 결과 파일이 없으면 실행 완료로 기록하지 않는다.

## 실제 기기가 준비되었을 때의 짧은 확인

현재 사용 가능한 iPhone·iPad·Mac을 함께 사용하면3인 세션을 구성할 수 있다. 이것은 스마트폰·태블릿3대나5대의 실기기 시험을 대신하지 않는다. 먼저 실제로 연결 가능한 기기와 앱 빌드를 확인한다.

3명이 Ready·시작을 마친 뒤 한 사람이 만든 Raw를 왼쪽 이웃과 오른쪽 이웃에게 각각 보내 서로 다른 대상에게 도착하는지 확인한다. 받은 Raw를 직접 조합해 Combined로 만든 뒤 전달하고, 받은 사람이 투척해 공통 HP와 공격자 회복을 확인한다. 화면 잘림, 구슬을 잡는 표시, 정지 수신, 실제 손떼기·관성·반발도 함께 본다. 문제 없는 동작을 기계적으로100번 반복할 필요는 없다.

로비 이탈·재입장 시 번호 정리와 Ready 해제, 새 판의 구슬0·스태미나100·HP100·시간180 초기화도 별도로 확인한다. 실제 결과와 사용한 기기 수·빌드·확인 날짜를 남기며, 아직 실행하지 않은 항목은 미실행으로 둔다.
