# 야광귀 흔들기 해제 UI (#652)

Figma 원본: https://www.figma.com/design/wW7ny7lNQ4DXNJ4kD46AuR?node-id=4607-4747

`LabYaguangFlashHud`가 기존 입력·횟수·구슬 복원·Host 해제/재시도·보상을 소유한다. `LabYaguangShakeCue`는 안내 UI, `LabYaguangFlashLight`는 빛 표현만 담당한다. Scene/Prefab·공유 설정·통신 규약은 바꾸지 않는다.

## 현재 표시와 타이밍

- UI·숫자·눈 말풍선은349×765 균일 배율로 배치한다. 눈 말풍선은104×104 기준으로 Canvas 크기에 맞춘다.
- 3·2·1: Figma의 Shilla Culture Bold110·붓선·단계별 색을 PNG로 표시한다. 숫자는 처음부터 불투명하게 표시하고 기존1.45→1배 팝을 유지한다. 예고 빛은3일 때2.16%의 좁고 따뜻한 빛, 2일 때6.6%의 넓고 밝은 빛, 1일 때12%의 가장 넓은 빛으로 구분한다. 타원형 경계를 유지해 숫자를 가리지 않는다. 4초 이상 맞춤 예고에는 동적 Text가 남아 있다.
- 숫자가 끝나면 화면 전체가 동시에 번쩍인다. 최초 섬광 또는 인식한 흔들기 입력(K키 포함)마다0.5초 동안 제곱 감쇠하는 단발 섬광을 표시한다. 자동 반복은 없다. 원 확대·추가1 머무름·숫자 교차 페이드는 없다.
- 이후 잔광은 기존20% 입력에0.85배를 적용해15% 옅게 표시하며 흔들기 진행률에 따라 더 줄어든다. Screen 합성에서 빛 기여를 잔광은최대22%, 섬광 피크는최대42%로 제한해 배경이 보인다. 짧은 변의9% 반경으로 모서리를 둥글게 자른다. 단발 펄스 아래 같은 잔광을 유지하고 펄스 세기에 맞춰 Bloom을 보간한다.
- 폰은0회부터±12도/초당5회로 계속 움직인다. 첫 흔들기를 인식하면 제목·안내만 숨긴다. 목표2~18회에 맞춰 게이지 칸 수를 만들고, 목표 도달/일시정지/전투 종료의 기존 숨김 조건을 유지한다.

## 에셋과 렌더링

- Resources/Yaguang/Shake의 투명2배 PNG11개는 Single Sprite·무압축이다. 글자 PNG는 글리프 경계로 추출되므로 원본2배 크기의 절반을 해당 텍스트 칸에 중앙 배치한다. Source.json에 각 노드 출처를 기록했다. 횟수는 Nanum Brush Script Regular38·MetalYellow/700이며 OFL을 함께 보관한다.
- 일반/노란 눈 전체 PNG가 기존 EyeGlowAt 타이밍으로 전환된다. 다음 폭탄·단어 알림에서는 공용 배경과 꼬리 기준점을 복원한다.
- 전용 ARGBHalf/24-bit depth 카메라와 실제 URP Bloom으로 흰빛·옅은 황금빛을 렌더링해 UI 아래에 더한다. Bloom 강도는 펄스2.2, 나머지.35, scatter .75다. 기존 조명·카메라·전역 볼륨·파이프라인 자산과 패키지 버전은 바꾸지 않는다.
- 전용 리그는 UI 자식으로 소유하고 미사용31번 레이어·화면 밖에 둔다. Canvas 배율은 상쇄한다. 비활성 시 카메라/볼륨을 끄고 파괴 시 리그·프로필·재질·텍스처를 해제한다. 출력 긴 변 최대960px, Bloom 최대5단계이며 로딩 중 실제 렌더를 준비한다.
- 현재 LDR 최종 색 보정은 출력 밝기를1로 제한한다. GPU 검사는 후처리 전 HDR 발광, 후처리 후 광원 바깥 Bloom 증가와 자원 정리를 각각 확인한다. 지원되지 않는 셰이더 환경은 흰빛 UI fallback을 사용한다.

실행한 검사와 수정 이력은 VALIDATION.md의 #652 기록을 따른다. 실기기 밝기·성능·안전영역과 실제 다인 전투는 별도 검증 대상이다.

- 프로필이 없으면 번쩍임 피크의 코드 기본값은 HDR 흰빛10배다. 실험실에서 저장한 밝기·색상·Bloom은 유지하고 게임 섬광의 면적은항상1로 고정한다. 예고·잔광·숫자 표시는 그대로다.

## 발광 실험실

`C6 Lab > Experiments > Yagwanggwi Glow Lab`에서 실제 게임의 HDR 발광 셰이더와 URP Bloom을 미리 본다. Play 없이 동작한다.

- 순간 발광 HDR 밝기, 발광 면적, 중심 빛·주변 광채·Bloom 색상을 조절한다.
- 순간/예고·잔광 Bloom, 빛 번짐, Bloom 시작 밝기, 예고/잔광 배율을 비교한다.
- 계속 발광, 예고 3/2/1, 순간 번쩍임, 잔광, 전체 흐름을 선택한다. 번쩍임과 전체 흐름은 재생·반복·재생 위치를 지원한다.
- `게임 안내 함께 보기`로 숫자 PNG와 흔들기 안내를 겹쳐 본다. `작은 발광체 예시`는 면적을 줄인 강한 발광 프리셋이다.
- 실험값은 창에만 보관한다. `현재 게임값`은 저장된 게임 설정을 다시 읽는다. 최초 실험실의 면적 .18은 미리보기 전용이다.
- `게임 기본값으로 저장`을 눌러야 `Resources/Yaguang/Light/Tuning.asset`에 기록하고 실행 중인 빛에도 적용한다. 프로필이 없으면 기존 코드 기본값을 그대로 사용한다. 저장은 Undo를 지원하며 해당 에셋만 저장한다.
- 실험용 UI 카메라는 레이어29, 발광 카메라/Volume은 레이어30으로 게임의 레이어31과 분리한다. 창을 닫거나 스크립트를 다시 불러오면 임시 카메라·RT·Volume을 정리한다.

- `번쩍임`·`전체 흐름`은 게임과 같은 전체 화면 단발 펄스를 사용한다. `발광 계속보기`에서만 면적 슬라이더로 고정 광원을 비교한다.


## 전체 화면 섬광

중앙 원이 커지는 동작은 제거했다. 게임/전체 흐름의 면적은 첫 프레임부터1이다. 첫 피크는 흰색에 가깝게 밝히고 빠르게 사라지며 인식한 흔들기마다 새로 시작한다. Screen 합성의 최대42% 기여로 뒤의 빛나는 원과 배경이 계속 보이게 한다. 이후 중앙의 흰빛→외곽의 연노랑 잔광과0.85배 완화는 유지한다.

섬광 판정 후 잔광이 남아 있고 Pause가 아니면, 인식한 흔들기의 로컬 시각으로 단발 섬광을 시작한다. 기존 K키 디버그 입력과 실제 기기 흔들기를 같은 경로로 처리한다. 새 서버 섬광 판정이나 중복 햅틱은 만들지 않는다. 실험실 잔광 모드에서 K키 또는 `K · 흔들기 1회` 버튼으로 확인한다.

## 흔든 횟수에 따른 빛 제거

- 남은 빛 비율은 `glare × (1 - shownShake)`다. `shownShake`는 인식한 횟수/목표 횟수를 부드럽게 따라간다. 목표 도달 시 즉시0이다.
- HDR/Bloom 후 최종 합성 셰이더 `_Visibility`에 비율을 곱한다. 따라서 광원이 포화돼도 입력 섬광·잔광의 밝기와 덮임이 함께 줄어든다. 잔광 원본에 진행률을 중복해서 곱하지 않는다.
- 예고 숫자의 빛은 유지한다. 셰이더 미지원 fallback의 섬광에도 같은 비율을 적용한다. 구슬 복원·Host 요청·보상 판정은 기존 흐름을 유지한다.
- 실험실 `잔광`/`전체 흐름`에서 `인식한 흔들기 / 10` 슬라이더로0/10→5/10→9/10→10/10을 비교한다.
