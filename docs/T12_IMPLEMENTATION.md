# T12 구현과 실기기 수정

T12는 T11의 저장된 씬에서 별도의 IntegratedDeviceBattle 씬을 만든다. 같은 두 카메라·Config·NGO Host 권한·실제 Rigidbody/Collider 피격을 다시 연결하고 저장된 씬 참조를 검사한다. 빌드17은 실기기 진입과 부분 통합 검증, 빌드18은 그 과정에서 드러난 좌측 전달과 상태바 중단 수정을 구분한다.

## 좌측 전달

첫 생성 열 또는 수신 경계에서 구슬을 가까운 화면끝으로 끌 때, 기존 전체 화면폭18% 거리보다 실제 이동 가능한 공간이 작았다. GestureTuning의 선택 옵션 reachableEdgeTransferDistance는 기본false이며 T12 씬에서만 true다. 요구 거리는 기존18%와 ‘시작점에서 선택한 화면끝까지 거리의 절반’ 중 작은 값이되, 경계 띠의 절반 너비를 최소 움직임으로 둔다. 새 제스처·수평 우세·유효 하단 높이·끝에서 손떼기·조합과 발사 우선순위는 유지한다.

1206px 화면의 오른쪽 경계에서 두 큰 float 좌표를 빼고 정규화하면 정확한 문턱을 조금 못 미치는 값이 되는 실패가 첫 검사에서 드러났다. T12 옵션은 요구 거리를 같은 픽셀 좌표계의 종료 경계로 계산해 UP 좌표를 직접 비교한다. 임의 오차 범위를 늘리지 않았으며 정확한 문턱 승인과1px 미달 거절을 시험한다. 실패XML도 보존한다. 이전씬·Config 바이트와 기존 기본false 동작은 유지한다.

## 상태바와 실제 백그라운드

사용자는 결과 화면이 정상이라고 확인했고 상태바를 펼칠 때 연결 종료와 시간 중단만 수정하도록 지시했다. 결과 화면과 버튼 보호 처리에는 변경이 없다. Unity가 내보낸 iOS lifecycle에서 foreground inactive에도 엔진pause와 OnApplicationPause(true)를 보내 기존 Lobby.Leave가 실행되는 경로를 실제 기기 로그로 확인했다.

T12ForegroundLifecyclePostprocess는 실제 처리된 씬이 T12 하나인 iOS export에서만 실행한다. Unity6000.5.7f1과 검토한 두 native 원본 전체 SHA256, 각 치환 위치를 확인한다. 설치된 Unity와 과거 빌드 파일은 수정하지 않으며 새 export에 원본 백업과 패치receipt를 남긴다. 모르는 버전·사용자가 변경한 원본·일부만 적용된 상태는 임의 덮어쓰기 대신 실패한다.

상태바가 덮인 foreground inactive에서는 focus상실과 입력정리를 유지하고 엔진pause를 생략한다. 기존 CADisplayLink와 게임 루프가 타이머·통신을 계속 진행하도록 한다. 실제 background에서는 displayLink를 멈추고 pause메시지를 GPU없는 마지막 루프에서 처리한 뒤 엔진을 멈춘다. 수동pause는 보존한다. background모드·통신timeout·Host시계·결과UI는 바꾸지 않는다. 이는 T13 전체 앱중단 기능의 완료가 아니며 실제 장기 상태바 검증은 별도다.

## 실행 증거용 진단

T12DeviceDiagnostics는 명시적인 실행식별자를 준 개발 실행에서만 활성화된다. 일반 앱에서는 자동입력·파일폴링을 시작하지 않는다. 제한된 JSON명령은 정상 생성·조합·전달·발사 요청을 사용하며 HP·스태미나·시간·음양·구슬을 직접 주입하지 않는다. 반복전달은 두 기기의 각 승인 상태 관찰을 맞춘 뒤 다음 요청을 보내며 실제Touch의 증거로 계산하지 않는다.

명령ID/runId/계획지문·세션/라운드·송신자·현재소유자·동일ID/정보/살아있는ID집합을 기록한다. timeout과실패도 보존한다. Clock과focus/pause실제콜백에는UTC를 기록해 상태바가 열린 구간과 게임시간을 대조한다. 일시정지·focus를 변경하는 진단이 아니다. 여러 게임세션에서라운드/상태번호가 반복될 수 있으므로 세션을 나눠 분석한다. 결과에서는 revision이 계속 증가할 수 있으므로 HP·스태미나·구슬·남은시간과HUD가 고정됐는지를 본다.
