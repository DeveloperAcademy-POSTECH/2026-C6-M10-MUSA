# 구슬 조작 영역 경계선 계획 (#40)

기준 브랜치: `feat/#40-orb-area-borderline` · 대상 씬: `Assets/_Project/HapioMVP/Scenes/ContinuousTransferBattle.unity`

## 목적과 현재 상태

Figma 정면 배경을 적용한 뒤, 플레이어가 구슬을 굴리고 직접 드래그해 조합하는 하단 영역의 끝을 화면에서 알아보기 어렵다. 배경 이미지는 유지하고 **실제 구슬 작업 공간에 반투명 레이어와 경계**를 표시한다. 이 작업은 시각적 안내이며 구슬 물리·입력·전달·조합·투척 판정은 바꾸지 않는다.

UI 에셋 적용 전의 하단 영역은 별도 테두리가 아니라 어두운 카메라 배경과 26개 격자 선으로 구분됐다. Figma 적용 시 격자의 Renderer만 꺼졌고, 오브젝트는 남아 있다. `T09Overlay/ViewportDivider`는 이전에도 Image가 비활성화돼 있었으므로 이것만 켜는 것은 옛 구슬 영역의 복원이 아니다. 기존 격자를 통째로 활성화하면 현재 배경과 겹치고 하단 버튼 구역까지 선이 보일 수 있다.

실제 구슬이 표시되고 이동하는 공간은 `T09Hud.OrbWorkspaceScreenRect`다. 하단 카메라 영역과 기기 안전 영역의 교집합에서 `ResourceControls` 상단을 하한으로 사용한다. 상단 전투 화면으로 던지는 기준은 `SplitScreenLayout.BottomPixelRect.yMax`다. 현재 조합 손떼기 판정은 하단 카메라 전체를 허용하므로, 새 선은 **구슬이 움직이는 공간의 안내**로 정의하고 조합 가능 영역이 선과 픽셀 단위로 일치한다고 주장하지 않는다. 판정까지 선에 맞추는 변경은 별도 게임 규칙 작업으로 다룬다.

## 제안하는 화면 표현

1. 현재 Figma 배경의 어두운 청색과 돌바닥 색에 맞춰, 구슬 공간 전체에 짙은 청색 반투명 레이어를 놓고 가는 청록색 경계를 겹친다. 불투명 패널이나 촘촘한 격자는 넣지 않아 배경과 구슬이 계속 보이게 한다. 색·두께·투명도는 씬 Inspector에서 조절 가능하게 둔다.
2. 하단 카메라와 전투 화면 사이에는 상단 수평선을, 구슬 공간과 생성 버튼·스태미나·시간 표시 사이에는 하단 수평선을 둔다. 상단은 위로 던지는 출구임을, 하단은 구슬이 버튼 구역으로 들어가지 않는 끝임을 서로 다른 짧은 장식으로 구분한다.
3. 좌우 끝은 물리적인 벽이 아니라 이웃 화면으로 자동 전달되는 통로다. 연속된 세로 벽선 대신 짧은 열린 코너/방향 표식을 사용해 통과 가능한 경계로 보이게 한다. 전달 중 구슬과 표식이 겹쳐도 구슬을 가리지 않도록 약하게 표시한다.
4. 모든 장식은 기존 저장 Canvas의 편집 가능한 GameObject/Image로 둔다. `raycastTarget=false`로 터치를 가로채지 않으며, 사용자가 옮긴 HUD와 비활성화한 숫자 라벨은 유지한다.

## 구현 순서

1. Unity Editor에서 저장 씬과 현재 수동 배치 상태를 확인한다. 전체 `C6 → UI → Apply Figma Front Artwork` 메뉴는 수동 배치를 초기화하므로 다시 실행하지 않는다. 기존 격자와 `ViewportDivider`도 일괄 활성화하지 않는다.
2. `T09Overlay`에 작업 영역 전용 부모와 반투명 레이어, 상·하 수평선, 좌·우 열린 표식 자식을 추가한다. 기존 `T09Hud`·`T09BattleController` 참조와 Figma 배경/아틀라스 오브젝트는 유지한다. 씬·에셋 연결 변경은 Unity Editor API로 저장한다.
3. 장식 위치만 `OrbWorkspaceScreenRect`의 상·하·좌·우 값에 동기화한다. 고정 Y 좌표를 쓰지 않고 화면 크기, 안전 영역, 하단 카메라 분할, `ResourceControls`의 실제 상단 위치 변화에 따라 따라가게 한다. 색·두께·표식 길이와 투명도는 씬 값으로 남기고, 위치 계산 코드가 매 프레임 사용자의 스타일 값을 덮어쓰지 않게 한다.
4. 저장 씬에서 배경·몬스터·구슬·HP/시간/스태미나·Generate 버튼의 기존 활성 상태 및 연결을 비교한다. Figma 적용 도구를 후일 다시 사용할 경우 새 장식이 지워지거나 재배치되지 않도록 해당 도구의 처리 범위도 확인한다.

## 완료 기준과 검증

- 세로 iPhone 화면과 다른 화면 비율의 Editor 미리보기에서 경계가 실제 구슬 이동 공간과 맞고, 하단 HUD 위에 선이 침범하지 않는다. 안전 영역/화면 크기 변화와 HUD 높이 조정에도 경계가 따라간다.
- Figma 배경과 구슬은 반투명 레이어를 통해 계속 보이고, 선은 버튼을 가리지 않는다. 좌우 끝은 열린 통로로 인지되며, 장식 전체가 터치·드래그·Generate 입력을 차단하지 않는다.
- 직접 드래그한 Yin+Yang만 조합되고 자연 충돌은 조합되지 않는다. 구슬은 좌우 자동 전달과 감속을 유지하고, Combined를 위로 던질 수 있다. HP/시간/스태미나 표시는 계속 실제 수치에 반응한다.
- 저장 씬 참조 검사와 관련 EditMode/PlayMode 검사를 실행해 결과 수·실패 수를 기록한다. 새 iOS 빌드·실기기 확인을 수행한다면 그 결과를 별도로 기록한다. 이전 UI 실기기 기록을 새 경계선의 검증으로 승계하지 않는다.

## 구현·검증 기록 · 2026-09-22

저장 씬 `T09Overlay/OrbWorkspaceBoundary`에 `OrbAreaTint`, 상·하 그림자/강조선, 좌·우의 짧고 열린 표식을 추가했다. `OrbAreaTint`는 짙은 청색에 알파 0.42를 사용하며, 모든 `Image.raycastTarget`은 꺼져 있다. Canvas 안에서 경계 부모가 첫 번째 자식이므로 기존 HUD 컨트롤을 덮지 않는다. 사용자는 Inspector에서 각 자식 Image의 색·투명도와 RectTransform의 선 두께를 조정할 수 있다.

`OrbWorkspaceBoundaryView`는 프레임의 위치·크기만 `T09Hud.OrbWorkspaceScreenRect`에 맞춘다. 버튼 높이와 화면 분할·안전 영역이 바뀌어도 반투명 레이어와 선이 함께 이동한다. Figma 재적용 메뉴나 과거 격자는 실행하지 않았고, 구슬·조합·전달·투척 로직은 수정하지 않았다.
