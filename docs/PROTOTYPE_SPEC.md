## 프로젝트와 현재 구현

- 실제 루트는 `/path/to/2026-C6-M10-MUSA`, 원격은 비공개 `prototype-author/C6_Prototype`이다. Unity 6000.5.7f1, URP 17.5.0, Input System 1.20.0, Test Framework 1.7.0, UGUI 2.5.0, NGO 2.13.1, Transport 6.5.0을 유지한다.
- T07 씬은 `Assets/_Project/HapioMVP/Scenes/ResourceSmoke.unity`다. 저장된 T06 `AttackSmoke.unity`에서 별도로 파생하며, 기존 두 Base 카메라·상단 3D/하단 Orthographic 2D·Overlay HUD·발사 기준·연습 표적 Collider를 재사용한다. 이전 씬과 meta를 새 동작에 맞춰 덮어쓰지 않는다.
- T07 앱 설정은 버전 0.1.0, iOS 빌드 9, 기존 iOS ID `com.wolfuraark.c6prototype`, Mac ID `com.wolfuraark.c6prototype.t07.desktop`이다. iPhone+iPad 공용·세로·IL2CPP를 유지한다. 이 설정은 앱 빌드·서명·설치·실행 완료를 뜻하지 않는다.
- 명시적 개발 HOST 또는 직접 IP JOIN으로 실제 NGO 세션을 시작한다. 일반 라운드는 각 참가자에게 구슬 0개와 Stamina 100을 부여한다. 아직 정식 Ready/Host Start·180초 전투·승패 흐름은 T09 이전의 개발 상태다.
- 매 Generate 요청은 Raw 구슬 1개와 비용 20을 Host가 함께 확정한다. 첫 요청과 후속 요청은 동일하다. 첫 일괄 생성 및 `InitialBatchGenerated` 전용 상태는 사용하지 않는다.
- 개인 자원은 연속값이며, Playing이고 Host 앱이 운영체제에 의해 일시 정지되지 않은 동안 Host의 경과 시간으로 초당 `20 / 3`씩 회복한다. 백그라운드에서 일시 정지된 시간은 복귀 때 지급하지 않으며 단순 창 포커스 상실은 일시 정지로 보지 않는다. 화면의 다섯 구분선은 20 단위를 보여 주는 표시다. 자원을 정수 0~5로 반올림하거나 3초마다 한꺼번에 지급하지 않는다.
- 일반 음양은 Host Seed·실제 참가자 ID·그 참가자의 성공 생성 순번으로 결정한다. 거절·중복 요청과 다른 참가자의 요청 순서가 해당 참가자의 음양 순서를 바꾸지 않는다. 짧은 구간의 음양 균등 개수나 교대를 보장하지 않는다.
- 보관 상한은 개인별 20개다. Idle과 Launching을 보관 수로 센다. 비행 중 Projectile과 종료된 Consumed는 보관 슬롯을 점유하지 않는다. 화면은 사용 가능한 하단 공간에 5열×4행으로 새 구슬을 배치하고 표시 반지름·라벨을 조정한다.
- T06의 실제 Host Rigidbody/SphereCollider 비행과 고정 BoxCollider 피격을 재사용한다. 실제 유효 피격의 공격자에게만 Stamina 보너스 5를 한 번 적용한다. 시간 회복과 피격 보너스는 별도 원인이다. 다른 사람의 공격이나 빗나감·만료·중복 알림은 추가 피격 보너스를 만들지 않는다.
- 최대값을 초과하는 회복분은 버린다. 자원 부족·보관 상한·권한·상태·순서·중복 검증에서 거절된 요청은 생성 비용을 차감하거나 구슬·성공 생성 순번을 추가하지 않는다. 다만 Host의 정상 시간 경과에 따른 자동 회복은 계속될 수 있다.
- Generate 버튼은 초기 구슬이 없어도 보이며, Host 확인 대기·자원 부족·보관 상한·비 Playing 상태에 맞춰 비활성화된다. 개인 수치·연속 게이지·회복 속도·보관 수·거절 이유를 표시한다. 잦은 회복 snapshot이 마지막 실패 설명을 지우지 않는다.

## 일반 모드와 개발 Fixture

일반 HOST/JOIN과 `RESET EMPTY`는 모두 빈 구슬 보관함과 Stamina 100으로 시작한다. 일반 생성에 무료 공급이나 첫 Raw 5개 묶음을 섞지 않는다.

`DEBUG FIXTURE`는 Host가 명시적으로 선택하는 별도 새 라운드다. 화면·snapshot·로그에 `DEBUG_TEST_MODE`를 표시하고 P1에게 Raw Yin 5개, P2에게 Raw Yang 5개를 비용 없이 공급한다. 이 Fixture는 일반 Seed 결과나 유료 생성 결과가 아니다.

`DEV HIT ORB`는 Debug 모드에서만 사용할 수 있는 별도의 Combined 1개 공급 요청이다. 아직 T08의 실제 조합이 없으므로, T06 실제 비행·충돌과 T07의 피격 보너스 연결을 시험하기 위해 둔다. 자동 공급이나 조합 성공으로 기록하지 않는다. 일반 `RESET EMPTY`를 누르면 Debug 모드와 구슬·자원·이전 요청을 새 라운드로 초기화한다.

## 최종 목표와 고정 규칙

같은 로컬 Wi-Fi의 실제 iPhone 두 대에서 방 생성·발견·참가 → P1/P2·좌우 확인 → Ready/Host Start → 빈 구슬 보관함과 가득 찬 개인 게이지 → 개별 생성·전달·음양 조합 → Attack Zone → 실제 3D 피격 → 개인 회복·동일 승패·Reset을 검증한다. G2에서 승인된 iPhone 17+iPad 대체 결과는 그 승인 범위에 한정한다.

- 참가자는 P1 Host와 P2 Client 두 명이며 세로 Touch·Safe Area·같은 기본 몬스터 구도를 사용한다.
- 같은 소유자의 사용 가능한 Raw Yin+Yang만 조합한다. 전달·발사는 같은 OrbId를 유지하고, 조합은 재료 두 개 종료 후 새 ID 하나를 만든다. 실제 조합은 다음 T08의 범위다.
- Combined의 Attack Zone 최초 진입에서 발사를 요청한다. Raw 공격은 거절하고 보존한다. 승인 후 2D 뷰 제거와 논리 구슬의 최종 Consumed를 구분한다.
- 시간·피해·자원·승패·Reset은 Host가 확정한다. 이탈은 별도 NetworkError이며 자동 재접속·Host Migration은 구현하지 않는다.
- 3인 이상·오행·약점·몬스터 공격·실제 방어·온라인 서비스·정식 아트는 범위 밖이다. 방어는 false 변수만 유지한다.
