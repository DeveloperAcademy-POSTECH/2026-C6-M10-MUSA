# 팝업북 스토리 제작

## 현재 구현 범위

`Hapio > Story > Open Story Preview`를 열고 Play를 누른다. 움직이는 구름의 합이오 타이틀을 누르면 첫 사찰 컷이 시작되고, 사찰이 아래 모서리를 기준으로 펼쳐진 뒤 대사가 표시된다. 자동 진행, 이전, 다음, 건너뛰기, 다시 보기를 사용할 수 있다. 이전은 바로 앞 컷의 첫 대사로 돌아가며 자동 진행을 끈다. 첫 컷과 재생 종료 상태에서는 비활성화된다. 등장 중 다음을 누르면 해당 컷의 등장을 먼저 마친다. 마지막 컷은 화면에 유지하고 종료 알림은 한 번만 보낸다.

- 기준 좌표는 Figma와 같은 **402×874**다. 페이지 전체를 화면 안에 비율 유지해 표시하며, 제어 버튼은 안전 영역 안에 둔다.
- **피그마 번호 1~24번 전 컷**을 실제 그림으로 연결했다. 기본 미리보기는 `BatchPreview.asset`의 **1 → 2 → … → 24번, 총 24컷**이다. `OpeningPreview.asset`의 첫 두 컷과 `FirstCutPreview.asset`의 첫 컷 목록도 보존한다.
- `Opening.asset`에는 **24개의 작업 슬롯**을 준비했다. 모든 슬롯에 현재 피그마 그림을 연결했다. 컷별 상세 연출과 최종 원고 완성을 의미하지 않는다. 최종 순서는 확정 스토리보드에 맞춰 목록에서 조정한다.
- 현재 연출은 레이어별 등장 지연·시간·아래에서 펼치기·이동·잔잔한 왕복 움직임을 지원하는 가벼운 프리셋이다. Unity Timeline 패키지나 실제 책장 변형은 아직 추가하지 않았다.
- Home/전투/스테이지 결과와의 자동 연결 및 멀티플레이 스토리 동기화는 아직 구현하지 않았다. 기존 씬·빌드 목록·GameSession·LabConfig는 수정하지 않았다.

## 그림과 연출 수정

### 텍스트만 작업하기 / 한 컷에 여러 대사 넣기

Play를 종료한 뒤 **Hapio > Story > Edit Opening Text**를 선택하면 첫 컷의 텍스트 설정이 Inspector에 열린다. 다른 컷은 Project의 `Assets/Hapio/Story/Opening/Cuts`에서 `OP_002.asset` 등 해당 파일을 선택한다. 같은 이름의 `.prefab`은 그림 편집용이며 텍스트는 `.asset`에서 작성한다.

Inspector의 **대사 페이지** 목록을 펼쳐 `+`로 페이지를 추가한다. 각 항목에 화자·대사·자동 진행 대기 시간(초)·음성을 입력한다. 목록 순서를 바꾸면 표시 순서도 바뀐다. 줄바꿈은 같은 페이지 안의 줄바꿈이고, 새 페이지는 목록 항목을 추가해서 만든다. Unity 목록에서 항목을 복제해 추가한 경우 기존 글과 음성도 복제될 수 있으므로 새 내용으로 바꾼다.

예를 들어 그림 1개에 페이지를 3개 넣으면 `그림 등장 → 대사 1 → 대사 2 → 대사 3 → 다음 그림` 순서다. 대사만 넘길 때 그림의 등장 애니메이션을 다시 실행하지 않고 잔잔한 움직임은 이어간다. 자동 진행은 페이지마다 읽기 시간을 새로 계산하고 해당 페이지의 음성이 끝나기를 기다린다. 미리보기 상단의 다중 페이지 표기는 `현재 컷/전체 컷 · 현재 대사/해당 컷 대사 수`다.

기존 한 페이지 데이터는 페이지 목록으로 옮겼다. 이전 형식의 별도 컷 에셋은 목록이 비어 있으면 기존 대사로 재생하며 Inspector의 **기존 대사를 첫 페이지로 가져오기**로 변환할 수 있다. Play 중 ScriptableObject 에셋을 수정하면 편집이 디스크에 남을 수 있으므로 원고 작업은 Play 종료 후 진행한다.

1. 해당 컷 프리팹을 연다.
2. `… Placement`에서 최종 위치·크기를 조정한다. 자식 `Motion`의 `StoryLayer`에서 Delay, Enter Seconds, Enter Offset, Start Height를 조정한다. Idle Amplitude가 0이면 왕복 움직임이 없다.
3. 그 아래 `Artwork`의 Image > Source Image에 그림을 넣는다. 그림과 배치·움직임이 분리되어 있어 그림만 교체할 수 있다. 빈 Source Image는 재생 시 표시하지 않는다.
4. 같은 그림의 수정본은 PNG를 같은 경로로 덮어쓰고 `.meta`를 유지한다. PNG의 크기·여백을 바꾸면 최종 배치를 다시 확인한다. 임의로 Set Native Size를 누르면 피그마의 표시 크기가 달라질 수 있다.
5. 컷 데이터의 대사 페이지 목록에서 대사와 음성을 편집한다. 음성은 해당 페이지가 나타날 때 시작하며 자동 진행은 읽기 시간과 음성 종료를 모두 기다린다.
6. 미리보기 씬의 Story Player > Sequence에 확인할 이야기 목록을 넣는다. 전체 오프닝 확인은 `Opening.asset` 또는 기본 `BatchPreview.asset`을 사용한다. 두 목록 모두 1~24번을 포함한다.

`Create Missing Story Workspace`는 없는 파일만 만든다. 기존 컷 프리팹·대사·목록·미리보기 씬을 재생성하지 않는다. 기존 Sprite 가져오기 설정도 유지한다. 그림 수정이 피그마에서 자동 동기화되는 기능은 아니다.

대사 종이는 공통으로 사용한다. 컷 프리팹의 Story Cut View에서 Override Dialogue Layout을 켜면 그 컷의 Dialogue Rect, Speaker Rect, Speaker Badge와 Badge Rect, Speaker Color를 조정할 수 있다. 사찰 컷은 기존 공통 배치를 쓰고 두 번째 컷은 피그마의 대사 배치와 이름표를 사용한다. 페이지 전환 효과는 다음 작업 범위다. 프리팹 레이어의 형제 순서는 뒤→앞이다.

## 피그마 번호 6~24번 기본 구현

피그마의 바깥 프레임 이름 `6`~`24`를 컷 번호로 사용한다. 내부에 중첩된 프레임 이름이나 화면 좌우 순서를 번호로 해석하지 않는다. 각 `OP_006`~`OP_024`의 프리팹에 Source Figma Number/Node Id를 기록했다. 원본 노드·소스 이미지 키·배치·회전·불투명도·자르기 정보는 `Opening/ImportedFrames.json`에 보관한다. 임시 다운로드 URL은 보관하지 않는다.

- 배경·인물·소품은 원본 개별 PNG를 사용하고, 작은 벡터 장식은 원본에서 투명 PNG로 내보냈다. 화면 캡처 한 장을 그림 레이어로 사용하지 않는다.
- **Placement**는 최종 배치, **Motion**의 Story Layer는 등장 지연/시간/펼쳐지는 높이, 그 아래 원본 이름/노드 ID의 프레임은 회전·자르기 창, **Artwork**의 Source Image는 이미지 교체용이다. 자르기 창의 Rect Mask 2D는 유지한다. 구슬 그림은 한 이미지의 일부를 창으로 잘라 보여주는 원본 방식을 보존했다.
- 이어지는 작은 벡터 장식은 Ink Details의 같은 Motion 아래에 묶었다. 개별 장식의 위치와 이미지는 각각 편집할 수 있다.
- 현재 등장은 짧은 페이드와 작은 아래쪽 펼치기만 적용했다. 바람·회전 마법·호리병 파열·연기의 연속 동작·구슬 이동 등 컷별 상세 연출은 추후 작업이다.
- 15·17·18·19·20·21번은 현재 피그마의 화자/대사와 배치를 가져왔다. 다른 컷은 대사 페이지가 비어 있고 종이 대사창도 숨긴다. Cuts의 해당 `.asset`에 화자 또는 글을 쓰면 같은 공통 대사창을 표시하며 여러 대사 페이지도 추가할 수 있다. `Story Cut View > Hide Empty Dialogue`를 끄면 빈 종이도 표시할 수 있다.
- 85% 배경의 밝기를 피그마와 맞추기 위해 전용 Paper Background 재질을 사용한다. 선형 색 공간에서 흰 종이 위 sRGB 혼합을 재현하며 원본 이미지·Color의 알파 값은 유지한다. 이 재질은 불투명한 종이 배경용이다. 투명 인물 그림에 재사용하지 않는다.
- 새 `Import Prepared Figma Cuts 6-24` 메뉴는 준비된 로컬 원본으로 빈 프리팹만 채운다. 이미 그림을 연결한 프리팹과 대사 원고는 다시 실행해도 덮어쓰지 않는다. 피그마 수정본을 다시 가져오는 자동 동기화 버튼이 아니다. 수정 반영 시 컷 번호와 이미지 교체만 할지/배치도 바꿀지를 명시한다.

첫 1·2번의 컷 데이터, 프리팹, 메타 파일은 이번 일괄 작업 전후 해시가 같다. 기본 미리보기의 순서 목록만 새 BatchPreview로 연결했다. 당시 전체 Opening 목록에는 빈 3~5번이 유지되었으며, 아래 후속 작업에서 그림을 연결했다.

## 남은 3~5번 및 22번 수정 반영

- `OP_003`: 스승과 수장고 배경을 원본 두 이미지로 분리했다. 원본의 19pt 글자, 대사 영역 (76,751,283,23), 스승님 이름표와 “특히 안쪽 선반은 절대로 건드리지 말고.”를 연결했다.

- `OP_005`: 작별 장면의 이미지 레이어를 연결했다. 이후 추가된 구름 탄 스승 그림까지 현재 9개 레이어다. 건물의 자르기 창과 각각의 인물, 구름 위 스승 그림을 유지한다. 현재 원본에 대사는 없어서 대사창은 숨긴다.
- `OP_022`: 인물과 벡터 장식 이동, 호리병 축소/이동, 바닥 구슬의 새 위치·크기·자르기를 반영했다. 인물 최종 위치는 (-16,218), 호리병은 (143,549), 크기 123×129다. 기존 Motion의 지연·시간·펼침 높이·이동·왕복 설정을 보존했다. 다른 20컷의 데이터/프리팹/메타는 변경하지 않았다.

## 간결한 대사와 움직이는 타이틀

현재 원고는 사용자가 수정한 **24컷·26페이지 대본**이다. 8번은 금옥이→불이, 17번은 불이→금옥이 두 페이지이며, 13·14번은 대사창 없이 재생한다. 1·5번 내레이션에는 이름표를 표시하지 않는다. 사부님·불이·만복이·금옥이·묵이·솔이 표기를 사용한다. `Opening/ApprovedScript.json`에 전달받은 원고를 보관하며 실제 편집은 계속 각 `Cuts/OP_번호.asset`의 대사 페이지에서 한다. 예전 `DialogueDraft.json`은 초기 15컷 초안 기록이다. 자동 가져오기/씬 로드 시 원고를 덮어쓰는 기능은 없다.

이름표는 가운데 정렬이며 세 글자 이름도 같은 종이 이름표 안에 들어간다. 본문은 직접 조정한 1번을 기준으로 모든 컷에 (84,720,270,100) 영역을 적용했다. 중앙 정렬을 유지하면서 이름표와 간격을 두도록 이전보다 5px 내렸다. Unity에서 각 View의 Dialogue Rect로 수정할 수 있으며, 대본 재적용은 이미 설정한 본문 영역을 유지한다. 원고의 줄바꿈을 유지하되 긴 19번은 실제 글꼴 폭에 맞춰 약 18pt로 조정했다. 24번의 한 문단은 영역 폭에 맞춰 자동 줄바꿈한다. 17번 두 번째 페이지 “되겠냐.”는 자동 모드에서 1.3초 후 다음 컷으로 진행하며 수동 모드에서는 다음 입력을 기다린다.

- `Hapio > Story > Create Animated Title`은 없는 타이틀과 연결만 만들며 이미 만든 타이틀의 배치/움직임을 덮어쓰지 않는다.

## 스테이지 사이 이야기 확장

Project의 Create > Hapio > Story > Sequence/Cut으로 이야기를 추가한다. 순서와 무관한 고유 ID를 유지하고 컷 프리팹을 연결한다. `StoryPlayer.Play(sequence)`로 재생하고 `Finished(Completed/Skipped)` 또는 Inspector의 종료 이벤트를 받아 호출자가 진행을 이어간다. `Cancel()`이나 비활성화는 완료 알림을 보내지 않고 화면·음성을 정리한다.

멀티플레이의 결과 준비/진행 예약을 각 기기의 로컬 대사 완료로 우회하지 않는다. 실제 GameSession 연결 전에 Host 진행 권한, 전원 읽기 완료/스킵 정책, 이탈 처리와 이전 스테이지 알림 차단을 설계해야 한다. 이번 작업은 해당 네트워크 규약을 변경하지 않는다.

현재 데이터는 프리팹을 직접 참조한다. 고해상도 그림이 채워진 전체 오프닝의 메모리는 아직 측정하지 않았다. 실제 기기와 최종 해상도가 정해지면 필요한 컷만 로드하는 구조와 압축을 검증한다. 미리보기의 원본 이미지는 비압축이며 최종 모바일 최적화 설정이 아니다.
