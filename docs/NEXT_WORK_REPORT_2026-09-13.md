## 2. 가장 먼저 할 작업: T12 최종 판정

앞서 언급한 ‘T12 최종 판정’은 현재까지 쌓인 검증을 마감하는 작업이다. 산출물은 **검사 항목별 증거표, 적용한 기준 차이, 남은 문제, T13 진입 가능 여부를 한곳에 모은 결론**이다.

현재 보류 사유는 다음과 같다.

- **빌드별 증거 차이:** 100회 전달은 빌드18의 실행 근거다. 이를 빌드19에서 실행한 것으로 기록할 수 없다.
- **기기 범위 차이:** 사용자가 승인한 iPhone+iPad 결과와 원문의 ‘서로 다른 실제 iPhone’ 요구를 구분해야 한다. 이번 프로토타입의 완료 범위에 이를 어떻게 반영할지 명시해야 한다.
- **세부 미실행 항목:** 매우 짧은 외곽 드래그 조건은 코드 검사와 일반 손 조작 결과가 있지만, 그 짧은 거리 자체를 실기기에서 확인한 것은 아니다. 최신 기록대로 별도의 필수 수동 시험을 추가하지 않는다.

권고는 **기존 실행 증거와 변경 영향 분석을 활용해 이번 프로토타입의 완료 범위와 예외를 명확히 정리하는 것**이다. 이미 확인한 조작이나 100회 전달을 다시 사용자에게 요청하는 계획은 잡지 않는다. 원문 기준을 그대로 적용하면 미실행 항목과 G5 보류 상태가 남는다. 진행 기준을 조정하는 경우에도 기존 NOT_RUN 사실은 보존해야 한다. 이 보고서 자체가 기준 변경이나 G5 통과를 확정하지는 않는다.

T13의 명시된 시작 조건은 T12 및 G5 완료다. 따라서 이 정리가 먼저 필요하다.

## 3. 정식으로 남은 Task

| 순서 | 작업 목적과 주요 내용 | 완료 시 남길 결과 | 사용자 참여 |
|---|---|---|---|
| **T13 · 앱 중단·연결 실패** | Host 또는 Client의 홈 이동·잠금·앱 종료·네트워크 단절·시간 초과 처리. 중단 사유를 표시하고 추가 입력·생성·피해를 멈춘다. 수동으로 새 방에 연결할 때 이전 요청·구슬·연결 상태가 남지 않게 한다. | 상황별 재현 기록, 양쪽 종료 상태, 새 연결 후 초기화 근거 | 제가 가능한 기기 조작부터 수행한다. 잠금 해제·권한 설정처럼 도구로 할 수 없는 실제 기기 조작만 필요할 수 있다. |
| **T14 · 무결성·진단·자동 시험** | 동시·중복·이전 라운드 요청, 소유권, 구슬 ID 보존, 조합 재료 소멸, 피해·회복의 1회 적용, Reset 잔류를 검사한다. 기존 로그와 시험을 요구사항에 연결하고 누락을 보완한다. | 요구사항과 연결된 자동 검사 결과, 오류 재현 로그, 개발 도구의 적용 범위 | 대부분 제가 진행할 수 있다. 기존 996개 검사와 진단 도구를 활용한다. |
| **T15 · 반복·성능·화면 QA** | 장시간 유지·반복 시작·동시 조작·보관 상한·다수 투사체를 확인한다. 프레임 시간, 메모리, GC, 입력 지연과 화면 가림을 가능한 도구로 측정한다. | `docs/DEVICE_QA.md`: 기기·빌드별 실측값, 실행/미실행, 병목과 필요한 수정 | 자동 수집을 우선한다. 직접적인 조작감·발열 체감은 사람이 관찰한 범위만 기록한다. |
| **T16 · 협동 관찰·최종 보고** | 두 사람이 전달을 요청하고 조합·공격을 나누는지, 대기·혼동·역할 쏠림이 생기는지 관찰한다. 기술적 동작과 협동 경험을 구분해 다음 개발 방향을 판단한다. | `docs/PLAYTEST.md`, `docs/PROTOTYPE_REPORT.md`: 관찰 결과, 남은 문제, 진행·보완·규칙 재검토 권고 | 협동 경험을 평가하려면 실제 사람의 플레이 관찰이 필요하다. 관찰하지 않으면 미실시로 기록한 최종 보고도 가능하다. |

작업은 T13 → T14 → T15 → T16 순서이며 한 Task씩 진행한다. T16은 T15의 실행·미실행 기록을 바탕으로 보고할 수 있지만, 미검증 항목을 전체 PASS로 바꾸지는 않는다.

## 4. 기존 작업을 활용할 부분과 원문 요구

**T13:** 상태바·제어 센터를 열어도 연결과 시간이 유지되는 수정은 빌드18에서 이미 확인했다. 이 동작을 유지하면서 실제 백그라운드 이동·강제 종료·네트워크 끊김을 별도로 다룬다. 자동 재접속이나 Host 교체는 현재 정책에 포함되지 않는다.

**T14:** 이미 구슬·요청 ID 추적, 상태 비교, 자동 검사, 기기 진단 수집기가 있다. 기존 도구를 먼저 점검하고 필요한 부분만 보완한다. 일반 플레이와 디버그 주입 결과는 계속 분리한다.

**T15:** 원문에는 실제 **180초 시험 5회**와 서로 다른 화면 크기의 **iPhone 2종**이 명시돼 있다. 이는 앞으로 계획된 성능·반복 검증이며, 짧은 승리 5회로 대체할 수 없다. 현재 iPhone+iPad로 측정 가능한 범위와 원문 기기 조건의 차이를 기록해야 한다. 60fps는 목표이며 아직 성능 실측 통과 결과가 아니다. 횟수와 기기 조건을 변경하려면 변경 근거를 명시해야 한다.

**T16:** 지금까지의 ‘잘 작동한다’는 확인은 조작 검증에 활용한다. 자동으로 전달·조합·공격한 횟수만으로 협동의 재미를 판정하지 않는다.

## 5. 현재 일정에 포함되지 않은 확장

몬스터 공격 패턴·AI, 실제 방어, 추가 조합·스테이지, 3인 이상 플레이, 정식 아트·음악, 온라인 매칭과 스토어 배포는 T13~T16의 범위 밖이다. 이번 프로토타입을 평가한 뒤 별도 개발 계획으로 선정할 항목이다.
