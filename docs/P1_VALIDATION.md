## 어떤 물리 동작을 검사했는가

새 PlayMode18개는 실제 2D 물리 장면에서 벽·구슬 충돌, 감속 후 정지, 속도 상한, 오래 잡은 뒤 놓기, 취소·재잡기, 자연 접촉의 게임 요청0건, 직접 Yin/Yang 조합, 같은 음양 거부, 두 재료 승인 대기, 상태 수신 중 관성 보존, 종료·Retry 정리를 확인한다. 저장 씬/Prefab 검사7개와 새 iOS 씬의 기존 중단 패치 적용 범위 검사1개를 더했다.

자동 통합은 명시적 개발 Fixture와 실제 NGO 연결을 사용한다. 짧은 전투 종료는 **2초 Fixture**이며 180초 일반판 실기기 검증이 아니다. Mac 두 앱은 일반 Seed로 각1개씩 비용20을 지불해 생성했다. 이후 조합·표적 피격을 위해 Host에 Yin/Yang 재료2개를 명시적으로 주입했으며 이를 정상 생성 결과와 분리했다. 손떼기 3D 투척은 아직 없고 현재 고정 방향의 실제 Rigidbody 피격만 확인했다.

## 실패와 수정 기록

1. 첫 Prepare는 batchmode의 임시 빈 씬에서 Additive 새 씬 생성을 거부했다. batchmode만 Single 생성으로 바꾸고 다시 실행해 성공했다. 대화형 Editor는 기존 씬을 보존하는 Additive 경로를 유지한다.
2. 첫 EditMode는 956개 중1개 실패했다. Prefab 자산의 비활성 계층에서 기본 GetComponentInParent가 null을 반환한 검사 문제였다. 비활성 계층 포함 검색으로 수정 후956개 전부 통과했다.
3. 첫 새 PlayMode18개 중2개 실패했다. 하나는 보간 표시 위치와 물리 본체 위치의 차이로 움직이는 구슬 재잡기가 실패한 실제 입력 문제였다. 화면에 보이는 원을 기준으로 선택하고 잡는 위치를 맞춰 수정했다. 다른 하나는 보간 이동을 단1프레임만 기다린 검사였다. 제한 시간 안에 실제 표시 이동을 기다리도록 고쳤다. 새18개와 전체107개를 다시 실행해 통과했다.

첫 실패 결과와 수정 후 결과는 [원본 비공개 자료: 근거 목록 — 공개 요약](VALIDATION_SUMMARY.md)에 함께 보존한다.

## 보존·제한과 사람이 확인할 내용

- 원본 Editor가 열린 데스크탑 프로젝트에 중복 batchmode를 실행하지 않았다. `/private/tmp/C6_Prototype_NextPhase_P1`의 별도 Git worktree에서 검사했다. Unity CLI는 설치돼 있지만 연결용 Pipeline 패키지가 없어 Editor 원격 상태를 제공하지 못했다. 패키지를 추가하지 않고 기본 batch 실행을 사용했다.
- 과거 씬·`.meta`·빌드 안내·검증 기록은 보존했다. 이관은 변경 파일의 원본 해시를 확인한 뒤 명시한 파일만 수행한다. Unity가 검사용 작업 폴더의 두 URP 설정을 자동 재직렬화한 변경은 이번 이관에서 제외한다.
- Mac 560×746 구도에서 기존 TEAM HP 문구와 몬스터 머리가 일부 겹치는 점을 관찰했다. P1 기능 실행은 확인했으나 모든 비율의 최종 화면 QA는 아니다. P2의 카메라·목표 표시 범위 조정에 반영한다.
- 기기 설치가 준비되면 실제 iPhone/iPad에서 구슬을 밀고 다시 잡는 느낌, 마찰·반발 세기, 직접 조합을 짧게 확인해야 한다. 현재 실기기 결과를 과거 빌드에서 승계하지 않는다.
- 후속 구현 하나는 **P2: 기준 몬스터를 대상으로 손떼기의 방향·세기를 적용하는 3D 투척**이다. P1의 기기 조작감 확인과 함께 미확정 튜닝을 반영한 뒤 진행한다. 최대5인 통합은 그다음 P3다.
