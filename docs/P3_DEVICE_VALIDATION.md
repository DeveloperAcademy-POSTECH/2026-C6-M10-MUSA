# P3 빌드23 · iPhone·iPad·Mac 3인 실기기 확인

2026-09-14 사용자의 “실기기 연결해뒀으니 빌드하고 다음 작업 진행해” 요청에 따라 진행했다. 게임 소스는 로컬 커밋 `0795ae5` 그대로이며, 기존 P3 Unity 출력과 현재 소스 해시를 확인한 뒤 Xcode에서 다시 빌드·개인 Team으로 서명했다. Unity 재출력·게임 코드 변경·자동 테스트 재실행은 하지 않았다.

기기는 모두 사용자가 지정한 기존 기기를 사용했다. iPhone은 iOS26.6.2, iPad는 iPadOS26.2.1이며 유선 개발 연결·개발자 모드가 확인됐다. 게임 통신은 같은 로컬 네트워크에서 실행했고, iOS 설치용 케이블 연결을 게임 통신 방식으로 기록하지 않는다. Mac은 같은 빌드23의 일반 실행본으로 참가했고, P3 자동 주입 도구는 켜지 않았다.

## 실제 조작 수와 흐름

| 실제 실행 | 수량·방향 |
|---|---|
| 비용을 낸 Generate | iPhone5회 + iPad5회 = Raw10개. 최초 안내3회씩 이후 각2회 추가 생성 |
| Raw 전달 | iPhone→Mac 왼쪽1회, iPhone→iPad 오른쪽2회 |
| iPad 직접 조합 | 2회, 각 재료2개의 종료와 새 Combined ID |
| iPad 정상 손떼기 발사 | 2회 |
| 첫 번째 발사 | 빗나감, 약4.02초 뒤 만료. HP100 유지 |
| 두 번째 발사 | 실제 충돌1회, HP100→80 |
| 명중 회복 | iPad100→100, added0. 실제 +5 증가를 확인한 것으로 세지 않음 |

Host는 iPhone의 실제 네트워크 ID0, iPad는1, Mac은2였다. 화면 번호 P1/P2/P3와 네트워크 ID는 서로 다른 표기다. 전투 명단의 원형 이웃은 P1: LEFT P3/RIGHT P2, P2: LEFT P1/RIGHT P3, P3: LEFT P2/RIGHT P1이었다.

Mac에서 받은 Raw를 추가 전달하려던 자동 마우스 도구가 `noWindowsAvailable` 오류를 반환했다. 해당 게임 요청은 발생하지 않았으므로 Mac 발신 전달은 이번 실행의 성공 수에 포함하지 않는다. 게임 오류로 단정하지 않으며, iPhone의 실제 좌우 전달과 기존 Mac2/3/4/5인 자동 전달 검증은 구분해 유지한다.

## 아직 확대하지 않는 범위

- 이번 확인은 **실기기2대와 Mac1대**다. 실기기3대·4대·5대 검사나 성능 측정이 아니다.
- 전체 구간의 모든 게임 상태 해시를 세 실행본에서 비교하지 않았다. 같은 해시가 확인된 것은 Host에 도착한 **초기 두 Client ACK**다. 이후 공통 HP와 결과는 로그·화면·사람 확인 범위다.
- 이번 빌드의 실제 Victory·Retry, 모든 좌석의 모든 방향 전달, 모든 화면 크기의 Safe Area, FPS·마찰·반발 계수 측정은 NOT_RUN이다.
- 명중 당시 스태미나가 최대였으므로 실제+5 상승은 NOT_RUN이다. 이전 Mac 자동 검증의 공격자+5 결과는 별도 기록으로 보존한다.
- 기존 T14~T16 또는 미완료 원문 Gate를 재개하거나 PASS로 바꾸지 않는다. GitHub 업로드는 하지 않았다.

요청한 세 기능의 구현에 이어, 새 통합판의 기본 실기기 조작까지 확인했다. 후속 후보는 사용자가 원하는 감도로 마찰·반발·투척 수치를 조절하는 일이다. 추가 기능이나 반복 검증은 자동 시작하지 않는다.
