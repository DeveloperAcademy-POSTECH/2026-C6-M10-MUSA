# 박 클레이 스티커 표현 (#506)

## 적용 범위

기준 작업은 #466의 미커밋 수채·종이 스티커와 곡면 에셋 비교 시제품이다. `feat/#506-gourd-clay-stickers`에서 이를 보존하고, 사용자가 선택한 에셋 원형 부착과 [이슈 #506](https://github.com/DeveloperAcademy-POSTECH/2026-C6-M10-MUSA/issues/506)의 클레이·충돌 농도·DEV 조절을 적용한다.

박 바탕의 원본 텍스처를 다시 칠하지 않는다. 원래 박 메시를 공유하는 자식 `Clay Sticker Overlay`가 별도 색·높이 지도를 표시한다. 최신 main의 스테이지별 `LabGourdVisualRig`에서는 몸통과 `paintExtras`의 뚜껑 각각에 같은 방식의 층을 붙이며, 원래 메시·아트 바탕·애니메이션 부모·판정 껍데기·줄 연결은 유지한다. 명중마다 GameObject나 메시를 생성하지 않는다. 이전 한지·수채·종이 모드는 표현 프로필의 비교 경로로 유지한다. Scene·Prefab 배치와 원본 에셋은 그대로다.

## 현재 표현

이번 PR은 미커밋 상태였던 #466 기반도 함께 포함한다. 원격 main의 구형 Splatter와 비교하면 새 판정 외곽의 실제 셀 위치와 색/P 해시는 달라진다. 도색 예산·성장량 계산·소유권·승패 규칙의 보존과 구분한다.

- 원본 세 얼룩 `BroadPaper / LongPaper / ClusterPaper`의 Alpha를 베이크한 `BroadData / LongData / ClusterData`를 사용한다. 내부 한지 입자는 사용하지 않고 둥근 가장자리·부드러운 클레이 재질로 표시한다.
- 데이터는 512², 채널은 R/A 커버리지·G 안쪽 거리·B 둥근 높이다. 원본과 데이터 팩을 분리하고 SHA-256 버전을 라운드에 고정한다. 빌드 검사는 읽기 전용이며 자동 재베이크하지 않는다.
- 새 명중은 확정된 도장 프레임, 추가 성장은 실제 새 지급 셀의 군집 중심을 따라 원본 얼룩을 덧붙인다. 도장 종류·방향은 기록·seed로 고정하며 게임 난수는 사용하지 않는다.
- 색·높이 지도는 기록 순서대로 누적한다. 클레이는 불투명하며 낮은 충돌 강도도 투명도를 낮추지 않는다. 겹침 높이는 제한되어 오래된 자국을 지우지 않고도 두께가 무한히 커지는 것을 막는다.
- 기존 P번호 무늬 ON/OFF를 유지하며 플레이어 판정 지도를 시각 도장 ID로 덮어쓰지 않는다.

### 실제 도색 영역과 시각 실루엣

둥근 에셋 원형과 기존 계산 셀 윤곽은 완전히 같지 않다. 표현에는 **2셀의 고정된 시각 여유**를 허용하며 이 여유는 면적·점수에 포함하지 않는다. 셀이 실제로 바뀔 때 표시용 이웃 참조 수를 갱신해 2셀 이내를 빠짐없이 채우며, 2셀 간격으로 건너뛰어 검사할 때 생기는 격자 틈을 피한다. 여유보다 멀리 뻗은 원본 끝은 계산 영역에 의해 잘릴 수 있으므로 원본 Alpha 전체 보존을 보장하지 않는다. 판정 지도·면적·성장량·건조·승패는 기존 Host 규칙을 유지한다. 도색 100%는 실제 마지막 셀까지 칠해져야 하며, 그 시점에는 같은 클레이의 얇은 바탕층으로 남은 표시 틈까지 채운다. 완료 전의 시각 실루엣을 계산용 면적으로 역산하지 않는다.

건조는 해당 위치의 누적 색·높이 전체를 지운다. 전체 셀이 마르면 시각 여유까지 비워 오래된 얼룩이 떠 있지 않게 하며, 재도색 시 삭제된 아래색을 복원하지 않는다.

## 스티커별 코팅 광택 (#524, v2)

현재 표현 버전은 `clay-stickers-v2`다. Gloss는 모든 스티커의 공통 강도이지만, 반짝임 방향은 각 도장의 완만한 돔형 면을 따른다. 도장마다 광택 값을 무작위로 만들지 않는다. 박 곡면을 따라 넓게 이어지던 하이라이트는 제거했다. 겹친 곳에서는 최상층 스티커의 조명용 법선을 사용하며, 기울기는 최대 25도다.

높이 Half 지도의 R은 기존 물리적 높이를 그대로 보존한다. G/B는 공통 표면 좌표계에서 조명용 기울기를 커버리지와 함께 인코딩하고, A는 실제 스티커 커버리지를 보존한다. 100% 완료 시 색 Alpha는 기존처럼 모두 채우지만 높이 A는 강제로 채우지 않는다. 따라서 완료용 얇은 바탕층은 무광이며, 법선을 부드럽게 읽더라도 바탕층으로 광택이 새지 않게 최종 광택 마스크는 원래 위치의 커버리지를 쓴다.

Gloss 0에서는 추가 반짝임이 0이며 기존 확산 음영·색·접촉 음영을 유지한다. 실제 두께와 조명용 법선은 별개이므로 두께/광택 슬라이더는 독립적이다. 색 지도·높이 R·도색 판정·소유권·건조·통신 메시지·렌더 타깃 수는 유지한다. 건조는 새 G/B/A까지 함께 지우고 기록 재생으로 복원한다. 전투·완성 관람·PNG·Mac 앱은 같은 표면 셰이더를 사용한다.

Editor의 `LabClayVisualStudy.ExportLocalGlossComparison(절대 출력 폴더)`로 최초/재타격3회/같은색·다른색 겹침과 Gloss 0/0.35/1, 5색 완성 6방향을 비교한다. `LabClayLegacyRuntimeReference`·`LabClayLegacySurfaceReference`는 최신 구현과 독립적으로 색/R·무광 출력 동일성을 검사하는 고정 v1 GPU 기준이며 Editor 폴더에만 있다. 일반 Player의 의존성이나 런타임 비교 모드는 아니다.

## 충돌 강도와 농도

실제 Host 접촉 지점의 법선과 충돌 직전 속도를 사용한다. `LabPaintImpact`가 법선 방향 속도를 0~20 m/s의 **초기 테스트 범위**로 정규화한다. 빗겨 맞은 접선 속도를 정면 충격으로 세지 않는다. 투척 입력·탄도·충돌·피해량·도색량은 변경하지 않는다.

강도는 `LabPaintVisualStamp.impact01`에 보관한다. 0은 이전 기록의 기본 강도 0.5, 1~255는 새 정규화 강도 0~1이다. 기존 44바이트 레이아웃의 예약 바이트를 사용하고 나머지 예약 바이트는 0을 요구한다. 기본 기록의 기존 바이트는 유지되지만 구형 앱과의 연결은 새 프로토콜로 거절한다.

농도는 `minimumDensity`부터 `maximumDensity`까지 보간하며, 기본값은 둘 다 1이다. 그래서 기본 게임은 충돌 강도와 관계없이 오행 칠 팔레트(`LabPaintPalette`, 구슬 그림에서 뽑은 색)를 그대로 칠한다. 이전 기본값 0.65는 같은 오행색을 선형 공간에서 흰 클레이(0.82)와 섞었는데, 실제 투척은 최대 12.5 m/s라 정규화 강도가 약 0.62를 넘지 않아 농도가 0.65~0.87에 머물렀다. 그 결과 화는 분홍, 토는 회색, 수는 흐린 하늘색으로 보였다(측정은 `docs/VALIDATION.md`). Raw·타격 횟수·투사체 크기·스태미나·실제 도색 예산과 관계없는 표현값이다. 농도 범위는 `WatercolorStampProfile.settings.claySticker` Inspector에서 조정한다. 충돌 강도는 계속 `impact01`에 기록되며, 범위를 1 아래로 내리면 이전처럼 약한 명중이 밝아진다. 농도 범위는 표현 버전 문자열(`LabWatercolorStampSettings.Version`)의 fingerprint에 들어간다. 그래서 값이 다른 빌드의 Guest는 Host의 도색 기록을 적용하지 않고 버전 불일치(`paintArtVersionMismatch`)로 처리한다.

## DEV 조절

| 설정 | 범위 | 기본값 | 공유 슬롯 |
|---|---|---|---|
| Clay Thickness | 0~0.02, 박 로컬 단위 | 0.006 | 257 |
| Clay Gloss | 0~1 | 0.25 | 258 |

기존 0~256 슬롯을 이동하지 않고 전체 259개로 확장했다. 두께와 광택은 독립적으로 조정한다. 원본 LabConfig 에셋에 무관한 기본값을 재저장하지 않으며 새 필드는 코드의 직렬화 기본값을 사용한다.

전투 중 방장이 일시정지 → DEV → Gourd에서 조정하면 재시작 없이 표시가 바뀐다. 미리보기는 원본 설정이나 승인된 게임 수치를 바꾸지 않는 라운드별 표현 상태다. `clay_appearance` 신뢰 전송은 현재 세션·라운드·설정 리비전/지문·증가하는 순번을 확인한다. 참가자가 보낸 값이나 이전 라운드 값은 적용하지 않는다. 실제 기기간 전송 검증과 직접 수신 계약 검사는 구분한다.

Hapio에서는 `GameSession`이 전투 DEV의 `ClayAppearanceChanged`를 구독해 Common 프로필의 이 두 값만 기억하고 다음 스테이지에도 유지한다. 다른 DEV 편집은 기존 APPLY 절차를 사용한다. Lab의 명시적인 APPLY & RESTART는 입력한 두 값을 새 세션 설정에 반영한다.

통신·예술 기록의 기존 4KiB 페이지·한 피어당 미확인 1페이지·게임 상태 우선·64MiB 기록·2MiB 페이지 캐시는 유지한다. 화면용 descriptor 캐시 128개를 넘으면 디스크에서 찾으며 옛 자국을 임의로 제거하지 않는다. 한 번의 갱신은 연산/그리기 예산으로 나누고 GPU 완료와 수신·적용을 따로 기록한다. 초기 준비에서는 원본 3종의 색·높이 합성 패스를 작은 전용 타깃에 미리 그린다. 실제 도색 지도와 순번은 건드리지 않으며, 기존 main의 도색·오디오 준비 경로도 유지한다.

당시 최신 main의 접속 묶음 **5688 / Lab49 / Game35 / 공유 설정259개**를 유지했다(현재는 Bulk 선택 ACK로 5690 / Lab51 / Game37, 설정 수는 같다). 이번 수정은 메시지 형식을 바꾸지 않으며, 도색 기록의 표현 버전은 v2로 확인한다. 참가자들은 같은 표현 버전의 앱을 사용한다.

## 완성 박 Mac 재질 실험 앱

### 처음 실행하기

1. Unity 6000.6.5f1에서 프로젝트를 열고 컴파일이 끝나면 Play를 중지한다. 미저장 Scene은 도구가 자동 저장하지 않는다.
2. 상단 `C6 Lab → Experiments → Clay Sticker → Prepare Mac Preview Scene`으로 v2 샘플을 준비한 뒤 `Build Mac Preview App`을 선택한다. 이미 v2로 준비됐다면 바로 빌드할 수 있다. 빌드 자체는 샘플을 자동 재생성하지 않는다.
3. 빌드가 끝나면 같은 메뉴의 `Open Last Mac Preview Build`로 폴더를 열고 `Hapio-Clay-Experiment.app`을 실행한다. 기존 빌드 파일을 받은 경우에는 앱 실행부터 시작한다.
4. 우측 슬라이더를 움직여 두께·광택을 조절한다. 숫자 표시는 현재 값이며, 박 위 드래그는 회전, 마우스 휠은 확대·축소다.
5. `Front / Right / Back / Left / Diagonal / Above`는 6방향 보기다. `Reset defaults`는 두께 **0.01**·광택 **0.35**·정면·기본 배율로 복원하고, `Quit`는 앱을 종료한다.

실험 앱은 확인한 `WhiteGourd` 모델과 고정 완성 도안의 재질 비교용이다. 현재 일반 게임의 스테이지별 박 모델을 선택하는 도구는 아니다.

실험 앱의 시작값은 앞서 확인한 완성 렌더 기준이다. 일반 게임 DEV의 기본 두께 0.006·광택 0.25와 구분하며, 앱에서 조절한 값은 일반 게임에 자동 적용되지 않는다. 실험 Scene을 Unity에서 직접 열어 Play할 수도 있으나 기존 게임의 Build Settings에는 추가하지 않는다.

### 샘플과 빌드 관리

결과는 `Builds/Experiments/ClayPreview/<생성시각>/Hapio-Clay-Experiment.app`에 저장된다. 실행하면 100% 완성된 5색 박이 바로 표시되므로 방 입장이나 직접 도색은 필요 없다. 앱을 다시 실행하면 시작값으로 돌아온다. 실험값을 실제 게임에 사용하려면 원하는 숫자를 확인한 뒤 게임 DEV에서 별도로 입력한다.

새 전용 Scene과 `Assets/Experiments/ClayPreview/Sample`의 색 PNG·높이 Half EXR를 직접 참조한다. 샘플은 기존 실제 도색 규칙과 seed 123으로 생성하며 1024×512 Linear 값을 유지한다. 현재 샘플은 67회 명중으로 32768/32768셀을 채운 결과다. 숫자 67을 고정된 완성 조건으로 사용하지 않는다. 샘플 생성과 임포트의 왕복 오차·해시·원본 보존 결과는 `SampleInfo.json`에 기록한다.

높이 EXR는 Default(RGBA Half·무압축·최대 1024)와 함께 iOS도 같은 값으로 명시 override한다. 이 프로젝트의 Editor는 보통 iOS가 활성인데, 그때 Default만 따르는 Half EXR는 가져올 때 RGBM으로 인코딩된다. RGB가 8비트 배율로 나뉘고 그 배율이 A의 커버리지 자리에 들어가므로, 높이 R·법선 GB·커버리지 A가 모두 저장한 값과 달라진다. `ClayPreviewBuild.ImportMap`이 이 override를 쓴다. 빌드·준비 검사의 `ValidateMap`과 PlayMode 검사는 iOS의 RGBA Half 형식과 최대 크기 1024 이상을 확인한다. 압축 항목은 형식을 직접 고르면 쓰이지 않으므로 확인하지 않는다. 둥근·코팅 비교의 높이 EXR 4개도 같은 경로를 쓴다. 색 PNG는 iOS에서도 그대로 들어오므로 override하지 않는다.

`Prepare Mac Preview Scene`과 `Rebake Completed Preview Sample`은 같은 seed·명중 순서로 현재 버전의 샘플을 명시적으로 재생성한다. 슬라이더 조작만으로는 무늬가 바뀌지 않는다. v1 EXR에는 새 법선/커버리지가 없으므로 그대로 사용하지 않는다. 준비 도구는 v2 메타데이터와 실험 Scene의 참조·해시만 갱신하며, 빌드 검사는 버전·색/높이 파일·물리 높이 R·Scene 연결을 읽기 전용으로 확인한다. 슬라이더는 기존 실제 `ClayStickerSurface` 셰이더의 두 수치만 바꾸며 도색을 다시 실행하지 않는다. 배경에 회전 이미지 한 장을 표시하는 방식이 아니라, 원본 박의 메시·로컬 변환을 유지한 렌더 전용 복사본을 표시한다. 물리·네트워크·게임 세션 컴포넌트는 복제하지 않는다.

카메라는 30fps 제한으로 동작하고 자동 회전하지 않는다. 앱이 포커스를 잃으면 카메라를 멈추며, 종료 시 소유한 재질·렌더 타깃·모델 복사본을 해제한다. 앱 내 UI는 실험 전용 UI Toolkit 패널이다. 일반 전투 HUD와 DEV의 두께·광택 설정은 변경하지 않는다.
