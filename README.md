## 우리 게임은

합이오는 친구들과 둥글게 둘러앉아, 내 화면의 구슬을 스와이프해 옆자리 친구에게 넘기고 요괴를 향해 던져 **제한 시간 안에 요괴를 봉인하는 협동 게임**입니다.

오랜 봉인이 약해져 요괴들이 깨어나기 시작한 지금, 견습 도사가 된 여러분은 오행 색의 구슬을 던져 박을 색칠해야 합니다.

꽹과리 장단이 울려 퍼지는 가운데, **여러분은 과연 힘을 합쳐 한국 설화 속 요괴들을 봉인할 수 있을까요?**

## 핵심 경험

### Aesthetic · 왁자지껄한 분위기

친구들과 둘러앉아 "이거 빨리 넘겨줘!", "누가 이 구슬 필요해?"를 외치며 플레이하는 왁자지껄한 분위기를 지향합니다. 각자 조용히 플레이하기보다, 대화와 반응이 자연스럽게 터져 나오는 파티 게임 경험을 만듭니다.

### Main Mechanic · 하나의 전장, 여러 개의 화면

플레이어들은 하나의 360도 전장을 각자의 휴대폰 화면으로 나누어 바라봅니다. 좌우 스와이프로 구슬을 주고받고, 필요한 구슬을 조합한 뒤 3D 전장의 요괴를 향해 직접 던집니다.

### Art · 친근하게 풀어낸 한국 설화

한국 설화 속 요괴와 음양오행을 중심으로 합이오만의 세계관을 만들었습니다. 전통 소재를 그대로 재현하기보다, 밝고 유쾌한 파티 게임 분위기에 맞게 친근하고 개성 있는 비주얼로 풀어냅니다.

### Music · 우리 장단의 흥

한국 전통 장단을 활용한 배경 음악과 전통 악기 기반의 효과음으로 게임의 리듬감을 살립니다. 여기에 명인의 추임새를 더해, 공격과 성공의 순간마다 한국적인 흥을 살립니다.

## Our Story

"오늘 뭐 하지?"라는 말이 나올 때, **함께 꺼내 즐길 수 있는 게임**을 만들고 싶었습니다. 각자의 휴대폰을 들고도 서로 웃고 떠들며 노는 것. 합이오는 그 바람에서 시작됐습니다.

친구와 구슬을 주고받는 협동에 한국 설화 속 요괴와 음양오행을 더했습니다. 함께 구슬을 던져 박을 칠하고, 오래된 봉인을 되살리는 놀이에 우리만의 색을 담았습니다.

지금은 **2026년 10월 22일 첫 출시**를 준비하고 있습니다.

## 개발용 3스테이지 실행

기존 단일 Scene은 `Assets/Lab/Scenes/Lab.unity`로 유지합니다. 별도 게임은 `Hapio > Open Home` → Play → 한지 타이틀의 **게임 시작**에서 시작합니다. 인원 2~5명을 선택해 **새 방 만들기 +**를 누르면 방 등록 완료 후 Host가 자동으로 입장합니다. 다른 참가자는 **수장고-N 카드에 입장**한 뒤 각자 P번호를 고릅니다. Host의 **요괴 봉인 시작 · 3스테이지**로 구미호 → 야광귀 → 지귀 순서의 같은 Battle Scene을 재사용하며, 세 스테이지의 외형은 박 안의 기존 검은 요괴를 공통 사용합니다. 혼자 확인할 때는 Home의 **DEV · SOLO**를 사용합니다. 공통 폭탄·좌우 전달 막기를 유지하고 Home/Lobby DEV에서 공통/요괴별 값을 조정합니다. 자세한 실행·빌드 경로·현행 제한은 [개발용 게임 흐름](docs/GAME_FLOW.md)을 참고하세요.

## 모바일 구슬 조작과 화면 방향 (#310)

구슬을 화면 좌우 안쪽의 전달 구간까지 바깥 방향으로 끌고 손을 놓으면 옆 플레이어에게 전달합니다. 잠시 들고 멈춰도 전달 준비를 유지하며, 안쪽으로 되돌리거나 위로 투척 방향을 바꾸면 해제합니다. 준비 중인 방향은 작은 화살표로 표시합니다. 직접 음양 구슬을 겹치는 조합이 우선이며, 전달 차단·2:2 벽·Host 소유권 확인은 그대로 적용합니다.

좌우·하단에서 거의 멈춘 일반 구슬은 약 0.3초 뒤 다시 잡기 쉬운 안쪽으로 부드럽게 이동합니다. 드래그·전달/투척/조합 대기·이동 중인 구슬과 북·폭탄·여우불은 자동 보정하지 않습니다. 자동 보정이 일반 구슬의 충돌 조합을 새로 일으키지 않도록 구분합니다. 실제 터치가 구슬 본체에 닿으면 다른 구슬의 확대된 보조 범위보다 우선합니다.

전투 Scene의 `OrbBoard > LabOrbBoard > Screen-edge controls (#310)` Inspector에서 조절합니다. `Transfer Inset` 기본36, `Minimum Drag`12, `Turn Back Tolerance`4, `Minimum Grip Radius`22, `Target Padding`4, `Bottom Padding`16은 가로390 기준 UI 단위이며 화면/카메라 크기에 맞춰 환산합니다. `Rest Delay` 기본0.3초, `Rest Speed`0.035와 `Nudge Speed`0.18은 보드 폭/초 기준입니다. 이 값들은 로컬 조작 보조이며 공유 게임 규칙이나 통신 버전을 바꾸지 않습니다.

iOS는 정방향 세로로 고정합니다. 실제 조작 가능한 전투 중에만 좌우·하단 시스템 제스처를 유예하고, 로비·일시정지·결과에서는 복원합니다. 홈 이동을 완전히 차단하는 기능은 아닙니다. Hapio/Lab iOS 내보내기는 세로 방향·전체 화면 설정을 공통으로 검사합니다. 컴파일/자동 검사와 실기기 회전·홈 제스처 확인 결과는 [검증 기록](docs/VALIDATION.md)에서 구분합니다.

## 방 입장·페인트 완료·UI 보정 (#315)

Hapio 방 생성은 등록 완료 뒤 같은 세션으로 자동 입장합니다. 일반 협동 자리는 박을 위에서 내려다볼 때 P번호 순서가 시계방향이며, 내 자리가 화면 아래라면 다음 P가 왼쪽·이전 P가 오른쪽입니다. 2:2는 기존 팀 배치를 유지합니다.

페인트 100% 승리는 최종 지도를 공유한 뒤 약1.2초·표현0.2배 완료 연출을 함께 보고 결과로 이동합니다. 크랙 모드와 구형 분리 연출은 제거했고, 스태미나 위로 구슬이 보이도록 합성 순서를 복구하며 결과 박은 원본 비율을 유지합니다. 세부 동작·확인 방법·실행 검증 범위는 [#315 작업 안내](docs/SESSION_FINISH_UI.md)와 [검증 기록](docs/VALIDATION.md)을 참고하세요.

### 야광귀 시간표와 통합 기믹 (#311 / #314)

기믹은 #311의 공용·고유 실행 경로를 사용한다. 구미호·지귀·Lab은 기존 주기/확률 정책을 유지하며 야광귀 스테이지만 시간표를 공급한다. 야광귀 기본 전투120초, 고유 예고10초 섬광/35초 콤보/60초 섬광/75초 콤보, 공용25/40/60/80초다. 공용은 첫 종류를 seed로 정한 뒤 폭탄·넘기기 막기를 교대한다. 공용과 고유는 겹칠 수 있다.100초에 남은 방해를 무결과 정리하고120초까지 일반 플레이를 계속한다. 별도 피버 기능을 추가한 것은 아니다.

Hapio DEV 야광귀 탭에서 시간표를 조정한다. 그 탭에서 사용하지 않는 일반 간격·확률은 숨긴다. 폭탄/막기·섬광/콤보 스위치는 해당 시간표에도 적용되며, 걸 대상이 없는 공용 차례는 대기시키지 않고 건너뛴다. 동일 시각 고유 패턴은 기존대로 콤보가 먼저이고 나머지는 앞선 고유 효과 종료 후 전체 예고부터 시작한다.

현재 공유 설정228개, 프로토콜5669 / Lab30 / Game13이며 구형211·220개 시간표/기믹 빌드와 혼용하지 않는다. 실기기 검증 여부는 [검증 기록](docs/VALIDATION.md)을 따른다.

### 음·양 연속 출현 보정 (#324)

기본 ON이며, 플레이어별 실제 음·양 생성 순서에서 같은 종류가2개 연속이면 다음 Raw의 반대 종류 확률을75%로 정한다. 같은 종류가3개 연속이면 다음 Raw는 반드시 반대다. 최대 연속 수가 우선하며 DEV에서 최대1을 선택하면 교대한다. 이는 일정 묶음을 절반씩 맞추는 방식이 아니며, 짧은 구간의 쏠림을 줄인다.

Lab의 `Generation chances`, Hapio의 `Common`에서 `Raw Streak Correction`(ON/OFF), `Opposite Chance After 2 Raw (%)`(0~100, 기본75), `Maximum Consecutive Raw`(1~10, 기본3)를 조정한다. 기존 적용·공동 Pause 후 재시작 절차와 Host 설정 확인을 따른다. 원본LabConfig는 런타임 조정으로 저장하지 않는다.

아이템 종류 확률은 기존 추첨을 유지한다. 아이템·전달받은 구슬·피버의 직접Combined·실패/중복/과열 무생성은 음·양 기록을 늘리거나 초기화하지 않는다. 한쪽 생성 비중이0이면 보정으로 금지된 종류를 생성하지 않는다. OFF는 기존 난수 결과를 그대로 사용한다. 기본 음·양 비중을50:50 이외로 바꾸면 ON의 조건부 보정이 그 비중보다 우선하므로 원래 장기 비율까지 같다고 보장하지 않는다.

설정225~227을 추가해 총228개, 프로토콜5669/Lab30/Game13을 사용한다. 실제 실행 결과와 실기기 미검증 범위는 [검증 기록](docs/VALIDATION.md)을 따른다.
