## 열기와 실행

### 플레이어 번호와 자리

일반 공유 방에 들어오면 **Host와 참가자 모두 미선택**으로 시작합니다. 로비의 **CHOOSE PLAYER POSITION**에서 목표 인원 N에 맞는 **P1~PN** 중 빈 번호를 선택합니다. **OPEN**은 선택 가능, **TAKEN**은 다른 참가자가 선택한 자리, **YOU/CLEAR**는 내 자리이며 내 번호를 다시 누르면 선택을 해제합니다. Host의 승인 응답과 확정 점유표를 모두 받은 결과만 반영하며, 승인 대기 중에는 선택 버튼을 잠급니다. 다른 사람이 먼저 고른 번호는 거절하고 기존 선택을 유지합니다. 응답이 없으면 대기를 해제하고 재시도 안내를 표시합니다.

방장 권한과 P번호는 독립적이므로 Host도 P1 외의 번호를 고를 수 있습니다. **설정 인원 전원 입장 + 서로 다른 P번호 선택 완료 + 전원 최신 설정 확인**을 만족해야 Host의 **START**가 활성화됩니다. 별도 Ready 단계는 없습니다. 새 참가자만 미선택이며 기존 참가자의 선택을 덮어쓰지 않습니다. 퇴장 시에는 그 사람의 번호만 비우고 남은 번호를 다시 매기지 않습니다. 전투 중에는 선택을 바꿀 수 없습니다.

**Retry·DEV APPLY & RESTART·같은 방 로비 복귀는 선택을 유지**합니다. 같은 방 로비에서는 다시 변경할 수 있으며, 방을 완전히 나가거나 새 방에 입장하면 선택을 초기화합니다. 전투 중 누군가 나가면 기존 연결 종료 규칙에 따라 같은 방 로비로 돌아옵니다. 개발자 솔로와 자동 검증 전용 `--lab-auto-start`는 이 일반 로비 선택 경로와 구분합니다. 솔로는 P1, 자동 검증은 Host가 빈 번호를 자동 할당합니다.

본인 원은 하단 중앙, 이전 번호는 왼쪽, 다음 번호는 오른쪽에 표시합니다. 처음과 마지막 번호는 연결되고 2명일 때 양옆은 같은 상대, 솔로에서는 양옆을 숨깁니다. 현재 전달 방향은 고정이며 시계/반시계 전환 기능은 추가하지 않았습니다. Figma `2238:8414` 기준 원 크기는 48×48, 좌상단 좌표는 왼쪽 (-7,437), 오른쪽 (360,437), 본인 (177,809)입니다.

- Unity Hub에서 이 저장소 루트를 프로젝트로 추가하고 **Unity 6000.6.5f1**로 엽니다. 버전 기준은 `ProjectSettings/ProjectVersion.txt`입니다.
- 실험 Scene은 `Assets/Lab/Scenes/Lab.unity`입니다. Scene에 저장된 Canvas와 GameObject는 Hierarchy/Inspector에서 직접 조정합니다.
- 게임 수치는 `Assets/Lab/Resources/LabConfig.asset`의 **단일 설정 원본**에서 조정합니다. 속성을 바꿨다면 새 세션에서 확인합니다.
- 구슬의 **보이는 형태**는 `Assets/Lab/Art/Orbs/`의 에셋에서 조정합니다. 게임 수치와 시각 에셋은 분리되어 있습니다.
- 공유 방은 Host를 포함해 **2~5명**, 기본값은 **3명**입니다. 앱을 실행하면 기존 로비의 **LOCAL ROOMS** 목록이 자동으로 검색을 시작합니다. 방 이름을 눌러 입장합니다. Host는 목록 위의 **ROOM PLAYERS** `−`·`+`로 목표 인원을 정한 뒤 **CREATE ROOM**을 누릅니다. 개발자 수치를 함께 조정하려면 **DEV → CREATE ROOM**을 사용합니다. 방을 만든 뒤에는 목표 인원을 바꿀 수 없습니다.
- 접속 중에도 목록이 남고 선택한 행에는 **CONNECTING**이 표시됩니다. 이때 다른 입장·방 생성은 잠기며 **CANCEL CONNECTION**으로 취소할 수 있습니다. 접속 실패·취소 뒤에는 전송 종료가 완료된 후 검색이 한 번 재개되고, 이전 사유가 안내에 남습니다. 검색 자체가 실패하면 **REFRESH ROOMS**로 명시적으로 다시 시도합니다.
- **REFRESH ROOMS**는 기존 행을 최대 5초 동안 보존하며 새로 확인합니다. 새 탐색에서 주소가 확인되기 전인 행은 선택할 수 없고, 확인되지 않은 행은 제거합니다. 결과가 없으면 5초 뒤 안내를 표시하면서 검색은 계속합니다. 방의 현재 인원·전투 상태를 실시간으로 표시하는 기능은 이번 범위에 포함하지 않습니다.
- **DIRECT IP**를 펼치면 기존 Host 주소·포트 입력과 **JOIN BY IP**가 나타납니다. 기본 포트는 `7777`, 같은 Mac에서 직접 접속할 때는 `127.0.0.1`입니다. 직접 IP도 실패·취소 뒤 목록으로 복귀합니다.
- 입장 후에는 **Host와 참가자 모두 Host가 확인한 방 이름**을 표시합니다. 각자 로비에서 빈 **P1~PN**을 선택하고, 목표 인원·고유 번호·최신 설정 확인이 모두 갖춰지면 Host의 **START**가 활성화됩니다. 선택 패널은 DEV·전투·결과 화면을 덮지 않습니다. **LEAVE ROOM** 또는 DEV의 **END SOLO**로 나가면 전송 종료 뒤 자동 검색 화면으로 돌아갑니다.

핫스팟에서 시험할 때는 iPhone에서 개인용 핫스팟을 켜고 그 iPhone에서 방을 만듭니다. 참가 기기를 그 핫스팟에 연결한 뒤 자동 목록에서 Host와 같은 방 이름을 선택합니다. 같은 방의 IPv4·IPv6 주소는 한 행으로 묶고 기존 순서로 시도하며, 경로별 12초·전체 60초 기준을 유지합니다. 연결 중 기다리기 어렵다면 취소 후 다시 선택할 수 있습니다. 두 앱의 로컬 네트워크 권한을 허용해야 합니다. 목록 검색과 직접 IP 접속, 자동 Mac 검사와 실기기·핫스팟 검증은 [검증 기록](docs/VALIDATION.md)에서 구분합니다.

Host가 명시한 정원 초과·전투 진행 중·버전 거절은 이유를 표시합니다. 현재 NGO가 구버전 접속을 이유 없이 끊는 경우도 있어, 모든 버전 불일치를 특정 원인으로 판별하지는 못합니다. 모든 참가자가 같은 새 버전 앱을 사용해야 합니다.

### 한 대로 조합·투척 실험하기

Unity Editor에서 Play를 누르거나 **Development Build**로 만든 앱을 실행합니다. 화면 오른쪽의 **DEV**를 누르면 142개 설정의 입력·토글과 고정 목표 행이 있는 패널이 열립니다. `Monster Max HP`, `Orb Generation Cost`, `Orb Lifetime (seconds)`, `Throw ...` 등 필요한 값을 조정하고 **START SOLO**를 누르세요. 한 명의 Host 세션이 즉시 시작되며, 솔로 플레이어가 모든 북을 갖습니다. 조합판 위 **북**을 탭해 Yin/Yang을 만든 뒤 서로 다른 두 구슬을 직접 겹쳐 Combined를 만들고 위쪽으로 빠르게 스와이프해 박에 던질 수 있습니다. 북에서는 기본으로 음·양만 나오며(각 50%), 박이 20~30초마다 떨어뜨리는 폭탄은 솔로에서 모두 내 판에 떨어집니다. 좌우 끝 전달은 이웃이 없으므로 발생하지 않고, 같은 이유로 **잠긴 아이템도 솔로에서는 풀리지 않습니다.** 아이템을 시험하려면 아이템 확률을 올리고, 풀린 아이템을 혼자 보려면 `Item Unlock Swipes Min`·`Max`를 0으로 둡니다. 박 폭탄을 빨리 보려면 `Gourd Bomb Interval Min`·`Max`를 5처럼 작게, 폭탄 없이 투척만 비교하려면 `Gourd Bomb Interval Max`를 0으로 둡니다. 박의 상하 움직임을 비교하려면 DEV의 **Gourd** 묶음에서 `Gourd Rope Cycle Amplitude`와 `Period`를 조정하고 **RESTART SOLO**를 누릅니다. 명중 뒤 더 탱글거리는 반응은 `Hit Bounce`를 올리고 `Damping`을 낮춰 비교하세요. 강한 측면 타격으로 박 아랫면을 드러내려면 `Gourd Swing Impact Strength`와 `Maximum Angle`을 조정하고, `Return Strength`와 `Damping`으로 공략 시간을 맞춥니다.

값을 다시 조정하려면 **DEV → 값 변경 → RESTART SOLO**를 누릅니다. 새 값으로 새 판을 시작하며 구슬·요괴/개인 HP·시간·스태미나가 초기화됩니다. 예를 들어 느긋하게 조합을 시험하려면 `Battle Duration (seconds) = 600`, `Orb Lifetime (seconds) = 60`, `Orb Generation Cost = 1`로 입력합니다. **DEFAULTS**는 저장된 `LabConfig.asset` 값을 입력칸에 불러오고, **END SOLO**는 로비로 돌아갑니다. 오류가 있는 값은 적용하지 않고 패널에 이유를 표시합니다. 일반 빌드에서는 DEV 버튼이 숨겨집니다.

### 공유 방의 값 바꾸기

Host에서 **DEV**를 열고 **ROOM PLAYERS**를 2~5명 중 하나로 정한 뒤, 142개 설정을 확인하고 고정 목표 외의 값을 숫자 입력·슬라이더·토글로 조정합니다. 숫자 입력은 정확한 값을 지정할 때 사용하며 두 조작은 서로 같은 값을 보여줍니다. DEV의 **ROOM PLAYERS**는 일반 로비의 인원 선택과 같은 값을 표시·변경합니다. **CREATE ROOM**을 누르면 선택한 인원과 조정값으로 방을 만들고, 참가자가 자동 방 목록에서 이름을 선택하거나 직접 IP **JOIN**으로 들어오면 Host 설정을 받습니다. Host 로비에서 전투 시작 전에 다시 DEV를 열어 값을 바꿀 수 있으며, 이때 버튼은 **APPLY TO ROOM**입니다. 변경된 설정에 대해 참가자의 확인이 끝나야 **START**할 수 있습니다. 인원수는 방을 만들기 전에 선택합니다. Editor·Development Build의 Host는 전투를 일시정지한 뒤 **DEV → APPLY & RESTART**로 새 설정을 참가자에게 보내고 확인을 받아 새 판을 시작할 수 있습니다. 진행 중인 판의 설정은 바꾸지 않고, 설정은 실행 중인 세션의 복사본에만 적용되며 `LabConfig.asset`에는 저장되지 않습니다.

설정142개·프로토콜5637을 사용하므로 참가자 모두 같은 버전 앱으로 접속합니다. 완성품 관람도 같은 질감 설정을 복제합니다. iOS 화면·성능 검증 여부는 [검증 기록](docs/VALIDATION.md)의 #196 항목에서 확인합니다.

### 완성된 박 관람하기 (#191)

DEV의 `Gourd` 묶음에 있는 **Completed Gourd Viewer (0 off, 1 on)**은 **112번째(인덱스 111)** 설정이며 기본값은 **OFF(0)**입니다. 기존 0~110번 설정과 111번째 `Paint Vertical Weight`의 위치는 그대로 유지합니다. ON으로 적용한 판에서 Paint가 전체 셀을 칠해 **100% Victory**가 되고 Snapshot과 공개 표시 맵의 세션·라운드·해상도·Revision·셀 수·명중 수가 일치하면 결과 화면에 관람 버튼을 표시합니다. Crack·Defeat·미완성 또는 아직 수신 중인 맵에는 표시하지 않습니다.

이 허용값도 **START/RESTART SOLO**, **CREATE ROOM**, Host 로비의 **APPLY TO ROOM**, 공동 일시정지한 Host의 **APPLY & RESTART**에서 전체 142개 설정을 함께 검증·적용합니다. Host의 설정 지문과 참가자 확인 응답을 사용하며 진행 중인 판에 즉시 적용하지 않습니다. **일반 Release 참가자도 Host의 허용값을 따릅니다.** DEV 버튼은 Editor·Development Build에만 보이지만 관람에 별도 실행 인자나 Editor 메뉴 활성화는 필요하지 않습니다.

관람창은 각자 열고 닫으며, 드래그 회전·핀치 또는 마우스 휠 확대/축소·**RESET VIEW**는 자기 화면에만 적용됩니다. **BACK TO RESULTS**로 닫으면 미리보기 자원을 해제합니다. 관람 중에는 불투명 모달이 아래 결과 버튼 입력을 막으며 게임 맵·판정·점수를 바꾸지 않습니다. 일반 Retry는 허용값을 유지하지만 관람창과 이전 미리보기는 닫고 새 판의 완료 결과를 기다립니다. 새 설정 적용, 로비 복귀, 연결 종료, 모드 변경 때도 관람 UI와 미리보기 자원을 정리합니다. 저장 Scene은 바꾸지 않고 `Assets/Lab/Resources/GourdResultViewer/ViewerUI.prefab`을 필요한 결과에서만 불러옵니다.

## 전투 UI와 일시정지

전투 화면은 Figma `UI 가이드`의 **조합대·일시정지·제한시간·요괴 HP·스태미나 볼/바** 배치를 기준으로 합니다. 하단의 구슬 생성 버튼(`FigmaGenerateButton`)은 꺼 두었고, 생성은 조합판 위의 북으로 합니다. 개인 HP와 스태미나는 현재 화면 맨 아래의 축소된 하단 HUD에 표시됩니다. UI에 사용할 투명 그림은 `Assets/Lab/Art/UI/`에 두고, 위치와 크기는 저장 Scene `Assets/Lab/Scenes/Lab.unity`의 `LabCanvas`에서 조정합니다. 배경 풍경·요괴 캐릭터·플레이어 캐릭터 이미지는 이번 UI 이식 대상이 아닙니다. 기존 3D 요괴와 판 위 구슬의 물리·판정은 유지합니다.

전투·일시정지·결과 화면에서는 상단 전투 카메라와 하단 구슬 카메라의 단색 배경을 로비보다 밝게 표시합니다. 색은 저장 Scene의 `LabHud`에 있는 `Battle Background Color`·`Orb Background Color`에서 조정할 수 있으며, 같은 방 로비로 돌아가면 기존 어두운 카메라색으로 복원됩니다. 조합대 종이판과 요괴·구슬 에셋의 색은 이 설정에 포함되지 않습니다.

제한시간은 Host가 확정한 남은 시간을 **분:초**로 표시합니다. 상단 막대는 Paint에서 **GOAL**과 공동 색칠 진행도/목표 비율을, Crack에서 **YOKAI HP**와 요괴 HP 비율을 표시합니다. Paint 목표는 항상 **100%**입니다. 숫자와 막대는 Host Snapshot의 `paintCoveredCount / paintCellCount` 정수 셀 수를 기준으로 하고, 숫자는 소수 첫째 자리까지 내림해 미완료 상태를 100%로 표시하지 않습니다. 셀 수가 없는 예전 검사 fixture에만 `paintCoverage`를 보완값으로 사용합니다. 자기 HP는 하단 오른쪽, 스태미나는 하단 왼쪽의 연속 Fill로 현재값/최대치 비율을 표시합니다. 구슬 생성은 조합판 위의 북을 탭해 요청합니다. 좌우 둥근 표시에는 선택한 P번호의 순환 순서에 따른 이웃 **P번호**를 표시합니다. 2인 판은 양쪽에 같은 상대가, 솔로 판은 `P—`가 보입니다. 이름 입력이나 속성 선택을 새로 만들지 않습니다.

전투 중에는 어느 참가자든 일시정지를 요청할 수 있으며, Host가 승인한 상태가 모든 참가자에게 전파됩니다. 일시정지 동안 색칠 성장·남은 시간·구슬 수명·폭탄 타이머와 판의 물리 진행을 멈추고 생성·조합·전달·투척 입력을 받지 않습니다. **재개**와 **모두 로비로**는 Host만 실행합니다. 모두 로비로 돌아갈 때 참가자를 연결 해제하거나 방 이름을 없애지 않고 같은 방을 유지합니다. Editor·Development Build의 Host는 일시정지 메뉴에서 DEV 설정을 열어 **APPLY & RESTART**로 새 값이 확인된 후 같은 방의 새 판을 시작할 수 있습니다. 이 기능은 솔로의 **RESTART SOLO**와 별개입니다. 세부 연결과 검증 항목은 [UI 이식 기록](docs/UI_GUIDE_ASSET_IMPLEMENTATION.md)과 [검증 기록](docs/VALIDATION.md)에 구분했습니다.

조합대의 보이는 모양·위치·크기는 **PR #154의 배치**를 유지합니다. 저장된 종이판 `OrbBoardPlate`의 local position은 `(0, 0, 0.55)`, local scale은 `(10, 5, 1)`이며, 실행할 때는 기존 방식대로 하단 카메라 전체의 가로세로에 맞춥니다. 하단 HUD가 종이판 일부를 덮는 원래 구성이므로, 곡선 물리를 위해 종이판을 HUD 위로 올리거나 세로로 줄이지 않습니다.

물리·입력 범위는 실제로 **보이는 영역**을 따릅니다. `LabOrbAreaProfile`에 `BoardPlate.png`의 상하 외곽과 `BottomHudBackground.png`의 불투명 상단 외곽을 각각 65점으로 저장합니다. 위쪽은 종이판 곡선, 아래쪽은 종이판 하단과 HUD 상단 중 높은 곡선을 사용하며 두 선분의 교차점까지 계산합니다. 직사각형 HUD 높이로 잘라내거나 일괄 여백을 더하지 않습니다. 원본 그림의 배치와 에셋은 바꾸지 않습니다. `OrbInteractionArea`는 비시각 참조이며, 현재 저장 Scene에서 종이판을 재배치하는 기준으로 사용하지 않습니다.

상하에는 3D MeshCollider 벽을 만들고 좌우는 전달 통로로 열어 둡니다. 구슬·북의 실제 반지름을 고려해 생성·드래그·수신·크기 검증에 같은 경계를 적용합니다. 곡선 밖 빈 배경이나 HUD 위에서는 새 입력을 시작하지 않으며 이미 잡은 구슬의 영역 밖 손떼기·투척·전달은 유지합니다. 화면·HUD 위치·제어점 변경 시 같은 ID·위치 비율·보드 폭 기준 속도와 요청 대기를 보존하며 드래그 중에는 변경을 보류합니다. `C6 Lab/Fit Curved Orb Area`는 #154의 저장 배치를 복원하고 현재 그림의 윤곽을 연결합니다. 같은 그림에서 수동 조정한 기존 제어점은 보존하며, 런타임 픽셀 읽기 대신 검증된 형상을 캐시합니다.

## 전투 조작과 물리

전투 중 각 플레이어는 매달린 박 표적을 둘러싼 자기 자리의 시점에서 봅니다.

구슬은 조합판 위의 **생성 북**으로 만듭니다. 북은 기본적으로 한 게임에 **1개**이고(DEV `Drum Count`로 1~5개), 판마다 Host가 받을 사람을 무작위로 정합니다. 북이 인원 이하이면 서로 다른 사람이 받습니다. **북이 있는 사람만** 북을 **탭**해 Yin·Yang Raw 구슬(기본 각 50%, DEV로 아이템도 가능) 한 개를 설정 확률에 따라 만들 수 있으므로, 북을 서로 넘겨줘야 합니다. 탭할 때마다 하나씩 나오므로 스태미나가 있는 만큼 연타할 수 있습니다.

- 구슬은 북 안에서 톡 튀어나와 커지며 **360° 무작위 방향**으로 바로 날아갑니다. 나오는 짧은 순간(기본 0.15초)에는 다른 구슬·북을 통과해 연타해도 막히지 않고, 위아래 벽에는 부딪힙니다. 북이 옆 가장자리 가까이 있으면 그쪽으로 나가는 구슬은 옆 사람 화면에 닿기 전에 멈출 만큼만 나갑니다.
- 북은 끌어서 옮기거나 **좌우로 튕겨 옆 사람에게** 넘길 수 있습니다. 위로 튕겨도 던져지지 않습니다.
- 넘긴 북은 **받는 사람 판 안에서 서서히 멈춥니다**(#178). 멈추는 자리는 Host가 확률로 정하므로 같은 힘으로 넘겨도 매번 다릅니다: 들어온 쪽 가장자리에서 판 폭 **20~40%(40%)**, **40~60%(35%)**, **60~80%(15%)**, 또는 **그다음 사람에게 통과(10%)**. 세게 넘기면 들어오며 속도를 줄여 미끄러져 들어오고, 약하게 넘기면 1.2초 안에 도착하도록 밀어 줍니다. 통과한 북은 그다음 사람 판의 가까운 쪽(20~40%)에서 반드시 멈춥니다. 멈춘 뒤에는 원래처럼 떠돕니다. 도착하는 중에 잡으면 그때부터 내 북입니다.
- 폭탄 충격파에 밀려 옆으로 넘어간 북은 힘대로 넘어가 미끄러지되, **넘어간 사람의 판 안(먼 쪽 끝 80% 이내)에서 반드시 멈춥니다.**
- 구간 경계와 확률은 DEV의 `Drum Stop …`·`Drum Pass Through Chance` 8개로 조정합니다(경계는 가까운 쪽 → 먼 쪽 순서, 확률 합 100).
- 가만히 두면 북은 사방으로 천천히 떠돌고, 길이 휘는 쪽과 스치는 충돌에 따라 화면을 향한 채 회전합니다. 혼자서는 옆 화면으로 넘어가지 않고 가장자리에서 되돌아옵니다.
- 북은 수명·보관 한도·조합·던지기·폭탄 폭발의 대상이 아닙니다.

조합판의 구슬 조합판의 구슬은 3D 구체이며 `Rigidbody`·`SphereCollider`의 PhysX 충돌을 사용합니다. 위치와 속도의 Z축은 고정해 기존 XY 평면에서만 움직입니다. 손가락이나 마우스로 밀면 관성으로 이동하다 감속하고, 상하에서 반발합니다. 좌우 끝으로 나가면 이웃 화면으로 속도와 높이를 이어 전달합니다. Yin과 Yang Raw는 직접 드래그해 놓거나, 현재 기본 설정처럼 접촉 자동 결합이 켜져 있을 때 서로 부딪혀 Combined가 될 수 있습니다. 같은 극성끼리는 결합하지 않습니다. Combined에는 Host가 화·수·목·금·토 중 하나의 속성을 같은 확률로 정해 주며, 조합판과 날아가는 투사체 모두 그 속성 색으로 보입니다.

아이템(릴레이 구슬·시크릿 상자·회복물약·폭탄)은 기본 생성 확률이 0이라 북에서 나오지 않으며, DEV에서 확률을 올리면 다시 나옵니다. 폭탄은 아래 **박의 폭탄**에서 따로 설명합니다. 나머지 아이템은 구슬 정면의 아이콘으로 구분하며 **잠긴 채로** 생깁니다. 오른쪽 아래 배지의 숫자는 남은 잠금 횟수(기본 2~4)이고, 아이템을 **옆 사람 화면으로 넘길 때마다 1씩** 줄어 0이 되면 배지가 사라집니다. 잠긴 동안은 아이콘이 흐려지고 그 위에 **자물쇠**가 겹쳐 보입니다. 마지막 잠금이 풀리는 순간 받은 사람 화면에서 자물쇠가 위로 떠오르며 사라지고, 금색 원이 구슬 크기로 줄어든 뒤 구슬이 한 번 반짝입니다(약 0.6초). 아이템은 15초 뒤 사라지며 음·양과 조합되지 않습니다.

풀린 아이템은 이렇게 씁니다.

- **회복물약**: 같은 구슬을 빠르게 두 번 탭하면 내 개인 HP가 10 오릅니다(최대 HP를 넘지 않음). HP가 가득 차 있거나 0이면 쓰이지 않고 남습니다.
- **시크릿 상자**: 두 번 탭하면 그 자리 양옆에 던질 수 있는 속성 구슬 2개가 생깁니다. 보관 칸이 하나 더 있어야 열립니다.
- **릴레이 구슬**: 풀리는 순간 배지가 `×1`이 되고, 옆 사람에게 넘길 때마다 `×2` → `MAX`로 오릅니다. 위로 던지면 기본 피해의 1·2·4배를 줍니다.

### 박의 폭탄 (#177)

박은 방해공작으로 **20~30초마다**(DEV `Gourd Bomb Interval Min`·`Max`, 최대 0이면 끔) **무작위 한 명**의 판에 폭탄을 떨어뜨립니다. 구슬이 가득 찬 판에도 떨어지고, 같은 사람이 연달아 받을 수도 있으며, 스태미나는 쓰지 않습니다. Host가 시각·대상·착지 위치를 정하므로 모든 기기가 같은 결과를 봅니다.

- **모든 화면**: 전투 화면의 박 오른쪽 위에 손그림 느낌의 **"!" 말풍선**이 톡 튀어나와 흔들리다 약 1.4초 뒤 사라집니다.
- **받는 사람 화면**: 알림 문구가 뜨고, 착지 지점에 빨간 **"!" 경고**가 0.6초 표시된 뒤 폭탄이 구슬판 위쪽에서 떨어져 두 번 튀며 내려앉습니다. 내려앉기 전에는 잡거나 밀 수 없고 다른 구슬과 부딪히지 않습니다.
- **모양**: 만화 폭탄 그림이며, 몸통의 **빨간 숫자가 남은 초**입니다(15부터 줄어듦). 도화선 끝에서 불꽃이 일렁이고 **치지직** 소리가 나며(DEV `Fuse Sound Volume`), **마지막 3초에는 빨갛게 점점 빠르게 깜빡이고 소리도 빨라집니다.**
- **움직임**: 가만히 두면 북처럼 혼자 떠돌며(북의 떠돌기 값 공유), 움직이는 만큼 굴러 꼭지와 도화선이 공 둘레를 입체로 돕니다. 꼭지는 몸통 뒤로 숨지 않습니다. 혼자서는 옆 화면으로 넘어가지 않고, **좌우로 튕기거나 폭발에 밀려야** 옆 사람에게 넘어갑니다.
- **규칙**: 폭탄에는 **잠금이 없고 던질 수 없습니다.** 몇 번을 넘겨도 도화선은 이어서 타며, **15초**(아이템 수명)가 끝나면 그때 들고 있는 사람 판에서 💥 **"BOMB!"** 과 함께 터지고 진동이 울립니다. 충격파가 주변의 구슬·북·잡고 있던 구슬을 밀어내며 **구슬은 사라지지 않습니다.** 세게 밀려 옆 가장자리를 넘은 구슬은 옆 사람에게 넘어가고, 잠긴 아이템은 이때도 잠금이 1 줄어듭니다. 충격파 범위·세기는 DEV `Bomb Blast Radius`(기본 판 폭의 40%)·`Bomb Blast Strength`(기본 9)로 조정합니다.
- 폭탄 기믹은 이후 다른 이슈에서 다시 다듬을 예정이라, 던질 수 없는 지금은 DEV `Bomb Damage Multiplier`와 결과 화면의 폭탄 사용 수가 쓰이지 않습니다.
- 그림·연출 값은 `LabOrbAppearance`의 **Bomb art**(몸통 `ItemBombBody`·꼭지와 도화선 `ItemBombFuse`, 크기·꼭지 방향·남은 초 글씨)와 **Gourd bomb drop**(경고·낙하·튕김 시간과 높이) 칸에서, 말풍선 크기·시간은 `LabGourdAlert`의 기본값에서 조정합니다.

Combined를 잡고 **구슬 판 안에서 위쪽으로 빠르게 움직이며 손을 놓으면** 그 자리에서 3D 투척합니다. 손을 놓는 가로 위치와 움직임의 방향·세기가 발사 위치와 속도에 반영되므로, 중앙으로 던지면 표적을 맞힐 수 있고 옆으로 치우치면 빗나갑니다. 느리게 옮기면 투척되지 않고 판 위에 남으며, 좌우 끝으로 빠져나가면 기존 이웃 전달이 우선합니다. 기본 `Lab.unity`에서는 `WhiteGourd` 흰 박 프리팹이 보이며, 실제 피격체는 기존 Unity Cylinder의 MeshCollider입니다. 박 표면과 판정 모양에는 차이가 있습니다. Host가 충돌을 확인한 명중만 HP·보상을 반영하며, Paint에서는 승인된 속성 명중의 색칠도 같은 처리에서 확정합니다. 새 조작의 속도·생성 상승 거리·카메라 거리 등은 `LabConfig.asset`에서 조정합니다.

손을 놓아 투척한 Combined에는 속성 색의 짧은 비행 잔상이 남습니다. Host가 실제 명중을 확정하면 맞은 지점에서 속성 색의 코어·스파크·확대 충격파가 나타납니다. **Crack**에서는 `-실제 감소 HP` 숫자도 표시하며, 마지막 명중에서 남은 HP가 설정 피해보다 적으면 숫자도 실제 감소량만 보여 줍니다. **Paint**에서는 피해 숫자를 숨기고 색칠·입자 효과로 피드백하며, 내부 HP가 0이 된 뒤의 유효 명중도 입자·소리·햅틱·명중 보상을 유지합니다. 빗나감에는 피해 숫자·피격 입자가 나오지 않습니다. 숫자는 저장 Scene의 `LabCanvas / LabImpactFeedback`에서, 피격 입자는 `Impact Particle VFX`와 `Assets/Lab/Art/Effects/ImpactParticleBurst.prefab`에서 표시 크기·수명을 조정합니다. 투척 잔상 길이·폭·머티리얼은 `Assets/Lab/Art/Orbs/LabOrbAppearance.asset`에서 조정합니다. 이 시각 효과는 투사체의 물리·판정을 바꾸지 않습니다.

박 모드는 `LabConfig` Inspector의 **Gourd Mode** 또는 DEV의 **`Gourd Mode (0 paint, 1 crack)`**로 고릅니다. 기본 **Paint(0)**는 흰 박의 모든 셀을 칠해 **100%**에 도달하면 전원이 같은 `VICTORY`를 받습니다. 기존 **`Paint Victory Coverage (%)`**의 88번째/인덱스 87과 이름은 유지하며, 값과 허용 범위는 **100~100**으로 고정합니다. 옛 에셋의 80도 유효값·공유값으로 읽을 때 100으로 정규화하고, DEV로 100 외 값을 보내면 전체 설정을 거절합니다. 원본 `LabConfig.asset`도 Unity에서 목표 100과 성장 기본값을 저장했습니다. **Crack(1)**은 기존 `Target2_Intact` 박·HP 단계 크랙·HP 0 승리를 사용하며 약 1.2초 마무리 후 결과를 표시합니다. 시간 종료와 전원 개인 HP 0은 두 모드에서 패배이고, Paint 결과와 패배 결과는 별도 연출 지연 없이 표시합니다.

Paint의 승인 명중은 Host 모델이 구슬 소모·실제 HP 감소·명중 보상·색칠·승패를 한 번에 처리합니다. 이미 처리한 구슬과 종료/시간 초과 명중은 목표를 올리지 않습니다. 무속성 릴레이·폭탄은 기존 명중 효과·보상과 공격값 기록을 유지하지만 칠하지 않습니다. 결과 대시보드의 Paint 피해/딜 기록은 기존 설정 공격값의 누계이며 실제 HP 감소량이나 칠한 면적의 기여도가 아닙니다. Crack의 기록은 실제 HP 감소량입니다.

색칠은 선택한 해상도의 동일 면적 구면 셀 맵에 저장하며 회전·흔들림을 따라갑니다. 아래 6개는 **DEMO_TUNING_VALUE**로 DEV의 `Gourd` 묶음과 단일 원본 `LabConfig.asset`에서 조정합니다. 기존 0~104번 인덱스를 보존하고 105~110번에 추가했습니다. 새 판 시작 때 설정을 복사하므로 입력칸을 바꿔도 진행 중인 판은 바뀌지 않습니다.

유효한 오행 명중이 안 칠한 셀에 닿으면 초기 면적을 즉시 칠하고, 이미 칠한 셀에 닿으면 그 연결 영역에 반복 성장 면적을 공급합니다. 이후 Host 전투 시계가 진행될 때 미사용 예산을 가진 영역들이 전체 표면 기준 `%/초` 속도를 나눠 쓰며 빈 인접 셀로 자랍니다. 시간이 흐르는 동안 공급 예산이 없으면 자라지 않으며, 그 대기 시간의 성장량을 미리 적립하지 않습니다. 여러 영역은 차례대로 성장하고 서로 닿으면 하나로 병합됩니다.

이미 칠한 셀의 색은 덧칠하거나 병합할 때 바뀌지 않습니다. 명중별 면적 공급은 각 연결 영역 안에서 먼저 들어온 순서(FIFO)대로 소비하고, 병합 뒤에도 공급 순서를 유지합니다. 한 셀을 채우는 데 이전 공급의 남은 소수 면적과 다음 공급이 함께 필요하면 **그 셀을 마지막으로 채운 공급자의 색과 소유자**를 사용합니다. 마지막 전체 셀을 채운 공급자가 `lastHit`를 받으며, 가장 최근에 던진 사람이 반드시 받는 것은 아닙니다.

가로 이음새는 연결하고 남·북극에서는 세로 범위를 고정합니다. 모든 빈 셀에는 인접 성장 경로가 있으므로 기한 내에 충분한 명중 예산과 성장 시간을 확보하면 같은 지점을 반복해서 맞혀도 전체 100%까지 도달할 수 있습니다. `Fill Chance`가 0 또는 100이어도 다른 후보로 진행하는 대체 경로를 유지합니다. 셀은 투명 또는 불투명이며, 진행도는 `CoveredCount / CellCount`입니다. 이 비율은 화면 픽셀·조명·실제 메시 삼각형 면적을 측정한 값이 아닙니다.

제한 시간 전에 마지막 셀이 완성되면 공동 Victory가 되고, 마지막 성장 시각과 제한 시간 종료가 정확히 같으면 Defeat가 우선합니다. 늦게 도착한 Tick도 제한 시간 전에 완료될 성장은 해당 시각까지 계산합니다. 공동 일시정지 동안 성장·전투 시계·입력·물리는 멈추며 재개 뒤 이어갑니다. 일반 Retry는 모드와 캡처한 성장 설정을 유지하면서 맵·영역·공급 예산·명중 수·난수 진행을 초기화합니다. 새 DEV 값은 다음 시작/재시작에 캡처하며 진행 중인 판에는 적용하지 않습니다. 로비 복귀와 방 이탈도 표시·수신 상태를 정리합니다.

기본 Scene을 바꾸거나 Paint 전용 연결 메뉴를 실행할 필요는 없습니다. `LabSceneController`가 실행 시 `LabGourdPaint.Attach(network)`로 Resources의 표현을 연결하고, 초기 설정과 `ConfigApplied`에서 `ApplyMode()`를 호출합니다. DEV 변경은 **START/RESTART SOLO**, **CREATE ROOM**, Host 로비의 **APPLY TO ROOM**, 일시정지한 Host의 **APPLY & RESTART**로 적용합니다. Client는 Host 설정을 사용합니다. 142개 설정(완성 박 관람 허용, #201 추임새 확률·간격 포함)과 셀 delta/체크포인트를 공유하는 프로토콜은 **5637**, 연결 토큰은 `C6PhysicsLab/11`이며 이전 버전 앱과 섞어 접속하지 않습니다. [박 색칠 연결 안내](Assets/Lab/Art/GourdPaint/README.md)를 참조하세요.

기존 포물선은 기본 **ARC**로 유지합니다. **DEV → Throw form**에서 **STRAIGHT**를 선택하면 기존 스와이프 입력·초기 속력·좌우 조준·카메라를 유지한 채 더 낮은 직구를 비교할 수 있습니다. 출발 오프셋 XYZ·발사각·떠오름 비율·중력 배율은 6개 숫자 입력과 슬라이더로 조정하며 Host 설정으로 공유합니다. 관람 토글 인덱스 **111**을 보존하고 직구 7개를 **112~118**에 추가했습니다. [포물선·직구 비교 가이드](docs/THROW_TUNING_GUIDE.md)를 참조하세요. 공통 세기 반응·발사각·공기 저항은 **DEV**의 `Throw Power Exponent`, `Throw Loft Offset (degrees)`, `Throw Air Damping`으로 한 판씩 비교할 수 있습니다. 명중·빗나감 뒤 화면에 비행 시간·최고 상승·수평 이동 거리가 나타납니다. 값의 의미와 반복 시험 순서는 [직선 투척 물리 실험 가이드](docs/THROW_TUNING_GUIDE.md)를 참조하세요.

## 개인 HP 확인

새 라운드에서 Host는 각 참가자의 개인 HP를 `Player Max HP`로 초기화합니다(기본 300, DEV 허용 범위 1~300). HUD의 개인 HP 참조는 **자기 HP만** 읽지만, 현재 저장 Scene의 `FigmaPlayerHpBar`가 비활성화되어 막대와 숫자가 화면에 보이지 않습니다. 참가자는 Host가 보낸 확정 스냅샷의 값을 읽습니다. 한 사람만 0이 되어도 라운드는 계속되고, 모든 참가자의 개인 HP가 0이면 `DEFEAT`로 끝납니다. 결과 화면의 HP 표시 역시 현재는 보이지 않습니다.

**현재 구슬·요괴 기능은 플레이어 HP를 감소시키지 않습니다.** Host 모델에는 이후 피해 기능이 호출할 수 있는 개인 HP 변경 경로만 있습니다. 그러므로 DEV의 최대 HP 슬라이더로 새 라운드의 시작 HP를 비교할 수 있지만, 실제 플레이에서 전원 0 패배를 재현하는 공격 패턴이나 DEV 피해 버튼은 아직 없습니다. 이 종료 규칙은 자동 검사와 실제 피해 기능 추가 후의 플레이 검증을 구분합니다.

## Mac에서 여러 실행본 만들기

1. Unity에서 `Lab.unity`를 연 뒤 **C6 Lab → Build Mac App**을 누릅니다. 또는 **File → Build Profiles**에서 이 Scene을 포함해 원하는 경로로 빌드할 수 있습니다.
2. 프로젝트 루트에서 아래 명령을 실행합니다. 첫 줄은 가장 최근에 만든 기본 경로의 Mac 앱을 찾습니다. 출력 위치를 직접 지정했다면 `APP`을 해당 `.app`의 전체 경로로 바꾸세요.

```sh
APP="$(find "$PWD/Builds/Lab" -maxdepth 3 -type d -name C6_Physics_Lab.app -print | sort | tail -n 1)"
test -n "$APP" || { echo 'Mac 앱을 찾지 못했습니다. 빌드 출력 경로를 확인하세요.'; exit 1; }
open -n -a "$APP" --args --lab-host --lab-port 7777
open -n -a "$APP" --args --lab-join 127.0.0.1 --lab-port 7777
open -n -a "$APP" --args --lab-join 127.0.0.1 --lab-port 7777
```

위 명령은 기본 목표 인원 **3명**의 예입니다. 각 실행본의 로비에서 서로 다른 **P1~P3**을 선택한 뒤, Host 화면의 참가 인원·P 선택이 모두 `3 / 3`이고 설정 확인이 끝나 **START**가 활성화되면 누릅니다. **2명 실험**에는 `--lab-host` 없이 앱을 두 번 연 뒤 Host 일반 로비의 **ROOM PLAYERS**를 **2**로 바꾸고 **CREATE ROOM**을 누릅니다. 다른 실행본에서는 자동 목록의 방 이름을 눌러 입장하거나 **DIRECT IP → JOIN BY IP**로 접속합니다. DEV 패널에서도 같은 인원값을 선택할 수 있습니다. 자동 검증에서만 Host 인자에 `--lab-auto-start --lab-auto-generate --lab-auto-transfer`를 추가합니다. `--lab-auto-start`에서는 Host가 참가자에게 빈 P번호를 할당하고 조건이 갖춰지면 자동 시작하므로, 일반 수동 로비 선택 검증을 이 경로의 성공으로 대신하지 않습니다. 한 프로젝트 폴더를 Editor 여러 개에서 동시에 열 필요는 없습니다. 독립 실행 앱으로 네트워크 경로를 확인합니다.

iOS Xcode 프로젝트는 Unity 메뉴 **C6 Lab → Export iOS Xcode Project**에서 만듭니다. Console에 표시된 `.../iOS` 출력 폴더에서 `Unity-iPhone.xcodeproj`를 열고, Xcode에서 개발 Team을 선택해 기기에 설치한 뒤 로컬 네트워크 권한을 허용합니다. **Unity의 iOS 출력 폴더에는 Xcode 프로젝트가 있고, Xcode가 빌드한 설치용 앱은 별도의 DerivedData에 저장됩니다.** Xcode GUI에서 Run하면 보통 사용자 Library 아래 DerivedData를 사용합니다.

Xcode가 만든 앱 파일까지 같은 보이는 빌드 폴더에서 찾으려면, 서명 설정을 마친 프로젝트에 대해 아래처럼 `-derivedDataPath`를 지정해 터미널에서 빌드할 수 있습니다. `IOS_EXPORT`에는 Unity Console에 표시된 이번 `iOS` 폴더의 전체 경로를 입력하세요. 결과 앱은 `iOS` 폴더와 나란히 만들어지는 `XcodeDerivedData/Build/Products/` 아래에 생깁니다. Xcode 빌드·서명·기기 설치는 Unity의 Xcode 프로젝트 출력 성공과 별도로 확인해야 합니다.

```sh
IOS_EXPORT="빌드 로그에 표시된 iOS 출력 폴더의 전체 경로"
DEVELOPER_DIR="/Applications/Xcode.app/Contents/Developer" xcodebuild \
  -project "$IOS_EXPORT/Unity-iPhone.xcodeproj" \
  -scheme Unity-iPhone -configuration Debug -destination 'generic/platform=iOS' \
  -derivedDataPath "$IOS_EXPORT/../XcodeDerivedData" build
```

화면 간 이동 데이터는 여전히 **구슬 ID·소유자·정규화한 XY 위치와 XY 속도**입니다. Host가 승인한 좌우 전달에서 이 값을 이어 주고, 조합판 내부의 3D 물리 컴포넌트 자체는 네트워크로 전송하지 않습니다. 확정 피격 신호에는 구슬 ID·라운드·속성·실제 피해량·별도 명중 효과 값(`impactValue`)·요괴 기준 충돌 위치·색칠 방향/RGBA·Host 회전 충격량을 담으며, 방향/RGBA는 승인 피격 표현용입니다. 회전 각도·속도는 Host 스냅샷으로 보정합니다. 아이템 사용 요청·릴레이 단계·해금 시각·폭발 알림·박 폭탄 신호·일시정지 상태·북의 소유자/위치/도착 방식·로비 P번호와 확인된 방 이름도 기존 경로로 공유합니다.

Host의 권위 상태는 `LabModel.PaintSurface` 하나이며, 성장 계산은 Host의 전투 시간 진행에서만 합니다. Host 화면도 현재 Snapshot과 같은 버전의 `LabNetwork.PaintSurface` 표시 캐시를 사용해 맵과 HUD를 함께 반영합니다. Client는 승인 명중 방향을 재생해 성장시키지 않고 Host가 보낸 셀 변경(delta) 또는 전체 체크포인트를 별도 수신 맵에 적용합니다. 분할 수신 중에는 기존 공개 표시 캐시를 유지하고, 완성된 맵의 세션·라운드·해상도·Revision·칠한 셀 수·전체 셀 수·명중 수가 Snapshot 메타데이터와 모두 맞을 때 맵과 HUD를 함께 공개합니다. 픽셀이 그대로인 반복 명중도 명중 수가 바뀌면 빈 delta를 발행합니다.

전송은 프로토콜 **5637**의 `paint_cells`·`paint_resync` 경로를 사용합니다. 셀 ID와 RGBA를 담은 delta보다 전체 맵이 작으면 전체 맵을 보냅니다. base64 데이터는 조각당 최대 4,096자, 수신 조각 수는 최대 64개이며 기존 패킷 한도 32 KiB 안에서 전송합니다. 최대 해상도 전체 RGBA 맵은 131,072바이트이고 base64 174,764자를 43개로 나눕니다. 수신 시 헤더·기준 Revision·셀 ID 범위와 순서·payload 크기·알파/색·칠한 셀 수·SHA-256 해시를 검사한 뒤 전체 맵을 한 번에 교체합니다. 중복 완료·이전 전송/스냅샷 번호·이전 라운드를 거절하고, 기준 맵 누락이나 손상에는 Host의 마지막 발행 맵 복사본으로 체크포인트를 요청합니다. `sequence`는 연결 전체의 색칠 전송 번호, `epoch`는 그 맵을 발행한 게임 Snapshot 번호입니다. 체크포인트는 같은 맵 버전의 `epoch`를 유지하며 `sequence`는 새 번호로 증가합니다.

이 복구는 **현재 라운드에 계속 연결된 Client의 부분 맵 누락**을 복원하는 기능입니다. 연결이 끊어진 뒤 전투에 재접속하는 기능은 포함하지 않습니다. 실제 다중 앱·기기에서의 전송과 화면 일치는 자동 패킷 fixture와 구분해 검증합니다.

기본 Scene에서 보이는 박과 실제 피격 MeshCollider는 같은 축에서 흔들리고 회전하며, 로프와 천장 받침은 기존 매달림 연출을 사용합니다. [회전 확인용 그레디언트](Assets/Lab/Art/Targets/TargetSpinGradient.png)는 숨겨진 원통과 독립 원통 테스트용으로 남아 있습니다. 회전 강도·감쇠·최대 속도는 DEV의 **Target spin** 항목에서 새 판에 적용합니다.

## 현재 기준 수치

공유 방은 Host 포함 **2~5명**이며 기본 목표는 **3명**입니다. 목표 인원이 N명이면 Host를 포함한 각 참가자가 로비에서 고유한 P1~PN을 선택하며, Host가 승인한 번호 순서로 **360°/N** 간격의 원형 자리를 구성합니다. PN의 오른쪽은 P1이며 P1의 왼쪽은 PN입니다. 개발자 솔로 모드에서는 한 명의 Host가 같은 생성·조합·투척 규칙을 시험합니다. 기본값은 **Paint 목표 100% 고정**, 요괴 HP **1,000**, 플레이어별 HP **300**, 요괴 명중 공격값 **20**, 제한 시간 **180초**입니다. 요괴 HP는 Crack의 승리 조건이며 Paint에서는 내부 진단값으로만 감소합니다. 개인 스태미나는 **100**으로 시작하고 구슬 생성에 **20**을 쓰며 **1.7초당 20**(초당 약 11.8)을 회복합니다. 유효 명중한 공격자에게만 **10**을 추가 회복합니다. 북이 한 게임에 1개라 북을 받은 사람이 스태미나를 몰아 쓰고 넘기므로, 북이 세 사람을 한 바퀴 도는 동안(약 6~9초) 빈 스태미나가 거의 다 차도록(약 8.5초) 맞췄습니다. 북을 탭하면 음 **50%**, 양 **50%**로 생성합니다. 아이템 4종은 기본 **0%**이고, DEV로 켜면 폭탄 외 아이템은 **2~4회** 넘겨야 풀립니다. 박은 **20~30초**마다 무작위 한 명에게 잠금 없는 폭탄을 떨어뜨리고, 폭탄은 **15초** 도화선이 끝나면 터집니다. 회복물약은 개인 HP **+10**, 릴레이 구슬은 **×1·×2·MAX**에 따라 피해 **20·40·80**입니다. 모든 Raw/Combined 구슬은 생성 후 **8초**, 아이템은 **15초**에 만료되며 Combined는 조합 시 새 수명이 시작됩니다. 기본 수치는 `LabConfig.asset`에서, 실행 중 솔로와 Host 방 시험 값은 DEV 패널에서 조정할 수 있습니다.
