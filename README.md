## 열기와 실행

### #157 플레이어 번호 표시 변경

이 브랜치에서는 아래의 기존 번호 선택 안내를 입장 순서 방식으로 대체합니다. Host가 P1이며 이후 접속 완료 순서가 P2~P5입니다. 로비 번호 선택은 비활성화되며, 전원 입장 및 설정 확인 뒤 시작합니다. 퇴장 시 남은 참가자의 순서를 유지해 번호를 정리하고 재입장은 마지막 순서로 처리합니다.

본인 원은 하단 중앙, 이전 번호는 왼쪽, 다음 번호는 오른쪽에 표시합니다. 처음과 마지막 번호는 연결되고 2명일 때 양옆은 같은 상대, 솔로에서는 양옆을 숨깁니다. 현재 전달 방향은 고정이며 시계/반시계 전환 기능은 추가하지 않았습니다. Figma `2238:8414` 기준 원 크기는 48×48, 좌상단 좌표는 왼쪽 (-7,437), 오른쪽 (360,437), 본인 (177,809)입니다.

- Unity Hub에서 이 저장소 루트를 프로젝트로 추가하고 **Unity 6000.6.5f1**로 엽니다. 버전 기준은 `ProjectSettings/ProjectVersion.txt`입니다.
- 실험 Scene은 `Assets/Lab/Scenes/Lab.unity`입니다. Scene에 저장된 Canvas와 GameObject는 Hierarchy/Inspector에서 직접 조정합니다.
- 게임 수치는 `Assets/Lab/Resources/LabConfig.asset`의 **단일 설정 원본**에서 조정합니다. 속성을 바꿨다면 새 세션에서 확인합니다.
- 구슬의 **보이는 형태**는 `Assets/Lab/Art/Orbs/`의 에셋에서 조정합니다. 게임 수치와 시각 에셋은 분리되어 있습니다.
- 공유 방은 Host를 포함해 **2~5명**, 기본값은 **3명**입니다. Host는 일반 로비의 **ROOM PLAYERS** 옆 `−`·`+`로 인원을 정한 뒤 **HOST**로 방을 만듭니다. DEV의 **ROOM PLAYERS**도 같은 인원 설정을 사용하며, 개발자 수치를 함께 조정할 때는 **DEV → CREATE ROOM**으로 방을 만듭니다. 방을 만든 후에는 인원수를 바꿀 수 없습니다. Host 로비에는 네트워크에 실제 등록된 방 이름이 표시됩니다. 참가자는 **FIND ROOMS**로 방 목록을 열고 원하는 이름을 눌러 입장하거나, Host 주소와 포트 `7777`을 입력해 **JOIN**합니다. 연결된 뒤 각자 로비에서 **P1~P(목표 인원)** 중 빈 번호를 선택합니다. Host도 원하는 번호를 고를 수 있습니다. Host가 번호를 확정해 모든 화면에 공유하며, 번호가 겹치면 해당 요청을 거절합니다. 설정이 모두 확인되고 목표 인원 전원이 서로 다른 P번호를 선택해야 **START**가 활성화됩니다. 같은 Mac에서 직접 IP로 접속한다면 주소는 `127.0.0.1`입니다.

핫스팟에서 시험할 때는 iPhone에서 개인용 핫스팟을 켜고 그 iPhone에서 방을 만듭니다. 참가 기기를 해당 핫스팟에 연결한 뒤 **FIND ROOMS**에서 Host 화면의 방 이름과 같은 항목을 눌러 입장합니다. 목록에는 방마다 한 행만 나타나며, 선택한 방의 IPv4·IPv6 주소는 접속 경로로 함께 시도합니다. 목록의 **REFRESH**는 다시 검색하고 **CANCEL**은 검색을 닫습니다. 검색이 되지 않으면 참가 기기에서 Host의 실제 IP 주소와 포트로 **JOIN**할 수 있습니다. 두 앱의 로컬 네트워크 접근 권한을 허용하고, 방 검색 실패와 직접 IP 접속 실패는 구분해 기록합니다. 기존 프로토타입의 핫스팟 성공 기록은 이 Lab 버전의 검증 결과가 아니므로 [검증 기록](docs/VALIDATION.md)에서 새 실행 결과를 확인하세요.

### 한 대로 조합·투척 실험하기

Unity Editor에서 Play를 누르거나 **Development Build**로 만든 앱을 실행합니다. 화면 오른쪽의 **DEV**를 누르면 79개 수치의 숫자 입력과 슬라이더가 있는 패널이 열립니다. `Monster Max HP`, `Orb Generation Cost`, `Orb Lifetime (seconds)`, `Throw ...` 등 필요한 값을 조정하고 **START SOLO**를 누르세요. 한 명의 Host 세션이 즉시 시작되며, 솔로 플레이어가 모든 북을 갖습니다. 조합판 위 **북**을 탭해 Yin/Yang을 만든 뒤 서로 다른 두 구슬을 직접 겹쳐 Combined를 만들고 위쪽으로 빠르게 스와이프해 박에 던질 수 있습니다. 북에서는 아이템도 섞여 나옵니다. 좌우 끝 전달은 이웃이 없으므로 발생하지 않고, 같은 이유로 **잠긴 아이템도 솔로에서는 풀리지 않습니다.** 풀린 아이템을 혼자 보려면 `Item Unlock Swipes Min`·`Max`를 0으로, 아이템 없이 투척만 비교하려면 `Yin Chance`·`Yang Chance`를 50, 아이템 확률을 0으로 둡니다.

값을 다시 조정하려면 **DEV → 값 변경 → RESTART SOLO**를 누릅니다. 새 값으로 새 판을 시작하며 구슬·요괴/개인 HP·시간·스태미나가 초기화됩니다. 예를 들어 느긋하게 조합을 시험하려면 `Battle Duration (seconds) = 600`, `Orb Lifetime (seconds) = 60`, `Orb Generation Cost = 1`로 입력합니다. **DEFAULTS**는 저장된 `LabConfig.asset` 값을 입력칸에 불러오고, **END SOLO**는 로비로 돌아갑니다. 오류가 있는 값은 적용하지 않고 패널에 이유를 표시합니다. 일반 빌드에서는 DEV 버튼이 숨겨집니다.

### 공유 방의 값 바꾸기

Host에서 **DEV**를 열고 **ROOM PLAYERS**를 2~5명 중 하나로 정한 뒤, 79개 값을 숫자 입력 또는 슬라이더로 조정합니다. 숫자 입력은 정확한 값을 지정할 때 사용하며 두 조작은 서로 같은 값을 보여줍니다. DEV의 **ROOM PLAYERS**는 일반 로비의 인원 선택과 같은 값을 표시·변경합니다. **CREATE ROOM**을 누르면 선택한 인원과 조정값으로 방을 만들고, 참가자가 **FIND ROOMS**의 방 목록에서 이름을 선택하거나 직접 IP **JOIN**으로 들어오면 Host 설정을 받습니다. Host 로비에서 전투 시작 전에 다시 DEV를 열어 값을 바꿀 수 있으며, 이때 버튼은 **APPLY TO ROOM**입니다. 변경된 설정에 대해 참가자의 확인이 끝나야 **START**할 수 있습니다. 인원수는 방을 만들기 전에 선택합니다. Editor·Development Build의 Host는 전투를 일시정지한 뒤 **DEV → APPLY & RESTART**로 새 설정을 참가자에게 보내고 확인을 받아 새 판을 시작할 수 있습니다. 진행 중인 판의 설정은 바꾸지 않고, 설정은 실행 중인 세션의 복사본에만 적용되며 `LabConfig.asset`에는 저장되지 않습니다.

## 전투 UI와 일시정지

전투 화면은 Figma `UI 가이드`의 **조합대·일시정지·제한시간·요괴 HP·스태미나 볼/바** 배치를 기준으로 합니다. 하단의 구슬 생성 버튼(`FigmaGenerateButton`)은 꺼 두었고, 생성은 조합판 위의 북으로 합니다. 개인 HP와 스태미나는 현재 화면 맨 아래의 축소된 하단 HUD에 표시됩니다. UI에 사용할 투명 그림은 `Assets/Lab/Art/UI/`에 두고, 위치와 크기는 저장 Scene `Assets/Lab/Scenes/Lab.unity`의 `LabCanvas`에서 조정합니다. 배경 풍경·요괴 캐릭터·플레이어 캐릭터 이미지는 이번 UI 이식 대상이 아닙니다. 기존 3D 요괴와 판 위 구슬의 물리·판정은 유지합니다.

전투·일시정지·결과 화면에서는 상단 전투 카메라와 하단 구슬 카메라의 단색 배경을 로비보다 밝게 표시합니다. 색은 저장 Scene의 `LabHud`에 있는 `Battle Background Color`·`Orb Background Color`에서 조정할 수 있으며, 같은 방 로비로 돌아가면 기존 어두운 카메라색으로 복원됩니다. 조합대 종이판과 요괴·구슬 에셋의 색은 이 설정에 포함되지 않습니다.

제한시간은 Host가 확정한 남은 시간을 **분:초**로, 요괴 HP 막대는 확정 스냅샷의 요괴 HP 비율로 표시합니다. 자기 HP는 하단 오른쪽, 스태미나는 하단 왼쪽의 연속 Fill로 현재값/최대치 비율을 표시합니다. 구슬 생성은 조합판 위의 북을 탭해 요청합니다. 좌우 둥근 표시에는 선택한 P번호의 순환 순서에 따른 이웃 **P번호**를 표시합니다. 2인 판은 양쪽에 같은 상대가, 솔로 판은 `P—`가 보입니다. 이름 입력이나 속성 선택을 새로 만들지 않습니다.

전투 중에는 어느 참가자든 일시정지를 요청할 수 있으며, Host가 승인한 상태가 모든 참가자에게 전파됩니다. 일시정지 동안 남은 시간·구슬 수명·폭탄 타이머와 판의 물리 진행을 멈추고 생성·조합·전달·투척 입력을 받지 않습니다. **재개**와 **모두 로비로**는 Host만 실행합니다. 모두 로비로 돌아갈 때 참가자를 연결 해제하거나 방 이름을 없애지 않고 같은 방을 유지합니다. Editor·Development Build의 Host는 일시정지 메뉴에서 DEV 설정을 열어 **APPLY & RESTART**로 새 값이 확인된 후 같은 방의 새 판을 시작할 수 있습니다. 이 기능은 솔로의 **RESTART SOLO**와 별개입니다. 세부 연결과 검증 항목은 [UI 이식 기록](docs/UI_GUIDE_ASSET_IMPLEMENTATION.md)과 [검증 기록](docs/VALIDATION.md)에 구분했습니다.

조합대의 보이는 모양·위치·크기는 **PR #154의 배치**를 유지합니다. 저장된 종이판 `OrbBoardPlate`의 local position은 `(0, 0, 0.55)`, local scale은 `(10, 5, 1)`이며, 실행할 때는 기존 방식대로 하단 카메라 전체의 가로세로에 맞춥니다. 하단 HUD가 종이판 일부를 덮는 원래 구성이므로, 곡선 물리를 위해 종이판을 HUD 위로 올리거나 세로로 줄이지 않습니다.

물리·입력 범위는 실제로 **보이는 영역**을 따릅니다. `LabOrbAreaProfile`에 `BoardPlate.png`의 상하 외곽과 `BottomHudBackground.png`의 불투명 상단 외곽을 각각 65점으로 저장합니다. 위쪽은 종이판 곡선, 아래쪽은 종이판 하단과 HUD 상단 중 높은 곡선을 사용하며 두 선분의 교차점까지 계산합니다. 직사각형 HUD 높이로 잘라내거나 일괄 여백을 더하지 않습니다. 원본 그림의 배치와 에셋은 바꾸지 않습니다. `OrbInteractionArea`는 비시각 참조이며, 현재 저장 Scene에서 종이판을 재배치하는 기준으로 사용하지 않습니다.

상하에는 3D MeshCollider 벽을 만들고 좌우는 전달 통로로 열어 둡니다. 구슬·북의 실제 반지름을 고려해 생성·드래그·수신·크기 검증에 같은 경계를 적용합니다. 곡선 밖 빈 배경이나 HUD 위에서는 새 입력을 시작하지 않으며 이미 잡은 구슬의 영역 밖 손떼기·투척·전달은 유지합니다. 화면·HUD 위치·제어점 변경 시 같은 ID·위치 비율·보드 폭 기준 속도와 요청 대기를 보존하며 드래그 중에는 변경을 보류합니다. `C6 Lab/Fit Curved Orb Area`는 #154의 저장 배치를 복원하고 현재 그림의 윤곽을 연결합니다. 같은 그림에서 수동 조정한 기존 제어점은 보존하며, 런타임 픽셀 읽기 대신 검증된 형상을 캐시합니다.

## 전투 조작과 물리

전투 중 각 플레이어는 매달린 박 표적을 둘러싼 자기 자리의 시점에서 봅니다.

구슬은 조합판 위의 **생성 북**으로 만듭니다. 북은 기본적으로 한 게임에 **1개**이고(DEV `Drum Count`로 1~5개), 판마다 Host가 받을 사람을 무작위로 정합니다. 북이 인원 이하이면 서로 다른 사람이 받습니다. **북이 있는 사람만** 북을 **탭**해 Yin·Yang Raw 구슬 또는 아이템 한 개를 설정 확률에 따라 만들 수 있으므로, 북을 서로 넘겨줘야 합니다. 탭할 때마다 하나씩 나오므로 스태미나가 있는 만큼 연타할 수 있습니다.

- 구슬은 북 안에서 톡 튀어나와 커지며 **360° 무작위 방향**으로 바로 날아갑니다. 나오는 짧은 순간(기본 0.15초)에는 다른 구슬·북을 통과해 연타해도 막히지 않고, 위아래 벽에는 부딪힙니다. 북이 옆 가장자리 가까이 있으면 그쪽으로 나가는 구슬은 옆 사람 화면에 닿기 전에 멈출 만큼만 나갑니다.
- 북은 끌어서 옮기거나 **좌우로 튕겨 옆 사람에게** 넘길 수 있습니다. 위로 튕겨도 던져지지 않습니다.
- 가만히 두면 북은 사방으로 천천히 떠돌고, 길이 휘는 쪽과 스치는 충돌에 따라 화면을 향한 채 회전합니다. 혼자서는 옆 화면으로 넘어가지 않고 가장자리에서 되돌아옵니다.
- 북은 수명·보관 한도·조합·던지기·폭탄 폭발의 대상이 아닙니다.

조합판의 구슬 조합판의 구슬은 3D 구체이며 `Rigidbody`·`SphereCollider`의 PhysX 충돌을 사용합니다. 위치와 속도의 Z축은 고정해 기존 XY 평면에서만 움직입니다. 손가락이나 마우스로 밀면 관성으로 이동하다 감속하고, 상하에서 반발합니다. 좌우 끝으로 나가면 이웃 화면으로 속도와 높이를 이어 전달합니다. Yin과 Yang Raw는 직접 드래그해 놓거나, 현재 기본 설정처럼 접촉 자동 결합이 켜져 있을 때 서로 부딪혀 Combined가 될 수 있습니다. 같은 극성끼리는 결합하지 않습니다. Combined에는 Host가 화·수·목·금·토 중 하나의 속성을 같은 확률로 정해 주며, 조합판과 날아가는 투사체 모두 그 속성 색으로 보입니다.

아이템(릴레이 구슬·시크릿 상자·회복물약·폭탄)은 구슬 정면의 아이콘으로 구분하며 **잠긴 채로** 생깁니다. 오른쪽 아래 배지의 숫자는 남은 잠금 횟수(기본 2~4)이고, 아이템을 **옆 사람 화면으로 넘길 때마다 1씩** 줄어 0이 되면 배지가 사라집니다. 잠긴 동안은 아이콘이 흐려지고 그 위에 **자물쇠**가 겹쳐 보입니다. 마지막 잠금이 풀리는 순간 받은 사람 화면에서 자물쇠가 위로 떠오르며 사라지고, 금색 원이 구슬 크기로 줄어든 뒤 구슬이 한 번 반짝입니다(약 0.6초). 아이템은 15초 뒤 사라지며 음·양과 조합되지 않습니다.

풀린 아이템은 이렇게 씁니다.

- **회복물약**: 같은 구슬을 빠르게 두 번 탭하면 내 개인 HP가 10 오릅니다(최대 HP를 넘지 않음). HP가 가득 차 있거나 0이면 쓰이지 않고 남습니다.
- **시크릿 상자**: 두 번 탭하면 그 자리 양옆에 던질 수 있는 속성 구슬 2개가 생깁니다. 보관 칸이 하나 더 있어야 열립니다.
- **릴레이 구슬**: 풀리는 순간 배지가 `×1`이 되고, 옆 사람에게 넘길 때마다 `×2` → `MAX`로 오릅니다. 위로 던지면 기본 피해의 1·2·4배를 줍니다.
- **폭탄**: 위쪽 빨간 숫자가 남은 초입니다. 그 안에 **잠금을 풀지 못하면** 그때 들고 있는 사람의 판 위 구슬이 모두 사라집니다. 잠금이 풀리면 타이머가 꺼지고 **일반 공격 구슬처럼** 그때부터 8초 동안 쓸 수 있습니다(끝나면 폭발 없이 사라짐). 위로 던지면 기본 피해의 3배를 주고, 빗나가면 그냥 사라집니다. 풀리기 전후 모두 옆으로 넘길 수 있습니다.

Combined를 잡고 **구슬 판 안에서 위쪽으로 빠르게 움직이며 손을 놓으면** 그 자리에서 3D 투척합니다. 손을 놓는 가로 위치와 움직임의 방향·세기가 발사 위치와 속도에 반영되므로, 중앙으로 던지면 표적을 맞힐 수 있고 옆으로 치우치면 빗나갑니다. 느리게 옮기면 투척되지 않고 판 위에 남으며, 좌우 끝으로 빠져나가면 기존 이웃 전달이 우선합니다. 기본 `Lab.unity`에서는 `Target2_Intact` 박 프리팹이 보이며, 실제 피격체는 기존 Unity Cylinder의 MeshCollider입니다. 박 표면과 판정 모양에는 차이가 있습니다. Host에서 충돌을 확인한 명중만 HP를 줄입니다. 새 조작의 속도·생성 상승 거리·카메라 거리 등은 `LabConfig.asset`에서 조정합니다.

손을 놓아 투척한 Combined에는 속성 색의 짧은 비행 잔상이 남습니다. **Host가 실제 명중과 HP 감소를 확정한 경우에만** 요괴의 맞은 지점에서 속성 색의 코어·스파크·확대 충격파가 나타나고, 근처에 `-실제 감소 HP` 숫자가 뜹니다. 마지막 명중으로 남은 HP가 설정 피해보다 적다면 숫자도 실제 감소량만 보여 줍니다. 빗나감에는 피해 숫자·피격 입자가 나오지 않습니다. 숫자는 저장 Scene의 `LabCanvas / LabImpactFeedback`에서, 피격 입자는 `Impact Particle VFX`와 `Assets/Lab/Art/Effects/ImpactParticleBurst.prefab`에서 표시 크기·수명을 조정합니다. 투척 잔상 길이·폭·머티리얼은 `Assets/Lab/Art/Orbs/LabOrbAppearance.asset`에서 조정합니다. 모두 시각 효과이며 투사체의 물리·판정을 바꾸지 않습니다.

기본 `Lab.unity`의 박은 Host 확정 HP에 따라 첫 피해에서 크랙 1단계, 남은 HP 66% 이하에서 2단계, 33% 이하에서 3단계를 표시합니다. 승리가 확정되면 약 1.2초 동안 두 쪽으로 벌어지는 껍질과 작은 기운을 보여 준 뒤 승리 결과를 표시합니다. 패배는 지연하지 않습니다. 새 판·로비 복귀에서 외형이 초기화됩니다. 외형 참조가 없거나 연출이 비활성인 경우 결과 화면은 기다리지 않습니다. 별도 `LabGourdCrack.unity`는 #150 당시 실험용으로 보존하며 기본 실행·빌드는 계속 `Lab.unity`를 사용합니다. Scene 연결 점검은 **C6 Lab → Validate Main Gourd References**, 기존 Scene에 참조를 다시 연결할 때는 **Apply Gourd To Main Scene**을 사용합니다.

직선 투척의 세기 반응·발사각·공기 저항은 **DEV**의 `Throw Power Exponent`, `Throw Loft Offset (degrees)`, `Throw Air Damping`으로 한 판씩 비교할 수 있습니다. 명중·빗나감 뒤 화면에 비행 시간·최고 상승·수평 이동 거리가 나타납니다. 값의 의미와 반복 시험 순서는 [직선 투척 물리 실험 가이드](docs/THROW_TUNING_GUIDE.md)를 참조하세요.

## 개인 HP 확인

새 라운드에서 Host는 각 참가자의 개인 HP를 `Player Max HP`로 초기화합니다(기본 300, DEV 허용 범위 1~300). HUD의 개인 HP 참조는 **자기 HP만** 읽지만, 현재 저장 Scene의 `FigmaPlayerHpBar`가 비활성화되어 막대와 숫자가 화면에 보이지 않습니다. 참가자는 Host가 보낸 확정 스냅샷의 값을 읽습니다. 한 사람만 0이 되어도 라운드는 계속되고, 모든 참가자의 개인 HP가 0이면 `DEFEAT`로 끝납니다. 결과 화면의 HP 표시 역시 현재는 보이지 않습니다.

**현재 구슬·요괴 기능은 플레이어 HP를 감소시키지 않습니다.** Host 모델에는 이후 피해 기능이 호출할 수 있는 개인 HP 변경 경로만 있습니다. 그러므로 DEV의 최대 HP 슬라이더로 새 라운드의 시작 HP를 비교할 수 있지만, 실제 플레이에서 전원 0 패배를 재현하는 공격 패턴이나 DEV 피해 버튼은 아직 없습니다. 이 종료 규칙은 자동 검사와 실제 피해 기능 추가 후의 플레이 검증을 구분합니다.

## 빌드 출력 위치

Unity 메뉴 **C6 Lab → Build Mac App**과 **C6 Lab → Export iOS Xcode Project**의 기본 출력은 프로젝트 루트의 `Builds/Lab/<빌드 시각-식별자>/`입니다. Mac 앱은 그 안의 `macOS/C6_Physics_Lab.app`, iOS Xcode 프로젝트는 `iOS/Unity-iPhone.xcodeproj`에 만들어집니다. 매번 새 폴더를 사용하므로 이전 빌드를 덮어쓰지 않습니다. `Builds/`는 Git에서 제외되어 있습니다.

빌드가 끝나면 Console의 `C6_LAB_BUILD_OK` 메시지에 **전체 출력 경로**가 나타납니다. Unity 메뉴 **C6 Lab → Open Last Build Folder**를 누르면 이 Editor 실행 중 마지막으로 성공한 빌드의 위치가 Finder에 열립니다. 기존처럼 `C6_LAB_BUILD_OUT` 환경변수에 직접 출력 경로를 지정할 수도 있습니다. 이때도 이미 존재하는 앱/폴더에는 덮어쓰지 않고 오류를 표시하므로 새 경로를 지정하세요. 상대 경로는 프로젝트 루트 기준입니다. 실행 중인 Unity Editor에는 나중에 바꾼 환경변수가 반영되지 않을 수 있으므로, 경로를 바꾼 뒤에는 Editor를 다시 열어 빌드하세요.

## Mac에서 여러 실행본 만들기

1. Unity에서 `Lab.unity`를 연 뒤 **C6 Lab → Build Mac App**을 누릅니다. 또는 **File → Build Profiles**에서 이 Scene을 포함해 원하는 경로로 빌드할 수 있습니다.
2. 프로젝트 루트에서 아래 명령을 실행합니다. 첫 줄은 가장 최근에 만든 기본 경로의 Mac 앱을 찾습니다. 출력 위치를 직접 지정했다면 `APP`을 해당 `.app`의 전체 경로로 바꾸세요.

```sh
APP="$(find "$PWD/Builds/Lab" -maxdepth 3 -type d -name C6_Physics_Lab.app -print | sort | tail -n 1)"
test -n "$APP" || { echo 'Mac 앱을 찾지 못했습니다. 빌드 출력 경로를 확인하세요.'; exit 1; }
open -n -a "$APP" --args --lab-host --lab-port 7777
open -n -a "$APP" --args --lab-join 127.0.0.1 --lab-port 7777
open -n -a "$APP" --args --lab-join 127.0.0.1 --lab-port 7777
```

위 명령은 기본 목표 인원 **3명**의 예입니다. Host 화면에 `3 / 3`이 보이고 설정 확인이 끝나 **START**가 활성화되면 누릅니다. **2명 실험**에는 `--lab-host` 없이 앱을 두 번 연 뒤 Host 일반 로비의 **ROOM PLAYERS**를 **2**로 바꾸고 **HOST**를 누릅니다. 다른 실행본에서는 **FIND ROOMS**의 방 이름을 눌러 입장하거나 직접 IP로 **JOIN**합니다. DEV 패널에서도 같은 인원값을 선택할 수 있습니다. 자동 검증에서만 Host 인자에 `--lab-auto-start --lab-auto-generate --lab-auto-transfer`를 추가합니다. 한 프로젝트 폴더를 Editor 여러 개에서 동시에 열 필요는 없습니다. 독립 실행 앱으로 네트워크 경로를 확인합니다.

iOS Xcode 프로젝트는 Unity 메뉴 **C6 Lab → Export iOS Xcode Project**에서 만듭니다. Console에 표시된 `.../iOS` 출력 폴더에서 `Unity-iPhone.xcodeproj`를 열고, Xcode에서 개발 Team을 선택해 기기에 설치한 뒤 로컬 네트워크 권한을 허용합니다. **Unity의 iOS 출력 폴더에는 Xcode 프로젝트가 있고, Xcode가 빌드한 설치용 앱은 별도의 DerivedData에 저장됩니다.** Xcode GUI에서 Run하면 보통 사용자 Library 아래 DerivedData를 사용합니다.

Xcode가 만든 앱 파일까지 같은 보이는 빌드 폴더에서 찾으려면, 서명 설정을 마친 프로젝트에 대해 아래처럼 `-derivedDataPath`를 지정해 터미널에서 빌드할 수 있습니다. `IOS_EXPORT`에는 Unity Console에 표시된 이번 `iOS` 폴더의 전체 경로를 입력하세요. 결과 앱은 `iOS` 폴더와 나란히 만들어지는 `XcodeDerivedData/Build/Products/` 아래에 생깁니다. Xcode 빌드·서명·기기 설치는 Unity의 Xcode 프로젝트 출력 성공과 별도로 확인해야 합니다.

```sh
IOS_EXPORT="빌드 로그에 표시된 iOS 출력 폴더의 전체 경로"
DEVELOPER_DIR="/Applications/Xcode.app/Contents/Developer" xcodebuild \
  -project "$IOS_EXPORT/Unity-iPhone.xcodeproj" \
  -scheme Unity-iPhone -configuration Debug -destination 'generic/platform=iOS' \
  -derivedDataPath "$IOS_EXPORT/../XcodeDerivedData" build
```

`LabOrbView`는 구슬 ID·3D 물리 루트와 교체 가능한 `Visual` 자식을 분리합니다. 조합판 구슬과 날아가는 투사체는 같은 `OrbVisual.prefab`과 Yin·Yang·Combined 머티리얼(Combined는 속성별 머티리얼, 비어 있으면 임시 속성 색)을 사용하지만, 조합판의 평면 물리와 투사체의 3D 비행은 각자의 물리 루트에서 처리합니다. 보드 구슬의 접촉 그림자도 물리 충돌체와 분리되어 있습니다. 표적은 Cylinder의 피격 MeshCollider와 박 프리팹을 장착하는 시각 Mount를 분리합니다. `LabGourdCrack`이 박 외형·크랙을, `LabGourdFinish`가 마지막 명중 연출을 담당합니다. 아이템의 아이콘·자물쇠·잠금 배지·해금 연출은 구슬 루트에 붙어 굴러도 돌지 않고 충돌체가 없습니다. 북은 같은 크기의 충돌 구 위에 북 그림(`GenerateButton.png`)을 화면을 향하게 그립니다. 아이템 아이콘·자물쇠·북 그림 외의 표현(해금 원·반짝임 포함)은 Unity에서 만든 도형과 재질만 사용합니다.

### 조합판 구슬의 외형 바꾸기

1. `Assets/Lab/Resources/LabConfig.asset`의 **Orb Appearance**가 `Assets/Lab/Art/Orbs/LabOrbAppearance.asset`을 가리키는지 확인합니다. 이 에셋에서 공통 Visual Prefab, 종류별·속성별 Material, 아이템 아이콘 4종과 자물쇠 이미지, 생성 북 그림(`Drum Sprite`), 잠금 표시(자물쇠 크기·아이콘 흐림)와 해금 연출(시간·높이·원 크기·색), 접촉 그림자의 색·크기·위치를 교체할 수 있습니다.
2. `Assets/Lab/Art/Orbs/OrbYin.mat`, `OrbYang.mat`, `OrbCombined.mat`에서 각 구슬의 색·광택을 조정합니다. `OrbVisual.prefab`에서는 구체 메시와 회전 표시를 직접 조정합니다. 외형 Prefab에 Collider나 Rigidbody를 추가하지 마세요. 충돌과 구슬 ID는 런타임 루트가 담당합니다.
3. `Assets/Lab/Scenes/Lab.unity`의 **OrbBoard → OrbBoardPlate / OrbBoardLight**에서 판 색과 빛을 조정합니다. `LabCanvas/BoardAreaTint`는 기존 배치를 보존하되 Image가 꺼져 있어 3D 조명을 가리지 않습니다. 판 크기는 `Board Height`와 화면 비율에 맞춰 실행 시 갱신됩니다.
4. Play 또는 Development Build의 DEV 솔로에서 Yin·Yang을 생성하고 직접 조합·투척해 보세요. Material 색을 변경한 뒤에는 새 라운드를 시작해야 이미 표시된 구슬에도 새 색이 적용됩니다. 외형 변경은 구슬의 반지름·소유권·전달·피격 판정을 바꾸지 않습니다.

화면 간 이동 데이터는 여전히 **구슬 ID·소유자·정규화한 XY 위치와 XY 속도**입니다. Host가 승인한 좌우 전달에서 이 값을 이어 주고, 조합판 내부의 3D 물리 컴포넌트 자체는 네트워크로 전송하지 않습니다. 확정 피격 신호에는 구슬 ID·라운드·속성·실제 피해량·요괴 기준 충돌 위치와 Host가 계산한 회전 충격량을 담습니다. 회전 각도·속도는 Host 스냅샷으로 보정합니다. 아이템 사용 요청·릴레이 단계·해금 시각·폭발 알림과 일시정지 상태, 생성 북의 소유자·위치, 로비의 P번호 선택도 공유합니다. 합쳐진 접속 프로토콜은 `5616`이며 다른 버전의 앱과 같은 방에 접속할 수 없습니다.

기본 Scene에서 보이는 박과 실제 피격 MeshCollider는 같은 축에서 흔들리고 회전하며, 로프와 천장 받침은 기존 매달림 연출을 사용합니다. [회전 확인용 그레디언트](Assets/Lab/Art/Targets/TargetSpinGradient.png)는 숨겨진 원통과 독립 원통 테스트용으로 남아 있습니다. 회전 강도·감쇠·최대 속도는 DEV의 **Target spin** 항목에서 새 판에 적용합니다.

## 현재 기준 수치

공유 방은 Host 포함 **2~5명**이며 기본 목표는 **3명**입니다. 목표 인원이 N명이면 선택 가능한 번호는 P1~PN이고, 선택한 번호 순서로 **360°/N** 간격의 원형 자리를 구성합니다. PN의 오른쪽은 P1이며 P1의 왼쪽은 PN입니다. 개발자 솔로 모드에서는 한 명의 Host가 같은 생성·조합·투척 규칙을 시험합니다. 기본값은 요괴 HP **1,000**, 플레이어별 HP **300**, 요괴 명중 피해 **20**, 제한 시간 **180초**입니다. 개인 스태미나는 **100**으로 시작하고 구슬 생성에 **20**을 쓰며 **1.7초당 20**(초당 약 11.8)을 회복합니다. 유효 명중한 공격자에게만 **10**을 추가 회복합니다. 북이 한 게임에 1개라 북을 받은 사람이 스태미나를 몰아 쓰고 넘기므로, 북이 세 사람을 한 바퀴 도는 동안(약 6~9초) 빈 스태미나가 거의 다 차도록(약 8.5초) 맞췄습니다. 북을 탭하면 음 **40%**, 양 **40%**, 아이템 4종 각 **5%**로 생성하며, 아이템은 **2~4회** 넘겨야 풀립니다. 회복물약은 개인 HP **+10**, 릴레이 구슬은 **×1·×2·MAX**에 따라 피해 **20·40·80**, 폭탄은 피해 **60**입니다. 모든 Raw/Combined 구슬은 생성 후 **8초**, 아이템은 **15초**에 만료되며 Combined는 조합 시 새 수명이 시작됩니다. 기본 수치는 `LabConfig.asset`에서, 실행 중 솔로와 Host 방 시험 값은 DEV 패널에서 조정할 수 있습니다.
